# 可视化交互组：录音、ASR 与语义结果接口

适用环境：ROS 2 Humble。业务链路为香橙派采集 → PC 接口端存档转交 → AI 端识别与语义处理。界面只发起录音控制、订阅结果和查询，不读取“目录中最新文件”来重复发起识别。

## 1. 订阅与调用清单

| 名称 | ROS 类型 | 界面用途 |
|---|---|---|
| `/audio/start_recording` | Service `std_srvs/srv/Trigger` | 请求设备开始录音；空请求，检查 success 和 message |
| `/audio/stop_recording` | Service `std_srvs/srv/Trigger` | 请求设备停止并发送；空请求，最多十秒自动停止 |
| `/ai/request_status` | Topic `robot_interfaces/msg/RequestStatus` | 保存、AI 受理、ASR、语义阶段的业务说明或拒绝原因 |
| `/ai/audio_state` | Topic `robot_interfaces/msg/AudioProcessingState` | 当前音频处理阶段、失败环节和来源关联 |
| `/ai/asr_text` | Topic `robot_interfaces/msg/RecognizedText` | 实际文字、语言、识别状态、错误详情 |
| `/ai/parse_result` | Topic `robot_interfaces/msg/TaskParseReport` | 任务候选、缺失字段、澄清问题或解析失败 |
| `/ai/query_audio` | Service `robot_interfaces/srv/QueryAudio` | 按音频 request_id 查询最新快照、识别和语义结果 |
| `/robot/component_status` | Topic `robot_interfaces/msg/ComponentStatus` | 筛选 component_id=asr，展示模型加载／就绪／忙碌／故障 |
| `/robot/component_status` | 同上，component_id=microphone | 实际录音进程状态，待机／运行／采集故障 |
| `/system/heartbeat` | Topic `robot_interfaces/msg/NodeHeartbeat` | ASR 节点活性；不能只据此认定模型或设备就绪 |

话题均使用 Reliable、Volatile；音频状态／识别／语义／业务回执 KeepLast(10)，部件状态 KeepLast(20)，心跳 KeepLast(50)。ASR 部件状态和心跳按 1 Hz 发布，阶段状态在变化时发布。保持双方 QoS 兼容。

## 2. 界面字段映射

### 音频处理阶段

AudioProcessingState 包含：stamp、source_node、boot_id、event_seq、request_id、session_id、segment_id、input_context_id、audio_path、operation、stage、message、error_code。

| stage | 建议显示 |
|---|---|
| QUEUED=0 | 已受理，等待处理 |
| WAITING_ASR=1 | 等待 ASR 服务 |
| RECOGNIZING=2 | 正在识别语音 |
| WAITING_PARSE=3 | 等待语义服务 |
| PARSING=4 | 正在理解任务 |
| READY=5 | 候选完整，尚未准备或确认 |
| NEED_CLARIFICATION=6 | 需要用户补充信息 |
| FAILED=7 | 当前处理阶段失败 |
| CANCELED=8 | 处理已取消 |
| NO_SPEECH=9 | 未识别到有效语音 |
| ASR_COMPLETED=10 | 本轮仅做 ASR，识别已完成 |

operation 保留本阶段的 `/ai/process_audio`、`/ai/recognize_audio` 或 `/ai/parse_task`，失败时也保留，用来区分“识别失败”和“识别成功但语义服务不可用”。同一请求按 `(source_node, boot_id, request_id, event_seq)` 去重，不能按到达顺序覆盖新状态。节点重启后 boot_id 改变，旧进程消息不能恢复成当前活动流程。

无可信进度百分比时展示阶段文字或等待动画，不根据耗时伪造识别百分比。

### 文字与任务候选

- RecognizedText.success=true 且 status=SUCCESS 才展示为有效识别文字；NO_SPEECH 与 FAILED 均不会进入语义解析。
- text 为模型实际结果。confidence=-1 表示模型未提供可靠置信度，界面应隐藏分数，不能显示为 100%。
- TaskParseReport 带 request_id/session_id/input_id/input_context_id、stamp、outcome、success/message/error_code、candidate、missing_fields、clarification_question。
- outcome 与 ParseTask 相同：READY=0、NEED_CLARIFICATION=1、UNSUPPORTED=2、FAILED=3、CANCELED=4。缺参时展示 clarification_question 和 missing_fields；不把空 candidate 当作默认运动任务。
- TaskParseReport 是模型解析结果；TaskDraft 是后续准备成功、可等待用户确认的任务，两者不能混用。订阅候选不能自动调用执行 Action，仍须原协议的准备、版本绑定和显式确认。
- audio_path 是共享目录中的本地文件路径，不是浏览器下载 URL。未共享文件系统的界面不可直接用该路径播放音频。

## 3. 状态恢复和查询

订阅晚加入、断线重连或发现 event_seq 跳号时，查询完整快照：

```bash
ros2 service call /ai/query_audio robot_interfaces/srv/QueryAudio \
  "{request_id: 'ui-query-001', target_request_id: '从接收日志取得的音频请求ID'}"
```

Request.request_id 是这次查询的 ID；target_request_id 才是录音任务 ID。Response.success=true 仅表示找到记录，不表示识别成功。必须检查 found、asr_available、parse_available，再读取各自嵌套 state/asr/parse。无记录返回 AUDIO_NOT_FOUND；不要把默认 stage=0 当作真实排队状态。

快照仅在当前 AI 编排进程内保存，上限 1024 条，与输入登记上限一致；进程重启后不会自动恢复。恢复持久化和业务确认状态属于后续任务层工作。非法输入在入队前被拒绝时没有快照，拒绝原因查看 RequestStatus。

## 4. 录音按钮和失败提示

开始录音前等待 ASR 部件状态 READY，STARTING 时展示“模型加载中”。开始成功只说明设备采集进程已启动，不能立刻显示识别完成。停止成功只说明音频已发出，文件保存和 AI 受理须分别检查 operation=/audio/segments、/ai/process_audio 的回执。

设备响应、保存回执或处理结果缺失时，显示“结果未确认”；不要自动重发开始或重播旧录音。麦克风复用 ComponentStatus，以 component_id=microphone 按 2 Hz 及控制后广播：READY 表示节点待机、BUSY 表示实际录音进程运行、FAULT 表示最近采集失败；enabled 不代表麦克风已经过硬件探测。界面超过三秒未收到状态时恢复未确认，不根据倒计时猜测停止。InteractionState 仍不由采集节点发布。

界面错误展示中文 message，程序逻辑判断稳定 error_code。重点处理 ASR_NOT_READY、ASR_MODEL_UNAVAILABLE、ASR_DEPENDENCY_MISSING、ASR_BUSY、ASR_TIMEOUT、NO_SPEECH、FILE_NOT_FOUND、AUDIO_FORMAT_UNSUPPORTED，以及语义阶段 DEPENDENCY_UNAVAILABLE、PARSE_TIMEOUT、MISSING_FIELDS。

## 5. 联调命令与验收

所有终端先加载 Humble 和工作空间环境，然后监听：

```bash
ros2 topic echo /ai/audio_state
ros2 topic echo /ai/asr_text
ros2 topic echo /ai/parse_result
ros2 topic echo /ai/request_status
ros2 topic echo /robot/component_status
```

图形界面及一键启动见《前端工作台_使用说明.md》。分节点调试时，FunASR 环境命令见根目录 README 的“真实 FunASR 识别”，真实语义模型启动见“使用 Ollama 千问 2B 完成语义解析”。只做 ASR 时设置 `enable_semantic:=false`；完整链路需启动 parse_task_node（默认 qwen3.5:2b），编排器设置 `enable_semantic:=true`、`parse_timeout:=120.0` 并配置真实白名单。

语义节点提供 `/ai/parse_task` 的 Feedback 和 Result，音频编排仍统一发布 `/ai/parse_result` 和查询快照。直接向语义 Action 发文字不会创建音频记录或发布音频编排话题。连接失败 LLM_UNAVAILABLE、模型缺失 LLM_MODEL_UNAVAILABLE、并发拒绝 LLM_BUSY、超时 PARSE_TIMEOUT、畸形输出 INVALID_MODEL_OUTPUT、白名单错误 UNKNOWN_STATION/UNKNOWN_OBJECT 均须显示实际原因，不能标成解析成功。ASR 的部件状态不代表 Ollama 模型可用，当前未新增 LLM 周期就绪广播。

验收场景：模型加载／就绪、真实录音识别、静音、缺文件、格式错误、识别忙碌／超时、界面晚加入查询、ASR 成功但语义服务缺失，以及澄清结果不触发执行。
