# 上位机调试程序

入口：`jy61p_motor_test.py`。用于电脑连接板载CH340，人工观察JY61P、调试Emm_V5与麦克纳姆底盘。本阶段不提供香橙派自动控制程序。

## 安装和启动

使用Python 3.10或更高版本，需要Tkinter和pyserial。在项目根目录执行：

```powershell
python -m pip install -r PC_Tools/requirements.txt
python PC_Tools/jy61p_motor_test.py
```

Windows通常随Python安装Tkinter；若提示缺少tkinter，修复Python安装的Tcl/Tk组件。选择实际CH340的COM端口，串口配置固定115200/8N1，无流控；不要同时让串口助手占用端口。程序在开口前关闭DTR/RTS，避免部分板卡被握手信号复位。

## 建议操作顺序

1. 先架空车轮，准备独立硬件急停/切断使能；烧录配套新固件。
2. 连接串口，等待自检。新固件由STM32查询四电机FLAG和新鲜IMU，PC只查询结果；旧固件采用PC只读探测，不具有全部新保护。
3. 自检通过后再使能目标电机，使用低速测试方向。自检在线不等于电机已使能。
4. 单台速度/位置/回零：填地址、方向、速度、加速度，按对应按钮。同步模式先暂存动作，再按广播同步触发。
5. 底盘：填写前进/左移/逆时针分量（-1000～1000），正负分别表示相反方向。首次应逐方向测试，随后再试合成。
6. “停止当前”按钮实际发送全车STOP 0 0，退出当前控制模式；从单电机切换底盘前先停止。

7. 异常时按鲜红色“全部急停”。排查后点击“重新自检”，通过后再手动发送新动作；绝不自动恢复旧动作。

底盘停止按钮、三分量全零或最大速度为0，也统一发送STOP 0 0，撤销持续授权并清空未发送的旧运动/续租帧。停止按钮不依赖速度、加速度输入是否有效；串口正在发送的单帧仍需先写完。

使能命令始终立即执行（sync=0）；同步复选框只适用于运动动作。界面仍允许编辑地址0～255，但固件的使能/运动只接受广播0和配置的四轮地址，其他地址返回参数错误。

## 持续授权与500ms停车

“持续授权当前动作”默认不勾选。未勾选的单次动作在运动授权500ms过期后停车并锁定，即使PC还在发送PING；测试较长的位置/回零动作也需要授权。

需要持续运动时先显式勾选，然后发动作。工具只在收到匹配成功ACK后，才每200ms发送带原动作SEQ的RENEW；位置动作本身不会重复发送。新动作会切换授权SEQ，错误ACK不会创建新授权。PING只表明链路正常，不能保持旧动作。

普通STOP、ESTOP、失能、重新自检、故障和断开连接会清除本地授权并取消勾选。排障后需要重新确认。下位机实际停车由收到的停车帧或超时保护完成；清除PC变量本身不是物理停车。

成功的周期RENEW应答不刷日志；拒绝、未知状态或载荷格式异常时会记录原因、取消持续授权并提示查询状态。此处理不代表已确认物理停车，也不会替代STM32的独立超时保护；必要时立即使用全车STOP或急停。

默认参数与协议未在此次整理中改变：链路500ms、运动500ms；PC周期200ms；未发送的RENEW超过250ms丢弃。真实制动时间还包含总线发送和机械减速。

## 自检与日志

- 控件禁止运动时，已连接状态下仍可按急停。
- READY仅说明STM32初始化完成，必须看自检结果；VALID是累计有效单帧，不是实时完整IMU在线证明。
- 自检确认在线为绿色、缺失为红色、检测中黄色、未连接灰色。运行锁定以STM32安全状态和故障提示为准，历史自检绿色不能证明设备当前仍无故障。
- QUEUE是等待发送，TX是串口写入提交，ACK成功是STM32接受/入队。E4成功是四轮应答及同步触发入队，不是到位确认。
- IMU默认不逐帧写日志；勾选后按GUI刷新记录最新快照。显示计数包含合并帧，不要求每帧都在日志中出现。
- 日志最多保留500行；查询状态查看历史计数的差值，单次非零计数不等于当前持续出错。

完整命令及ACK含义见 [HOST_PROTOCOL.md](../Docs/HOST_PROTOCOL.md)，接线/排障见 [UART_DEBUG_GUIDE.md](../Docs/UART_DEBUG_GUIDE.md)。

## 源码阅读

同一个入口文件保留三个职责明确的类，避免为了拆分再增加转发模块：

| 位置 | 职责 |
|---|---|
| 文件顶部常量、CRC、build_frame | 编码和协议编号，与STM32保持一致 |
| ConnectionSelfTest | 连接自检状态与旧固件只读探测，不执行运动 |
| SerialWorker | 后台串口收发、FIFO/急停优先槽、IMU邮箱与本地门禁 |
| TestApplication | Tk布局、请求匹配、状态显示与按钮命令 |

GUI线程才能读写Tk控件；后台线程通过事件和快照传数据。GUI每轮最多64事件或5ms，避免高频输入饿死按钮；串口写入最多等待100ms，不执行可能无限等待的flush。普通ACK不合并，只有IMU快照/协议错误合并。

急停后本地恢复阶段为：未请求 → 发SELF_TEST → 观察RUNNING → 观察无急停/待停车的PASSED。旧PASSED消息不能直接解锁；STM32也独立检查故障锁。此处不能简化为“收到任意ACK就恢复按钮”。

## 无串口测试

在项目根目录执行：

```powershell
python -m unittest discover -s Tests -p "test_*.py" -v
powershell -ExecutionPolicy Bypass -File Tests/run_tests.ps1
```

Python测试用模拟串口与控件，不向真实电机发动作。实车断线、机械制动和驱动器硬件急停仍须现场验证。
