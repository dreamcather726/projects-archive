# 串口与架空调试说明

本页说明硬件连接、人工调试顺序和故障排查。完整命令、CRC示例及状态字段只维护在 [HOST_PROTOCOL.md](HOST_PROTOCOL.md)，上位机按钮操作见 [PC调试程序说明](../PC_Tools/README.md)，代码分层见 [CODE_GUIDE.md](CODE_GUIDE.md)。

## 1. 串口连接

| 用途 | STM32外设 | TX / RX | 波特率 |
|---|---|---|---:|
| PC板载CH340 | USART1 | PA9 / PA10 | 115200 |
| 视觉预留 | USART2 | PA2 / PA3 | 115200 |
| JY61P | USART3 | PB10 / PB11 | 9600 |
| Emm_V5总线 | USART6 | PG14 / PG9 | 115200 |

均为8N1、无流控。外接UART时TX接对端RX，RX接对端TX并共地；按实际板卡和驱动器要求确认电平、供电和总线接法，不能把电机动力电源接到STM32串口引脚。板载CH340不应同时与另一主控争用USART1。

RX由DMA直接写入256字节循环区，DMA中断记录圈数/错误，任务按计数非阻塞读取；不是在每次DMA中断里搬运整帧。TX使用256字节软件环形区和TXE中断；普通写入是整段入队、空间不足返回错误，不等待硬件发完。

## 2. 第一次调试顺序

1. 架空车轮，确保现场可以切断电机使能/动力；检查四轮地址与方向配置。
2. 编译并人工烧录当前固件，启动PC工具、选择CH340端口连接。
3. 等待STM32自检结果。READY只说明初始化完成，不是允许运动；四电机和新鲜IMU通过后才能使能/运动。
4. 查询状态，确认IMU数据持续更新，错误/丢字节计数是否继续增长。
5. 低速使能并测试一台电机，使用全车STOP结束单电机控制后，再测试底盘方向。
6. 单次动作可不勾选持续授权；需要超过500ms的动作时，先显式勾选“持续授权当前动作”。位置/回零同样需要授权，不能反复发原动作保活。
7. 验证普通全车STOP、红色ESTOP、授权超时、主控断线及设备断线；每次故障排查后重新自检，再发送新动作。

速度上限仍是100RPM；并非要求首次测试直接使用100RPM。回零前先确认驱动器回零参数与机械限位，不能把示例模式视为适用于所有机构。

## 3. 看懂日志

| 日志 | 代表什么 | 不代表什么 |
|---|---|---|
| QUEUE | PC生成帧并放入待发送区 | STM32已经收到 |
| TX | 串口写调用已完整提交帧 | 设备已执行或到位 |
| RX / ACK=00 | STM32接受/入队，或命中重复请求缓存 | 电机运动已经完成 |
| E2 / 电机回复 | STM32转发完整电机帧 | 自动证明四轮都健康 |
| E3 / 自检、安全 | 当前检测阶段和锁定原因 | 故障消失后可自动恢复旧动作 |
| E4 result=2 | 四轮应答通过、广播同步触发已入队 | 物理同步时间、实际速度或位置已确认 |

ACK=05是忙，需先确认当前流程；ACK=07是自检未通过/故障锁定，不能用持续重发绕过。POS/HOME/SYNC有限去重窗口为最近8条成功请求、2秒内，不跨重启；不要盲目重试相对位置。

## 4. 超时、停车与恢复

链路与运动各有独立500ms计时。合法PING可维持链路，但只有新接受的动作或匹配原动作SEQ的RENEW可延长运动授权。PC心跳周期200ms，勾选持续授权后额外发送RENEW；过期RENEW不能恢复旧动作。

普通STOP 0 0、零底盘请求：撤销授权、全车停车、退出控制模式，不主动清除已有故障。ESTOP：优先停车并锁定；必须显式重新自检，通过后才能接受新运动。

启动/重新自检最多5秒；每台FLAG最多等待500ms、尝试两次。运动巡检与底盘发送错开，每轮完成后等待500ms；完整IMU样本1秒未更新会锁定。FLAG检查通信和堵转/保护/目标电机失能，但不是实际四轮速度闭环。

底盘各轮在TX空且硬件TC完成后计10ms等待回复，最多重试一次；整个序列还有200ms上限。急停删除未开始的TX帧，只保留已开始帧尾，防止把停车字节拼到旧命令中间。

以上时间是软件判定/发送条件，不是整车完全静止的时间承诺。断线的驱动器可能收不到广播；独立硬件急停/驱动器失联保护仍需验证。

## 5. 常见问题

| 现象 | 检查重点 |
|---|---|
| 连接后没有READY/STATUS | COM口、115200/8N1、CH340连接及USART1引脚；工具已关闭DTR/RTS |
| VALID增加但IMU仍未通过 | VALID是单帧历史计数；自检需要新的51/52/53完整样本，不是只看VALID非零 |
| IMU_DROP非零 | 看两次STATUS的差值；历史启动丢弃计数不等于当前仍在丢包 |
| IMU刷新不如2ms快 | 2ms是任务轮询周期，不是传感器输出周期；实际受IMU配置、9600带宽和GUI快照刷新限制 |
| PING正常，500ms后停车 | 检查是否勾选持续授权、动作ACK是否成功、RENEW是否匹配当前运动SEQ |
| 急停后按钮不可用 | 正常锁定；设备排障后重新自检，不会自动恢复旧动作 |
| 从单电机切换底盘返回忙 | 先普通全车STOP退出旧控制模式，再发送新模式命令 |
| 回复中有6B | 固件按功能码/长度取帧，数据内部6B不当帧尾；检查末字节与回复长度 |
| 日志看不到全部IMU帧 | 正常快照合并；界面取最新值并累计帧数，普通命令回复仍FIFO处理 |

当前IMU初始化会发送解锁/滤波/输出内容配置命令，但本轮不修改设备波特率或输出频率；后续如需提速，应同时评估设备配置、串口带宽和接收能力，不只缩短任务周期。

## 6. 无硬件回归验证

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File Tests/run_tests.ps1
powershell -ExecutionPolicy Bypass -File Tests/check_feature_switches.ps1
```

前者使用本机gcc和Python，涵盖协议、停车、自检、模式冲突、回复解析、TX帧边界、上位机队列与授权；后者用Arm Compiler检查IMU/HOST/IWDG八种组合，编译器路径在脚本开头。完整固件仍需Keil编译链接。

硬件验收清单见 [SAFETY_REVIEW.md](SAFETY_REVIEW.md)。模拟测试不能代替断线、复位、机械制动与长时间运行测试。
