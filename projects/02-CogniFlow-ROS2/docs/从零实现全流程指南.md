# AI 语音交互工作台 · 从零实现全流程指南

> 本文档教你一个人把这个项目从头到尾搭出来。按实现顺序走，每一步都有验证命令，做完一步确认能跑再做下一步。

---

## 第一步：搞清楚这个项目在做什么

工人对着麦克风说一句话，比如"把 box_1 从 A 点搬到 B 点"，系统自动完成：

```
说话 → 录音 → 语音转文字 → 大模型理解成任务步骤 → 人核对 → 存成草稿
```

最终交付的是一个 PySide6 桌面窗口，能录音、看识别结果、编辑任务步骤、保存草稿。机器人实际执行是下一步的事。

### 系统由 5 个 ROS 节点组成

| 节点 | 作用 |
|---|---|
| microphone_sender_node | 调系统麦克风录 PCM 音频 |
| audio_receiver_node | 收 PCM，攒成 WAV 文件存盘 |
| asr_node | FunASR 把 WAV 转成文字 |
| parse_task_node | Ollama 大模型把文字解析成结构化任务 |
| task_draft_node | 把人确认的任务存进 SQLite |
| robot_visualization | PySide6 窗口（上面所有节点的老板，统一拉起） |

## 第三步：定义消息接口（最先做，后面全靠它）

在 `robot_interfaces/` 下定义所有 msg / srv / action。这是整个项目的契约，**先把这个写完再写任何业务代码**。

### 3.1 msg 消息

**`msg/AudioSegment.msg`** —— 一段 PCM 音频：
```
std_msgs/Header header
string request_id
string session_id
string segment_id
string input_context_id
uint32 sample_rate
uint32 channels
string encoding
uint8[] data
```

**`msg/RecognizedText.msg`** —— ASR 识别结果：
```
std_msgs/Header header
string request_id
string session_id
string segment_id
bool success
string text
float32 confidence
string status
string error_code
```

**`msg/AudioProcessingState.msg`** —— 处理到哪一步了：
```
std_msgs/Header header
string request_id
string session_id
uint8 stage
string message
string error_code
```

stage 取值：0=排队，1=等ASR，2=识别中，3=等语义，4=解析中，5=完成，6=需要追问，7=失败。

**`msg/ComponentStatus.msg`** —— 组件在线状态：
```
std_msgs/Header header
string component_id
string state
string message
```

### 3.2 srv 服务

**`srv/SaveTaskDraft.srv`** —— 保存草稿：
```
string draft_id
string body_json
---
bool success
string draft_id
uint32 revision
string confirmation_token
string error_code
```

### 3.3 action 动作

**`action/ParseTask.action`** —— 语义解析（耗时长，用 action）：
```
string request_id
string text
string[] allowed_station_ids
string[] allowed_object_ids
---
bool success
string message
string error_code
---
uint8 stage
string message
```

### 3.4 改 CMakeLists.txt 和 package.xml

在 `robot_interfaces/CMakeLists.txt` 里把上面的 msg/srv/action 都加进去，然后：

```bash
cd ~/ai-interaction-ui
colcon build --packages-select robot_interfaces
source install/setup.bash
```

**验证**：
```bash
ros2 interface show robot_interfaces/msg/AudioSegment
# 能看到消息字段就对了
```

## 第四步：做麦克风采集节点（ai_interface 包）

### 4.1 节点功能

- 提供 `/audio/start_recording` 和 `/audio/stop_recording` 两个服务
- 用 `parecord` 命令录 16kHz / 16bit / 单声道 PCM
- 每 0.5 秒读一块 PCM，发布到 `/audio_data` Topic
- 提供最长 120 秒自动停止

### 4.2 关键代码结构

`ai_interface/ai_interface/devices/microphone_sender_node.py`：

```python
import rclpy
from rclpy.node import Node
import subprocess
import numpy as np

class MicrophoneSenderNode(Node):
    def __init__(self):
        super().__init__("microphone_sender_node")
        self.create_service(Trigger, "/audio/start_recording", self.start_cb)
        self.create_service(Trigger, "/audio/stop_recording", self.stop_cb)
        self.process = None
        self.pcm_buffer = bytearray()

    def start_cb(self, request, response):
        self.process = subprocess.Popen(
            ["parecord", "--format=s16le", "--rate=16000", "--channels=1"],
            stdout=subprocess.PIPE
        )
        response.success = True
        return response
```

### 4.3 验证

```bash
ros2 run ai_interface microphone_sender_node
# 另一个终端：
ros2 service call /audio/start_recording std_srvs/srv/Trigger
# 说一句话
ros2 service call /audio/stop_recording std_srvs/srv/Trigger
ros2 topic echo /audio_data
# 能看到 PCM 数据在流
```

## 第五步：做音频接收和存盘（ai_interface 包）

### 5.1 节点功能

- 订阅 `/audio_data`
- 收到停止信号后，把所有 PCM 块拼成 WAV 文件
- 存到 `received_audio/` 目录
- 通知下游"有新音频可以处理了"

### 5.2 关键代码

用 Python 标准库 `wave` 模块写 WAV 文件头：

```python
import wave
import os

def save_wav(pcm_data, path, sample_rate=16000):
    with wave.open(path, 'wb') as wf:
        wf.setnchannels(1)
        wf.setsampwidth(2)  # 16bit
        wf.setframerate(sample_rate)
        wf.writeframes(pcm_data)
```

## 第六步：做 ASR 语音识别节点（ai_edge 包）

### 6.1 节点功能

- 启动时后台加载 SenseVoiceSmall 模型（10~30 秒）
- 收到 WAV 路径后，调用 FunASR 识别
- 发布识别结果到 `/ai/asr_text`

### 6.2 关键代码

```python
from funasr import AutoModel

class ASRNode(Node):
    def __init__(self):
        super().__init__("asr_node")
        # 后台线程加载模型，不阻塞 ROS
        self.model = None
        threading.Thread(target=self.load_model, daemon=True).start()

    def load_model(self):
        self.model = AutoModel(
            model="models/SenseVoiceSmall",
            disable_pbar=True
        )

    def recognize(self, wav_path):
        result = self.model.generate(input=wav_path, language="zh")
        return result[0]["text"]
```

### 6.3 验证

```bash
# 等日志显示"模型已就绪"
# 手动喂一个 WAV 文件测试
ros2 service call /ai/recognize_audio ...
# 或者直接看 /ai/asr_text Topic 有没有文字出来
```

## 第七步：做语义解析节点（ai_edge 包）

### 7.1 节点功能

- 收到 ASR 文字后，发给 Ollama 大模型
- 让模型输出结构化 JSON：任务类型、取货点、放货点、物料
- 信息不全时返回追问

### 7.2 Prompt 模板（核心）

```
你是一个工业搬运任务解析器。把用户指令转成 JSON。

可用工位：station_a（A点）、station_b（B点）
可用物料：box_1（一号箱子）

支持的动作：
- NAVIGATE: 导航到某个工位
- PICK: 抓取物料
- PLACE: 放下物料

用户说："{text}"

只输出 JSON，格式：
{
  "task_type": "TRANSPORT",
  "pickup_station": "station_a",
  "dropoff_station": "station_b",
  "object_id": "box_1",
  "missing_fields": []
}

如果信息不全，把缺的字段写在 missing_fields 里。
```

### 7.3 调用 Ollama

```python
import requests

def call_ollama(prompt):
    resp = requests.post("http://127.0.0.1:11434/api/generate", json={
        "model": "qwen3.5:2b",
        "prompt": prompt,
        "stream": False
    })
    return resp.json()["response"]
```

### 7.4 验证

```bash
# 测试"把 box_1 从 A 搬到 B"
# 预期输出完整 JSON
# 测试"搬到 B 点"（缺取货点和物料）
# 预期 missing_fields 非空
```

## 第八步：做草稿存储节点（ai_edge 包）

### 8.1 功能

- SQLite 存草稿，重启不丢
- 保存草稿 → 返回草稿 ID 和版本号
- 确认草稿 → 状态变成"已确认"
- 修改草稿 → 版本号 +1，旧确认失效

### 8.2 表结构

```sql
CREATE TABLE drafts (
    draft_id TEXT PRIMARY KEY,
    body TEXT NOT NULL,      -- JSON 格式的任务步骤
    state INTEGER,           -- 0=编辑中, 1=已确认, 2=已取消
    revision INTEGER,        -- 版本号
    created_at INTEGER,
    updated_at INTEGER
);
```

### 8.3 验证

```bash
# 保存草稿
ros2 service call /ai/task_drafts/save ...
# 查询草稿
ros2 service call /ai/task_drafts/query ...
# 重启程序，草稿还在
```

## 第九步：做 PySide6 工作台（robot_visualization 包）

这是用户直接看到的窗口。

### 9.1 整体布局

```
┌─────────────────────────────────────────────────────┐
│ 顶部栏：标题 + 状态徽章 + 时钟                        │
├──────┬──────────────────────────────┬──────────────┤
│ 左侧  │ 中间主内容区                  │ 右侧状态栏    │
│ 导航  │  - 地图/摄像头                │  - 机器人状态  │
│      │  - 录音控制 + ASR 文字        │  - 电池/网络  │
│ 首页  │  - 任务候选 + 草稿表格         │  - 服务状态    │
│ 地图  │  - 日志面板                    │  - 当前任务    │
│ 草稿  │                              │              │
└──────┴──────────────────────────────┴──────────────┘
```

### 9.2 关键要点

1. **ROS 跑在子线程**：用 QThread 跑 rclpy.spin()，不阻塞 Qt 主线程
2. **用 Signal 通信**：ROS 收到消息后发 Qt Signal，主线程更新 UI
3. **一键启动所有节点**：app.py 启动时用 subprocess 拉起后端节点，关窗口时全部杀掉
4. **日志分级**：INFO 显示给用户，DEBUG 默认隐藏，加个复选框切换

## 常见坑

| 问题 | 原因 | 解决 |
|---|---|---|
| ASR 启动慢 | 模型加载要 30 秒 | 等日志显示"已就绪"再录音 |
| 语义结果不对 | prompt 里白名单和实际配置不一致 | 检查 allowed_station_ids 参数 |
| PySide6 崩溃 | 装了 6.12.0 | 卸载重装 6.8.3 |
| WSL 没声音 | PulseAudio 没配好 | `parecord --list-devices` 看设备 |
| 草稿连不上 | get_parameter_or 方法不存在 | 改成 get_parameter() |
| 节点起不来 | 端口/域名冲突 | 检查 ROS_DOMAIN_ID |
