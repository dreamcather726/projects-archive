# PySide6 语音交互工作台

当前界面显示真实录音、语音识别、语义候选、最近记录、服务状态和运行日志。主窗口参考监控平台图片，采用顶部栏、左侧导航、中间主内容和右侧状态栏；地图、相机、底盘、电池和机器人执行区域明确显示待接入。

左侧导航包括首页、地图与定位、机器人状态、任务管理、相机图像、日志分析、系统设置。默认1440×900，左侧120像素、右侧260像素，中间自适应；较小屏幕限制初始尺寸。首页同时展示录音、ASR、候选、当前语音阶段和日志；长列表、文字及摘要通过按钮分页，不使用主窗口滚动条。右侧服务状态常驻，工位／物料管理位于系统设置内部页签。

手动编排时，先选中步骤，再在表格下方修改动作，通过分页选择框选择已配置的物料和工位，修改即时生效。双击单元格会聚焦选择栏，不再进入表格行内编辑。长草稿在”动作编辑”分页查看，在”审阅摘要”分页核对；保存包含所有页面的步骤。操作日志输出到终端与日志页。原生崩溃会打印线程堆栈，需保留完整错误而不只保留最后一行 Segmentation fault。

新增的草稿编辑、确认和长录音功能见[任务草稿与长任务](任务草稿与长任务.md)。接口现为0.3.1，所有相关包须完整重建。

## 界面布局

窗口标题为”机器人可视化与监控平台 · 三栏监控版”，整体分四块：

| 区域 | 内容 |
|---|---|
| 顶部栏（64px） | 机器人图标、平台标题、系统在线徽章、AI 编排连接徽章、任务状态徽章、每秒刷新的北京时间 |
| 左侧导航（120px） | 首页、地图与定位、机器人状态、任务管理、相机图像、日志分析、系统设置 |
| 中间主内容区 | 首页上排：SLAM 地图、摄像头画面；中排左：语音／文本页签、录音控制、ASR 文字、任务候选；中排右：任务流程四步、当前步骤、任务信息、执行进度条；底部：系统日志、请求 ID 查询、清空显示 |
| 右侧常驻栏（260px） | 机器人状态（位置/速度）、底盘状态、电池电量、网络连接、服务状态徽章（麦克风/音频接收/语音识别/语义解析/AI 编排/任务草稿）、当前任务 |

各导航页对应的内容：任务管理页放完整草稿编辑表格；日志分析页放运行日志和历史记录；系统设置页放工位管理、物料管理和当前配置。地图、相机、底盘、电池、网络在 SIM 模式下由 robot_simulator 提供模拟数据，真实硬件接入后替换为对应 Topic 订阅。日志面板顶部有”显示调试日志”复选框，默认只显示 INFO 和 ERROR，勾选后显示全部 DEBUG 级别日志。

### 更新后整个窗口仍然是长页面

新界面的窗口标题带“三栏监控版”，左侧是七项导航，首页为双列卡片，右侧是常驻状态栏。如果仍看到原顶部八个页签，或者录音、结果、草稿和日志纵向排列在长页，运行内容与当前源码布局不一致。常见原因是只更新源码而没有重建安装副本，或者终端加载了另一个工作空间。需要先核对实际路径，不能直接认定是哪一种原因。

先关闭旧工作台，在 **Ubuntu 中实际存放本仓库的目录** 执行 `git pull --ff-only`（Windows 仓库更新不会自动更新另一个 Ubuntu 克隆）。再打开新终端，在 ROS 工作空间根目录执行：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --packages-select robot_visualization
source "$PWD/install/setup.bash"
ros2 pkg prefix robot_visualization
/usr/bin/python3 -c 'import robot_visualization.ui.window as w; print("界面代码：", w.__file__); print("界面布局：", getattr(w.DashboardWindow, "LAYOUT_DESCRIPTION", "旧版或未标识"))'
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard --ros-args \
  -p allowed_station_ids:="[station_a, station_b]" \
  -p allowed_object_ids:="[box_1]"
```

上面只重建前端，适用于已经完成 0.3.1 接口构建、仅更新界面的情况；首次部署仍按后文完整构建。白名单按实际项目配置修改。构建失败时先处理报错，不继续用旧安装副本启动。

包路径应属于当前工作空间的 `install`，Python 文件也应来自该工作空间的安装目录（使用符号链接安装时可以解析到其源码目录），布局说明应包含“三栏监控工作台”。启动终端也会打印这两项。只有窗口标题、七项导航和加载路径均对应新版，才说明本次更新已在实际运行的界面生效；`--prefix /usr/bin/python3` 只选择解释器，不会把旧安装代码切换为新源码。

## 1. 首次准备

运行位置：PC 的 WSL Ubuntu-22.04 / ROS 2 Humble，使用 WSLg 显示窗口。先更新、构建并安装 PySide6，现有 FunASR 和 Ollama 模型沿用：

```bash
cd ~/ai-interaction-ui/src
git pull --ff-only origin main
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
/usr/bin/python3 -m pip install --user -r src/robot_visualization/requirements.txt
```

正常应看到四个包构建完成，PySide6 安装成功。工作台可执行入口为 `robot_visualization dashboard`。不要把安装依赖的 Python 命令当作节点启动方式，所有节点均通过 ros2 run 启动。

### PySide6 依赖替换与崩溃排查

ROS 2 Humble 使用 Python 3.10，项目将 GUI 依赖固定到 PySide6 6.8.3。Python 3.10/3.11 搭配 PySide6 6.12.0 已有 `Fatal Python error: none_dealloc: deallocating None` 的[同类故障报告](https://qiskit-community.github.io/qiskit-metal/roadmap.html)。这属于原生扩展引用计数异常，堆栈中的 ROS 回调或 `app.exec()` 只是崩溃时的位置，不能单凭该位置认定出错组件；`UNSUPPORTED_TASK` 是另一个语义业务结果。

若已安装 6.12.0，请先关闭工作台，在 Ubuntu 终端手动替换整套 Qt Python 依赖。6.12 拆分出的 Pdf/WebEngine 包也一并移除，避免残留依赖要求重新安装 6.12：

```bash
/usr/bin/python3 -m pip uninstall -y \
  PySide6 PySide6-Essentials PySide6-Addons \
  PySide6-Pdf PySide6-WebEngine shiboken6
/usr/bin/python3 -m pip install --user "PySide6==6.8.3"
/usr/bin/python3 -m pip show PySide6 PySide6-Essentials PySide6-Addons shiboken6
```

四个包版本应全部为 `6.8.3`。只替换 Python 依赖无需重新构建 ROS 包。随后使用下节命令启动，先静置窗口，再录音并等待解析返回，最后关闭窗口；观察是否仍然自动退出。若继续崩溃，请保留首个 Fatal 提示及其后的完整堆栈，继续排查；依赖替换尚需在实际运行环境复测，不能据此保证所有崩溃都已解决。

## 2. 一个命令启动全部现有功能

每个新终端先加载 ROS 和工作空间，然后运行：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
source ~/ai-interaction-ui/install/setup.bash
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard --ros-args \
  -p asr_python:=/usr/bin/python3
```

工作台自动通过 ros2 run 启动音频接收、FunASR、千问语义解析、AI 编排和真实麦克风及草稿管理六个节点；本地 Ollama 不可达且已安装 ollama 时会启动 `ollama serve`。模型仍使用 `qwen3.5:2b`，不会自动拉取 Ollama 权重。启动后的模型加载需要时间，等 ASR 为“已就绪”、麦克风状态已确认后再录音。

默认音频目录是相对路径 `received_audio`，以启动目录为基准。请从包含 `src`、`build`、`install`、`log` 的工作空间根目录启动，录音 WAV、同名识别 TXT 和语义解析 JSON 会保存在与 `src` 同级的 `received_audio/`。工作台与独立启动的接收、编排、ASR 节点使用一致的默认值；内部会解析成绝对路径用于文件交接，不再固定到某个用户的旧工作空间。

```text
ai-interaction-ui/
├── build/
├── install/
├── log/
├── src/                  # 源码
└── received_audio/       # 运行数据，首次保存音频时自动创建
    ├── audio_时间_UUID.wav
    ├── audio_时间_UUID.txt
    └── audio_时间_UUID.parse.json
```

ASR 从本仓库的 `models/SenseVoiceSmall` 加载模型，准备方法见 [本地模型说明](../models/README.md)。缺少完整权重时报告故障，不自动回退到用户缓存。麦克风使用默认 PulseAudio 设备，也可指定为 RDPSource。完整参数例子：

```bash
ros2 run --prefix "$HOME/venvs/ros2_audio/bin/python" robot_visualization dashboard --ros-args \
  -p device:=RDPSource \
  -p allowed_station_ids:="[station_a, station_b]" \
  -p allowed_object_ids:="[box_1]"
```

首次可以用启动白名单导入真实ID，默认不创建虚构资料。也可在工位管理、物料管理页添加名称和语音别名；已有资料库优先，启动白名单不会覆盖它。空白名单仍可完成录音和ASR，但不能生成包含任意工位的完整候选。详见[工位与物料管理](工位与物料管理.md)。

需要自定义数据目录时，例如 `-p audio_root:=data/audio`，该目录仍相对于启动目录。工作台会将同一个目录传给它启动的所有音频节点；手动分终端启动时，各终端应进入相同的工作空间根目录，或显式指定相同的绝对路径。已经运行的节点不会自动更换目录，更新配置后需重新启动。原目录中的历史文件不会自动移动。

第一次切换一键启动时，可先停止以前手动启动的节点。工作台发现同名已有节点会沿用它们，它们仍使用原参数；不会替用户修改正在运行节点的模型和文件目录。相同 ROS_DOMAIN_ID 只允许一个工作台负责启动，其他窗口只连接。与其他机器人组联调时，沿用实际 ROS_DOMAIN_ID。

## 3. 录音按钮

1. 点击“开始录音”，或在窗口中按 Alt+R。按钮发起 `/audio/start_recording`，等待异步响应期间禁止重复提交。
2. 设备状态变为“录音进程运行中”，界面显示本次观察计时；该计时不是硬件采样时间，也不用于判断设备是否已停止。
3. 说完点击“停止并识别”，或按 Alt+S。实际调用 `/audio/stop_recording`，设备保存的 PCM 经接收节点写为 WAV，然后自动进入 ASR 和语义解析。
4. 不手动停止时，麦克风节点默认最长120秒自动停止，可配置为1～300秒；界面根据设备实际广播恢复待机。
5. 查看识别文字和任务候选；缺少字段时显示澄清问题，不支持输入时显示原因。候选不会自动进入任务准备或机器人执行。

停止响应成功只表示音频已发布；后续保存、ASR、语义处理各自显示真实结果。服务超时显示“结果未确认”，不自动重发开始请求。设备状态超过三秒未刷新时显示未确认，开始按钮保持禁用，停止入口仍可用于确认停稳。

## 4. 界面数据和记录

- 服务连接：通过 ROS 服务发现、节点发现和 ComponentStatus 判断。语义“服务在线”表示 Action 可调用，不代表模型一定已加载成功。
- 阶段条：只显示音频接收、语音识别、语义解析与结果保存的实际阶段，不生成百分比或模拟音量波形。
- 最近记录：当前窗口最多缓存 100 条，按 request_id 关联音频、文字和候选；切换记录不会再次调用识别。
- 查询：输入原始音频 request_id 后点击“查询已有记录”，调用 QueryAudio 恢复实际快照。AI 编排重启后内存记录消失，界面不会扫描旧文件重新识别。
- 文件：WAV、同名 .txt 和 .parse.json 保存在音频目录，失败／静音不生成假文字。
- 日志：界面最多显示 1000 行；本次启动节点的日志保存到 `~/.local/state/ai_interaction/dashboard_日期时间_进程号.log`。当前窗口未启动的节点也通过 ROS 回执与 rosout 提供说明。

启动终端会实时回显后台进程输出，也可切换到“运行日志”页逐页查看。控制台包括：

- 工作台和 ASR 实际使用的 Python 路径、模型、音频目录、日志文件位置。
- 每个后台节点的启动命令、进程号和退出码；进程启动不代表模型已经就绪。
- 服务连接变化、开始录音不可用的原因、录音请求发送及设备响应。
- FunASR 依赖导入、模型初始化与耗时、加载失败的完整异常堆栈。初始化未结束时每十秒提示一次已等待时间。
- 每条音频的请求 ID、ASR／语义阶段、等待上限、处理耗时和结果文件路径；长时间等待结果时每十秒提示一次。

相同服务状态和重复心跳不会持续刷屏；等待时间不代表模型下载或推理进度百分比。子进程的 Python 输出使用无缓冲模式，即使将控制台重定向到文件也会及时刷新。已有外部节点仍使用它们原来的输出设置。

界面不会把 READY 候选显示成“机器人任务执行成功”。草稿确认只记录人工审阅，不下发运动，不提供尚未接入的机器人执行控制。

## 5. 香橙派和仅显示模式

真实麦克风节点在香橙派上时，PC 不再启动第二个麦克风节点：

```bash
ros2 run --prefix "$HOME/venvs/ros2_audio/bin/python" robot_visualization dashboard --ros-args \
  -p start_microphone:=false
```

香橙派启动更新后的 `ros2 run ai_interface microphone_sender_node`，两端 ROS 环境、域编号和网络发现须一致。录音按钮直接调用设备服务。麦克风通过已有 ComponentStatus 广播真实进程状态，未更新的旧设备节点没有该状态时，界面不会凭倒计时猜测已就绪。

全部后端已由其他方式管理时，只运行界面：

```bash
ros2 run --prefix "$HOME/venvs/ros2_audio/bin/python" robot_visualization dashboard --ros-args \
  -p start_backend:=false
```

关闭窗口会等待后台清理，只终止本窗口创建的进程组；外部已有节点和 Ollama 服务继续保留。启动时打印“沿用外部节点”的进程，会在关闭时明确提示保留。本窗口明确发起的外部设备录音会尝试停止，响应缺失时不能认为设备已确认停稳，设备仍受 max_recording_seconds 配置的录音上限约束。

界面接收后台状态、记录、日志和线程结束消息时，使用显式 Qt 槽及队列连接，确保更新控件和关闭窗口都在 GUI 主线程执行。

Linux／WSL 下，每个自动启动的节点都有父进程退出保护。即使界面发生原生崩溃、未能执行 Python 的正常退出流程，也会触发对所创建进程组的清理。正常退出同样按整个进程组检查，避免 `ros2 run` 包装进程先退出、实际节点仍存活时漏掉清理。退出依次使用 SIGINT、SIGTERM、SIGKILL；终端只有在确认进程组消失后才报告“已全部退出”。这项保护不接管外部节点；若仍出现 Qt 原生崩溃，需要保留完整终端错误继续排查。

## 6. 模块分工与验证

| 目录／文件 | 职责 |
|---|---|
| `robot_visualization/app.py` | ROS 可执行入口、Qt 与通信组件装配 |
| `robot_visualization/ui/` | 样式、卡片、窗口、按钮信号和展示 |
| `robot_visualization/state.py` | 请求关联、乱序和旧进程状态过滤 |
| `robot_visualization/ros/` | 专用线程、异步服务、订阅和快照查询 |
| `robot_visualization/runtime/` | ros2 run 进程启动、日志和退出清理 |
| `ai_interface/devices/capture_health.py` | 麦克风实际进程状态广播 |

上述路径相对于各功能包根目录。GUI 主线程不加载模型或阻塞等待 ROS，通信线程通过 Qt Signal 更新窗口。实现参考 [Qt QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)，按钮测试使用 [Qt QTest](https://doc.qt.io/qtforpython-6/PySide6/QtTest/QTest.html)。

回归命令（已加载工作空间环境，使用现有虚拟环境解释器）：

```bash
QT_QPA_PLATFORM=offscreen ~/venvs/ros2_audio/bin/python -m unittest discover -s src/robot_visualization/test -v
~/venvs/ros2_audio/bin/python -m unittest discover -s src/ai_edge/test -v
```
