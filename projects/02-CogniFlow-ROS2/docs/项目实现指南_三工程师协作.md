# AI 语音交互工作台 · 三工程师协作实现指南

> 本文档面向三位学员：**AI 端侧工程师**、**接口工程师**、**前端可视化工程师**。读完本文后，三人能独立完成各自模块，并按约定接口联调出一个完整的 ROS 2 语音搬运机器人工作台。

---

## 一、项目总览

### 1.1 项目目标

工人对着麦克风说一句"把 box_1 从 A 点搬到 B 点"，系统自动：
1. 采集音频 → 保存 WAV
2. 语音识别（ASR）把语音转成文字
3. 大模型语义解析成结构化任务步骤（导航→抓取→导航→放下）
4. 信息不全时主动追问"要搬运哪个物料？"
5. 人工核对草稿后保存，等待后续机器人执行

### 1.2 系统架构

```
┌─────────────────┐     PC 端（WSL Ubuntu 22.04 + ROS 2 Humble）
│   麦克风 / 香橙派 │
│  (接口工程师)     │
└────────┬────────┘
         │ audio_data (PCM)
         ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│ audio_receiver  │───►│ audio_processing│───►│  parse_task     │
│ (接口工程师)     │    │  (AI 端侧)      │    │  (AI 端侧)      │
│  保存 WAV       │    │  编排调度        │    │  Ollama 语义    │
└─────────────────┘    └────────┬────────┘    └────────┬────────┘
                                │                      │
                                ▼                      ▼
                         ┌─────────────────┐    ┌─────────────────┐
                         │    asr_node     │    │  task_draft     │
                         │  (AI 端侧)      │    │  (AI 端侧)      │
                         │  FunASR 识别    │    │  SQLite 草稿    │
                         └─────────────────┘    └─────────────────┘
                                                         │
                                                         ▼
                                              ┌─────────────────┐
                                              │  robot_visualization│
                                              │  (前端可视化)     │
                                              │  PySide6 三栏 UI │
                                              └─────────────────┘
```

### 1.3 三个角色分工

| 角色 | 负责的包 | 核心任务 |
|---|---|---|
| **接口工程师** | `robot_interfaces`、`ai_interface`、`robot_simulator` | 定义消息接口、麦克风采集、音频接收落盘、模拟硬件数据 |
| **AI 端侧工程师** | `ai_edge` | FunASR 语音识别、Ollama 语义解析、多轮追问、SQLite 草稿存储 |
| **前端可视化工程师** | `robot_visualization` | PySide6 三栏工作台、录音控制、任务候选展示、草稿编辑表格、日志面板 |

### 1.4 技术栈

- ROS 2 Humble（Ubuntu 22.04）
- Python 3.10
- ASR：FunASR / SenseVoiceSmall（约 936MB）
- 语义：Ollama + qwen3.5:2b（本地 11434 端口）
- GUI：PySide6 6.8.3（固定版本，6.12.0 有崩溃问题）
- 数据库：SQLite

## 二、环境准备（所有人都要做）

```bash
# 1. 安装 ROS 2 Humble（Ubuntu 22.04）
# 参考官方文档，安装 ros-humble-desktop

# 2. 创建工作空间
mkdir -p ~/ai-interaction-ui/src
cd ~/ai-interaction-ui

# 3. 创建四个功能包（接口工程师先做）
cd src
ros2 pkg create robot_interfaces --build-type ament_cmake
ros2 pkg create ai_interface --build-type ament_python
ros2 pkg create ai_edge --build-type ament_python
ros2 pkg create robot_visualization --build-type ament_python

# 4. 安装 ASR 虚拟环境（AI 端侧工程师做）
python3 -m venv ~/venvs/ros2_audio
source ~/venvs/ros2_audio/bin/activate
pip install funasr modelscope torch torchaudio
# 模型放在 models/SenseVoiceSmall

# 5. 安装 Ollama（AI 端侧工程师做）
curl https://ollama.ai/install.sh | sh
ollama pull qwen3.5:2b

# 6. 安装前端依赖（前端工程师做）
pip install PySide6==6.8.3

# 7. 构建
cd ~/ai-interaction-ui
colcon build --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
```

## 三、接口工程师任务

### 3.1 第一步：定义消息接口（robot_interfaces 包）

这是所有工程师的契约，**先做完这一步再开始各自开发**。

在 `robot_interfaces/msg/` 下创建：

# RecognizedText.msg —— ASR 识别结果

### 3.2 第二步：麦克风采集节点（ai_interface/audio/microphone_sender_node.py）

**功能**：调用 `parecord` 采集 16kHz / 16bit / 单声道 PCM，按 0.5 秒一块通过 Topic 发送。

**关键实现点**：
- 提供 `/audio/start_recording` 和 `/audio/stop_recording` 两个 Service
- 用 `subprocess.Popen` 启动 `parecord --format=s16le --rate=16000 --channels=1`
- 从 stdout 管道读 PCM，拼成 AudioSegment 消息发布
- 最长录音时长可配置（默认 120 秒，1~300 秒可调）
- 发布 ComponentStatus（component_id=microphone）

**验收**：
```bash
ros2 run ai_interface microphone_sender_node
ros2 service call /audio/start_recording std_srvs/srv/Trigger
# 说一句话，再停止
ros2 topic echo /audio_data
# 能看到 PCM 数据流动
```

### 3.3 第三步：音频接收节点（ai_interface/audio/audio_receiver_node.py）

**功能**：订阅麦克风发来的 PCM，攒够一段后保存为 WAV 文件，然后通知 AI 编排节点处理。

**关键实现点**：
- 订阅 `/audio_data`
- 收到 stop 信号后，把所有 PCM 块拼成完整 WAV（用 `wave` 库写文件头）
- WAV 保存到 `received_audio/` 目录，文件名格式 `audio_时间_UUID.wav`
- 保存完成后发布 AudioProcessingState（stage=QUEUED）
- 同时发布原始文件路径给下游

**验收**：
```bash
# 跑起来后录音停止，received_audio/ 下应该出现 .wav 文件
# 用 audacity 或 ffplay 能正常播放
```

### 3.4 第四步：模拟器节点（robot_simulator，可选但推荐）

在没有真实硬件时，模拟所有传感器数据让前端能完整展示：
- `map_simulator_node`：发布假 OccupancyGrid 地图
- `camera_simulator_node`：发布假 image_raw（带时间戳的彩色测试图）
- `robot_state_simulator_node`：发布假里程计、电池、网络状态
- `execute_task_action_server`：收到确认草稿后按步骤发进度反馈

**验收**：
```bash
ros2 launch robot_simulator simulator_all.launch.py
# rqt_graph 能看到所有模拟节点
# rqt_image_view 能看到摄像头画面
```

## 四、AI 端侧工程师任务

### 4.1 第一步：ASR 节点（ai_edge/asr/asr_node.py）

**功能**：接收 WAV 文件路径，调用 FunASR 把语音转成文字。

**关键实现点**：
- 用独立 venv（`~/venvs/ros2_audio/bin/python`）启动，因为 FunASR 依赖和系统 ROS Python 冲突
- 启动时后台线程加载 SenseVoiceSmall 模型（加载约 10~30 秒）
- 提供 `/ai/recognize_audio` 接口，输入 WAV 路径，输出 RecognizedText
- 模型加载期间发布 ComponentStatus（state=BUSY），完成后 state=READY
- 超时保护：识别超过 180 秒返回 ASR_TIMEOUT，不卡死
- 用 Future + 定时器回收，不阻塞 ROS 回调线程

**验收**：
```bash
ros2 run ai_edge asr_node
# 等日志显示"FunASR 模型已就绪"
# 用一段中文 WAV 测试，能输出正确文字
```

### 4.2 第二步：AI 编排节点（ai_edge/audio/audio_processing_node.py）

**功能**：串起整个音频处理流水线：接收 WAV → 调 ASR → 调语义解析 → 发布最终结果。

**关键实现点**：
- 订阅 audio_receiver 发来的"新音频就绪"消息
- 维护一个处理队列（最多 10 个并发，满了返回 PIPELINE_BUSY）
- 调用 ASR 的服务，拿到文字后再调用语义解析的 Action
- 全过程发布 AudioProcessingState，让前端能看到当前阶段
- 去重：同一 request_id 不重复处理（用 OrderedDict 缓存最近 1024 条）

**验收**：
```bash
# 录音停止后，日志依次出现：
# QUEUED → WAITING_ASR → RECOGNIZING → WAITING_PARSE → PARSING → READY
```

### 4.3 第三步：语义解析节点（ai_edge/semantic/parse_task_node.py）

**功能**：把 ASR 文字发给 Ollama 大模型，让它输出结构化任务 JSON。

**关键实现点**：
- 提供 `/ai/parse_task` Action
- 构造 prompt：告诉模型支持的动作类型（NAVIGATE / PICK / PLACE）、可用工位列表、可用物料列表
- 要求模型输出严格 JSON：
  ```json
  {
    "task_type": "TRANSPORT",
    "pickup_station": "station_a",
    "dropoff_station": "station_b",
    "object_id": "box_1",
    "missing_fields": []
  }
  ```
- 解析模型返回的 JSON，校验字段类型和白名单
- 缺字段时返回 NEED_CLARIFICATION + 追问问题（"要搬运哪个物料？"）
- Ollama 连接失败返回 LLM_UNAVAILABLE

**Prompt 模板参考**：
```
你是一个工业搬运任务解析器。把用户的指令转换成结构化 JSON。
支持的工位：{stations}
支持的物料：{objects}
动作类型：NAVIGATE（导航）、PICK（抓取）、PLACE（放下）

用户说："{text}"

只输出 JSON，不要解释。如果信息不全，在 missing_fields 里列出缺什么。
```

**验收**：
```bash
# 输入"把 box_1 从 A 点搬到 B 点"
# 预期输出完整候选，READY 状态
# 输入"搬到 B 点"
# 预期返回 NEED_CLARIFICATION，追问取货点和物料
```

### 4.4 第四步：多轮对话澄清（ai_edge/semantic/dialogue.py）

**功能**：用户第一次说不全时，第二次回答能补全而不丢失已有信息。

**关键实现点**：
- 按 `(session_id, input_context_id)` 缓存待补充的候选
- 第二次录音时，把已有候选 + 追问历史 + 新回答一起发给模型
- 模型补全后校验，通过则返回 READY
- 用户说"取消""重新开始"时清空缓存
- 超时 300 秒自动过期
- 最多缓存 32 个待补充上下文

**验收**：
```bash
# 第一轮："去 A 点拿东西送到 B 点" → 缺物料，追问
# 第二轮："一号箱子" → 自动补全为 box_1，A→B 保留不变
```

### 4.5 第五步：草稿存储节点（ai_edge/task_drafts/node.py）

**功能**：把用户确认的任务步骤存到 SQLite，支持版本管理和确认令牌。

**关键实现点**：
- SQLite 数据库文件：`task_data/task_drafts.sqlite3`
- 提供三个 Service：保存草稿、确认/取消草稿、查询草稿
- 草稿保存时返回 draft_id、版本号、确认令牌（5 分钟有效）
- 用户修改草稿后版本号 +1，旧确认令牌失效，必须重新确认
- 草稿状态：0=编辑中，1=已确认，2=已取消，3=已过期
- 事务用 `isolation_level=None` + 统一的 `@contextmanager transaction()` 管理

**验收**：
```bash
# 保存草稿 → 返回 draft_id
# 确认草稿 → 状态变为"已确认"
# 修改草稿重新保存 → 版本号增加，旧确认失效
# 重启程序 → 草稿还在（SQLite 持久化）
```

## 五、前端可视化工程师任务

### 5.1 第一步：三栏布局（robot_visualization/ui/monitor_layout.py）

**窗口结构**：
- 顶部 64px：标题、状态徽章、时钟
- 左侧 120px：导航（首页/地图与定位/机器人状态/任务管理/相机图像/日志分析/系统设置）
- 中间自适应：主内容区
- 右侧 260px：状态栏（机器人/底盘/电池/网络/服务状态/当前任务）

**首页分区**：
- 上排：左=SLAM 地图控件，右=摄像头画面
- 中排左：录音控制 + ASR 文字 + 任务候选
- 中排右：任务流程四步 + 当前步骤 + 执行进度条
- 底部：日志面板

### 5.2 第二步：ROS 通信线程（robot_visualization/ros/worker.py）

**关键实现点**：
- 用 QThread 跑 ROS 节点，不阻塞 Qt 主线程
- 用 Qt Signal 把 ROS 消息传回主线程更新 UI
- 启动时自动拉起后端节点（音频接收、ASR、语义、编排、草稿）
- 窗口关闭时优雅清理所有子进程

### 5.3 第三步：录音控制

- "开始录音"按钮（Alt+R）：调用 `/audio/start_recording` Service
- "停止并识别"按钮（Alt+S）：调用 `/audio/stop_recording` Service
- 录音中按钮置灰，防止重复点击
- 设备状态实时显示（待机/录音中/错误）

### 5.4 第四步：ASR 文字和任务候选显示

- 左栏：实时显示 ASR 识别出的文字
- 右栏：显示解析后的任务步骤列表（导航到 A → 抓取 box_1 → 导航到 B → 放下 box_1）
- 缺参数时显示追问问题
- 长文字用分页按钮翻页，不用滚动条

### 5.5 第五步：草稿编辑表格（robot_visualization/ui/task_drafts.py）

**功能**：用户可以手动编辑任务步骤。

- 表格三列：动作、物料、工位
- 按钮：新建草稿、+导航、+抓取、+放下、上移、下移、删除
- 保存草稿、确认草稿、取消草稿
- 草稿列表下拉框（分页，每页 5 条）
- 确认按钮只有在草稿已保存且版本最新时才可点

### 5.6 第六步：日志面板

- 显示所有节点的运行日志
- 顶部复选框"显示调试日志"：默认只显示 INFO 和 ERROR
- 输入 request_id 可以查询指定音频的历史记录
- 清空按钮
- 日志分页显示，最多保留 1000 行

### 5.7 第七步：硬件状态显示

- 右侧栏订阅 `/robot/component_status`，显示各组件在线状态
- SIM 模式下订阅模拟器发布的地图、摄像头、电池数据
- 每个状态用绿/黄/红徽章表示正常/警告/错误

**验收**：
```bash
ros2 run robot_visualization dashboard
# 窗口打开，三栏布局正确
# 录音 → ASR 文字出现 → 任务候选显示
# 加入草稿 → 编辑步骤 → 保存 → 确认
# 日志面板有内容
```

## 八、常见问题

**Q: ASR 启动很慢？**
A: SenseVoiceSmall 模型加载需要 10~30 秒，属正常。日志显示"模型已就绪"后再录音。

**Q: 语义解析结果不对？**
A: 检查 Ollama 是否在跑（`ollama serve`），prompt 里的工位/物料白名单是否和实际配置一致。

**Q: 前端连不上后端？**
A: 用 `ros2 node list` 看后端节点是否都在。如果工作台启动了但服务状态都是灰色，检查 ROS_DOMAIN_ID 是否一致。

**Q: PySide6 崩溃？**
A: 确认版本是 6.8.3，不要用 6.12.0。卸载方法见前端使用说明文档。

**Q: 录音没声音？**
A: WSL 下检查 PulseAudio 是否正常，`parecord --list-devices` 看麦克风设备。
