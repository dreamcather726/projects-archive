# 任务草稿、确认界面和长任务

本次实现新增任务草稿编辑、SQLite 保存、人工确认和取消。确认只表示用户审阅了这份草稿，没有调用 `/task/prepare`、`/task/execute` 或导航／抓取接口，不会把机器人状态伪装成已准备或已完成。未来执行层必须再次准备、检查机器人条件并绑定任务版本，不能把草稿确认令牌当成运动授权。

## 动作组合（0.3.1）

草稿中的基本动作改为 **导航到某点（NAVIGATE）、抓取物料（PICK）、放下物料（PLACE）**。A点、B点都是导航目标参数，不是不同动作类型。表格只显示“动作、物料、目标／操作工位”三列。

例如把 box_1 从 A 搬到 B，会确定性展开成：

| 顺序 | 动作 | 物料 | 工位 |
|---|---|---|---|
| 1 | 导航到 | — | station_a |
| 2 | 抓取 | box_1 | station_a |
| 3 | 导航到 | — | station_b |
| 4 | 放下 | box_1 | station_b |

要求返回时，再追加独立导航动作。加入多个搬运候选时依次展开，已经拆开的动作不会重复展开。保存和确认的是展开后的完整列表；256步限制按展开后的动作数计算。语义解析也支持直接说“导航到A、抓取一号箱子、导航到B、放下箱子”等动作组合。

“+ 导航／+ 抓取／+ 放下”可以自由添加行，并进行删除、上移和下移。选中步骤，在表格下方固定输入栏修改动作、物料和工位；输入即时写入当前步骤。双击物料或工位单元格只聚焦对应输入栏，不再创建表格行内编辑器。导航行的物料应留空；抓取和放下行需要填写物料及操作工位。新增抓取／放下时，会沿用本草稿最近一次导航明确填写的工位；放下可沿用尚未放下的抓取物料，不从白名单猜物料或猜机器人当前位置。计划中已有导航目标与随后抓取／放下工位矛盾、抓取后放下另一物料等情况，会被拒绝保存；计划开始时机器人的实际位置和抓持状态仍需未来执行层检查，不能由草稿推断为已就绪。

旧版本的一行搬运草稿在加载时展开，并要求重新保存、核对和确认。原始记录不会因界面加载而覆盖。超过展开上限时明确提示，不能截断动作。

## 可变长度任务

`TaskCandidate` 新增 `SEQUENCE=3` 和动态 `TaskStep[] steps`。原有 UNKNOWN/NAVIGATE/TRANSPORT 编号不变，单任务的 steps 为空。多任务顶层的物料和地点留空，每一步独立填写导航、抓取或放下参数，顺序与用户输入一致，不能嵌套步骤列表。

一次指令可以形成多步候选，也可以把多次录音的完整候选加入同一草稿。界面支持增删步骤、上下移动、选择已配置物料和工位ID，不固定成两步或四步。每份草稿设置 256 步资源保护上限，超限明确拒绝，不能静默截断。单次模型调用仍受上下文、输出和超时限制；很长的计划可以分段录音、逐段加入草稿。

列表中的缺项使用 `steps[0].object_id` 等路径标记。追问一次指出第一个缺参步骤，下一轮携带完整列表补充，不自动把一个回答填入每一步。需要增删或修改已有语音候选时，可以重新描述；草稿编辑器则允许显式修改并重新保存。

## 草稿生命周期

1. 录音识别和解析得到完整候选，点击“加入当前候选”。也可点击“+ 导航／+ 抓取／+ 放下”手动添加动作。
2. 在“任务草稿 → 动作编辑”核对参数，使用上一页／下一页查看长列表；在“审阅摘要”逐页核对完整顺序。更换动作类型时，也要核对物料和操作工位；导航不填写物料。
3. 点击“保存草稿”。服务端独立校验白名单与必填项，将整个列表原子保存到 SQLite，返回草稿 ID、版本、服务实例、确认令牌和五分钟到期时间。
4. 点击“确认草稿”。服务端检查同一实例、会话、上下文、版本和令牌，以及是否过期；确认结果持久保存，界面显示“已确认草稿，尚未执行”。
5. 编辑后确认按钮关闭，重新保存会增加版本并轮换令牌，旧按钮不能确认新内容。多人窗口同时修改时，旧版本保存被拒绝，需刷新后核对。
6. 点击“取消草稿”只关闭该草稿。尚未保存的本地内容可以用“新建草稿”清空；这不是机器人运动取消接口。

草稿存放在工作空间的 `task_data/task_drafts.sqlite3`，不提交 Git。服务重启保留步骤、来源和历史，但旧确认失效，需重新保存和审阅。ROS 时钟明显跳变也使旧确认失效。请求超时显示结果未知，不自动重发；用“刷新已保存版本”恢复，必要时从草稿列表选择对应记录。

草稿服务默认等待确认 `300.0` 秒，可独立启动时设置 `-p confirmation_timeout:=600.0`（范围 1～1800）。

## 长录音

- 工作台和独立麦克风节点新增 `max_recording_seconds`，默认 `120.0` 秒，可设为 1～300 秒；随时可以点击停止，不必等自动结束。
- PCM 传输上限同步扩大到 9,600,000 字节，接收、WAV 校验与 ASR 使用相同的 300 秒边界，WAV 文件上限为 10 MiB。
- ASR 按 25 秒的 PCM 片段依次识别并拼接文本；固定切分边缘的词可能识别不准，要核对原文，任何片段失败都不把部分文本当完整任务提交。
- ASR 超时默认 180 秒，编排等待 ASR 为 185 秒；语义服务默认 290 秒，编排等待解析为 300 秒。
- ASR／语义文本允许最多 16384 字符；最终提示词还有 16000 UTF-8 字节预算。模型上下文为 32768，输出最多 16000 token；长文本、长步骤列表可能超限或超时，报错后应分段录音，不能假定模型已完整处理全部内容。

## 接口和代码

| 接口 | 类型 | 用途 |
|---|---|---|
| `/ai/task_drafts/save` | `SaveTaskDraft` Service | 创建或按版本保存草稿 |
| `/ai/task_drafts/review` | `ReviewTaskDraft` Service | 确认／取消草稿审阅 |
| `/ai/task_drafts/query` | `QueryTaskDraft` Service | 获取指定草稿或最近100份 |
| `/ai/task_draft` | `TaskPlanDraft` Topic | 广播草稿状态变化 |

`ai_edge/task_drafts/store.py` 负责规则和持久化；`node.py` 封装 ROS 接口；`robot_visualization/ros/drafts.py` 管理异步请求；`ui/task_drafts.py` 管理编辑和按钮。草稿操作与录音控制分开，不在 Qt 主线程等待服务。

## 固定页面和编辑稳定性

主窗口现为三栏监控布局（详见[前端工作台使用说明](前端工作台_使用说明.md)的”界面布局”一节），任务草稿位于左侧”任务管理”，历史记录位于”日志分析”，工位和物料管理位于”系统设置”。没有外层滚动区；表格和历史按窗口可容纳的行数分页，文本按显示宽高换行分页，草稿和资料选择每组最多五条。滚轮不翻页，用导航、页签和上一页／下一页切换。分页只改变显示范围，保存、校验和摘要始终读取全部步骤，包含其他页面的动作。基础资料的维护和生效范围详见[工位与物料管理](工位与物料管理.md)。

针对双击物料格时报告的原生崩溃，本次移除表格的临时编辑器与每行常驻下拉框，改用固定输入栏；添加只插入新增行，移动只交换相关行，结构修改时屏蔽中间信号，摘要等当前回调返回后再刷新。确认资格在修改发生时立即撤销。终端和日志页记录编辑字段、增删、移动及请求操作，启动入口启用 `faulthandler`，再次发生原生崩溃时打印所有 Python 线程堆栈。

仅凭 `[ros2run]: Segmentation fault` 还不能确认原生根因；以上调整针对已知触发路径，尚未在用户 WSL 环境复测。若固定输入栏仍崩溃，请保留操作前后的完整日志及 Fatal 堆栈，连同 PySide6／shiboken6 版本继续定位。

接口版本升级至 **0.3.1**，新增 TaskStep/TaskPlanDraft 和3个服务，并调整 TaskCandidate、AudioSegment 和 ParseTask 的类型定义。所有相关节点都必须使用同一版本并完整重建；旧安装目录中的 Python 类型不能混用。

## 用户手动测试

本次没有执行构建、测试、录音、GUI 或模型验证。先关闭旧工作台和此前手动启动的相关节点，更新仓库后在 WSL 工作空间根目录执行：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard --ros-args \
  -p asr_python:=/usr/bin/python3 \
  -p audio_root:=received_audio \
  -p max_recording_seconds:=120.0 \
  -p allowed_station_ids:="[station_a, station_b]" \
  -p allowed_object_ids:="[box_1]"
```

1. 不录音，点击“新建草稿”“+ 导航”，填写导航目标 station_a，保存。确认应成功并显示尚未执行。
2. 加入搬运候选：预期四行分别为导航到A、抓取box_1、导航到B、放下box_1。也可用三个动作按钮逐条添加。保存后版本增加，需重新确认；上移、下移、删除后摘要顺序应一致，存在矛盾时不能保存。
3. 录音说“把一号箱子从A点送到B点，再从B点送回A点”。预期包含两次搬运意图，加入草稿后展开为八个动作，前后路线均保留。再次录音补充后续任务，加入同一草稿；重复点击同一候选不会重复添加。
4. 录制超过十秒的一段实际任务描述，核对 WAV、TXT 和候选；应不再在第十秒自动停止。长录音需要等待真实模型完成。
5. 删除某一步的物料或使用白名单外地点，保存应被拒绝；确认按钮不能绕过校验。
6. 保存后修改本地表格，确认按钮应禁用。重新保存后核对新版本，再确认。两个窗口修改同一版本时，旧版本不能覆盖新版本。
7. 测试取消、超过五分钟的确认、服务重启后刷新草稿：旧确认失效，但任务内容仍能查到并重新保存。整个过程中不应出现机器人已执行的提示。
8. 在“动作编辑”选中抓取动作，反复双击物料格；焦点应进入下方固定选择栏。选择已配置的 box_1，切换步骤再回来，值应保留；再执行上移、下移、删除和新建，观察控制台的草稿操作日志。添加足够多步骤后翻页，确认删除的是当前页所选步骤、摘要及保存结果仍包含其他页的数据。
9. 依次切换七项导航及系统设置中的资料页签，将窗口缩小至允许的最小尺寸；识别长文字、动作摘要和日志均应通过按钮翻页，鼠标滚轮不滚动内容。若仍是纵向长页面或顶部八页布局，按[前端使用说明](前端工作台_使用说明.md)核对 Ubuntu 仓库更新、重建及实际加载路径；新版标题明确显示“三栏监控版”。

可选离线规则测试（从工作空间根目录，由用户自行执行；仓库直接在根目录时删去路径中的 src/）：

```bash
PYTHONPATH="$PWD/src/ai_edge${PYTHONPATH:+:$PYTHONPATH}" \
  /usr/bin/python3 -m unittest discover -s src/ai_edge/test -p 'test_task*.py'
```

运行时可用 `ros2 topic echo /ai/task_draft` 观察实际草稿状态；不需要反复向 SLAM 组发送消息，这一阶段没有下发运动任务。
