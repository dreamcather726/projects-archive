# 上位机工位与物料管理

工位管理、物料管理保留为两个独立资料页面，入口位于左侧”系统设置”的内部页签。主窗口为三栏监控布局（详见[前端工作台使用说明](前端工作台_使用说明.md)的”界面布局”一节）。列表和选择框均通过按钮分页，表格不提供行内编辑器，滚轮不滚动页面。

## 维护资料

每条资料包含固定 ID、显示名称、最多八个语音别名和启用状态。每类最多128条；同类 ID、名称和别名不能相互指向不同对象，避免模型遇到同名资料时猜测。ID、名称和别名各为1～128字符，不允许控制字符或首尾空格。

1. 打开“工位管理”，点击“新增”，填写实际工位。例如 ID 为 `station_a`、名称为“取货区”、别名为“A点，A工位”，保存。示例不会自动创建到系统。
2. 在“物料管理”添加实际物料，例如 `box_1`、名称“一号箱子”、别名“箱子一号”。
3. 修改已有资料时先选中记录，修改下方表单并保存。已保存 ID 不在编辑表单中改名，以免改变历史草稿的引用含义。
4. 编辑期间列表暂时锁定，先保存再切换记录；“新增”或“刷新资料”可以放弃当前未保存表单。保存失败保留输入，多个窗口同时修改时会拒绝陈旧版本，刷新后重新核对。
5. 临时不用时取消“启用”并保存。删除会移除该资料；历史草稿中的 ID 不会被替换，重新保存和确认时仍按当前有效资料校验。建议优先停用，保留名称和别名以便查阅。

本阶段维护的是任务引用数据，不代表物料已被视觉系统发现，也不代表工位已有导航坐标。SLAM 地图目标和机器人位置仍需执行层对接，不生成虚构坐标或运动许可。

## 保存位置与生效范围

默认资料库是启动目录下 `task_data/catalog.sqlite3`，与音频数据分开，已由 `.gitignore` 排除。通过 `-p catalog_path:=...` 可设置其他路径；工作台会把同一绝对路径传给它新启动的编排、语义和草稿节点。

- 第一次创建资料库时，可用启动参数 `allowed_station_ids`、`allowed_object_ids` 导入初始 ID，名称先等于 ID，随后在界面完善。已有资料库不会被启动参数覆盖，停用或删除的记录不会在重启时复活。
- 保存通过通信线程处理，成功后更新界面与草稿选择框。名称及别名作为结构化数据进入模型本轮提示词，模型仍只能输出白名单中的 ID。
- 名称、别名、任务和历史合计仍受模型输入预算限制；启用资料和别名过多时明确报告上下文超限，需减少本次启用范围或精简别名，不会截断资料后冒充完整解析。
- 新任务读取当前启用项；编排还按提交时与接收时白名单的交集检查结果。后台白名单变化会使旧草稿确认失效，须重新保存、核对和确认。
- 草稿中原有但已停用／删除的 ID 会标为“未配置或已停用”，不会自动替换成第一项。物料和工位通过下方分页选择框修改，可以明确选择留空。
- 多窗口共享同一文件时使用 SQLite 事务和资料版本拒绝陈旧覆盖；后台定期向其他窗口刷新已保存版本，未保存表单保留并提示刷新。
- 已在外部启动的旧节点不会被接管或改参数。独立节点必须升级代码并传入同一 `catalog_path`；不同机器需要各自同步资料库，目前没有跨主机配置服务。界面的保存成功仅表示本地资料库已持久保存，不能当作外部节点已同步的回执。

## 用户手动复测

本次没有运行构建、GUI、ROS、模型或测试。更新 Ubuntu 源码后，关闭旧工作台及独立旧节点，在工作空间根目录自行执行：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard
```

按前文添加两个工位和一个物料；在“任务草稿”编排导航、抓取、导航、放下，通过选择框填写参数，保存并审阅。再使用自定义名称／别名录音，核对候选中的 ID。关闭重开后资料应保留，启动白名单不能覆盖已有资料。

停用一个被引用的物料后，旧草稿确认应失效，旧 ID 保留但无法作为有效新计划保存。两个窗口分别编辑同一版本，后保存者应收到版本冲突；翻看草稿选择框的另一页，未保存草稿应保留。长文字、表情、英文单词及其他页的动作不能丢失。
