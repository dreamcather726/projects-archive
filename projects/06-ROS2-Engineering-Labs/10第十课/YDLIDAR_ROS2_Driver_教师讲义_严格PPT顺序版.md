# 第 10 课｜YDLIDAR ROS2 Driver：逐页教师讲义

对应课件：`YDLIDAR ROS2 Driver 理论学习指南.pptx`。

按用户提供的截图逐页编写，每次只完成当前一页。每页以讲课思路为主，实验交代操作、观察、解释、验收和排查；优先使用厂商与 ROS 2 官方接口及示例。环境暂沿用课程的 Ubuntu 22.04 / ROS 2 Humble，实际雷达型号与参数需根据设备确认。

## 第 1 页｜YDLIDAR ROS2 Driver 理论学习指南

### 这页的讲课思路

**建议用 3～5 分钟建立主线，再按课堂条件做导入观察。**先承接第 9 课：底盘驱动主要回答“机器人怎样运动、运动了多少”；激光雷达驱动负责把周围环境的测距结果提供给 ROS 2。两者最终在定位、建图和导航中配合工作。

开场可以这样讲：

> **今天我们追踪一条环境数据链：雷达测到一个物体后，这个距离怎样经过设备接口、SDK 和驱动，成为 ROS 2 中的一帧扫描？为什么设备能转不代表有有效数据，RViz 能看到点也不代表已经完成建图？学完这一课，希望大家既能启动驱动，也能解释数据从哪里来、出了问题该查哪一段。**

**第一步：用一个具体场景提问。**在雷达可测范围内放一块纸板，问学生：“纸板移动后，程序里哪个数据会变化，画面又为什么变化？”先接受“距离发生变化”的直觉回答，不急着讲测距公式和协议。

**第二步：按封面的四个关键词交代学习路线。**

| 封面关键词 | 本课要解决的问题 | 此页讲到什么程度 |
| --- | --- | --- |
| 激光雷达原理 | 设备怎样获得角度和距离？ | 知道数据具有方向与距离，不假定所有型号测距原理相同 |
| 驱动架构 | 硬件、SDK、ROS 2 节点各做什么？ | 先看数据链和职责，代码随后续截图展开 |
| 数据处理 | 原始数据怎样组织成扫描？ | 引出角度、距离、时间和无效测量，不在封面逐字段讲解 |
| ROS 2 接口集成 | 下游怎样接收并正确使用数据？ | 认识扫描消息、话题和坐标系的作用 |

**第三步：明确驱动与算法的边界。**厂商[官方驱动 Humble 分支说明](https://github.com/YDLIDAR/ydlidar_ros2_driver/tree/humble)介绍了对 YDLidar-SDK 的依赖，以及扫描发布和可视化入口。可以先用下面的链路帮助学生定位模块：

```text
环境物体 → 雷达测量 → 设备通信 → YDLidar-SDK → ROS 2 驱动节点
                                             ↓
                                  scan（LaserScan 消息）
                                    ↙              ↘
                              RViz 观察       建图 / 定位等算法
```

SDK 和驱动的具体分工以后续代码为准；本页不指定实际设备是串口还是网络型号。`scan` 是厂商默认话题名，常见根命名空间下为 `/scan`，也可能被命名空间或重映射改变。扫描点是当前测量的表达，地图则需要另外的建图过程，不能把两者混为一谈。

### 实验导入：从“消息接口”看到“物体移动后的扫描变化”

**实验目的：**让学生先看见最终输出，再带着问题学习驱动内部流程。分为无硬件和实机两部分；没有雷达时完成第一部分即可，不用伪造已测到的扫描。

**准备：**Ubuntu 中已安装 ROS 2 Humble。实机部分另需确认具体 YDLIDAR 型号、供电与连接，已安装匹配的 SDK / 驱动，并由教师按型号完成参数配置和启动。厂商示例参数不能直接视为所有型号的通用配置。本页不执行完整安装，也不照搬默认参数启动未知型号。

**1. 无硬件：先查看驱动应该输出什么。**

```bash
source /opt/ros/humble/setup.bash
ros2 interface show sensor_msgs/msg/LaserScan
```

让学生只找出 `header`、角度相关字段和 `ranges`，此时不要求背定义。对照 ROS 2 官方 [LaserScan 消息定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/LaserScan.msg)，指出距离使用米、角度使用弧度，测量必须结合坐标系和时间解释。这个命令查看的是接口定义，即使没有设备也可以成功，成功不代表雷达已经在线。

**2. 有硬件：教师启动好驱动后，检查真实话题。**每个新终端先加载 ROS 环境；若驱动来自源码工作区，也加载本机实际的 `install/setup.bash`。先枚举话题，再根据实际名称替换下面的 `/scan`：

```bash
ros2 topic list -t
ros2 topic info /scan --verbose
ros2 topic echo /scan --once --qos-reliability best_effort
ros2 topic hz /scan
```

先看发布者和类型是否存在，再查看一帧内容，最后观察接收频率。`hz` 会持续运行，观察数秒后按 Ctrl+C 停止；它统计当前订阅端接收到的频率，不直接等于设备内部采样率，也不应在型号未知时规定一个统一合格数值。

**3. 把数值与场景联系起来。**在 RViz 中添加 `LaserScan` 显示并选择实际扫描话题，QoS 与发布端兼容。导入演示可把 Fixed Frame 设为消息 `header.frame_id` 的实际值，先在雷达自身坐标系观察；这不证明雷达已正确安装到机器人 TF 树中。

保持雷达和底盘不动，在合适距离缓慢移动纸板，观察相应方向的扫描点变化。让学生解释“纸板靠近时，对应有效测距通常变小”。不要仅凭一帧中数值最小的元素判断纸板距离，也不要把 `ranges[0]` 当作固定正前方；方向要结合角度字段解释，细节留到对应页面。

**课堂记录与验收：**学生记录实际话题名、消息类型、`frame_id`，再用一句话说明物体移动与扫描变化的对应关系。无硬件组则解释接口定义为什么不等于实时数据。此页验收重点是认清数据链，不要求已经完成建图或源码分析。

**现象与排查顺序：**

| 观察到的现象 | 引导学生先检查什么 |
| --- | --- |
| 接口命令报找不到消息 | ROS 环境与消息包是否可用，还没到硬件排查阶段 |
| 没有扫描话题或发布者 | 驱动是否启动、日志是否正常、话题是否被改名，以及 ROS 发现环境 |
| 有话题但 echo 一直等待 | 数据是否持续发布、QoS 是否匹配、驱动是否初始化成功；等待时可按 Ctrl+C 退出 |
| 数值在更新但 RViz 不显示 | 话题选择、Fixed Frame、TF、QoS 和显示状态提示 |
| 能显示点但位置或朝向不对 | 角度约定、安装方向、参数及坐标变换，不能以“有画面”作为全部验收 |

结束时停止观察命令和 RViz，再按设备与驱动说明停止扫描、退出驱动并断电。本讲义只提供实验步骤；编写时未在本机运行 ROS 2 或验证真实雷达。

### 板书与收束

```text
主线：测到距离 → 通信与解析 → 组织扫描 → 发布接口 → 下游使用
设备能转 ≠ 有有效扫描；有扫描 ≠ 已完成建图
先观察输出，再追踪内部的数据来源与处理
```

课堂追问：“RViz 已经能看到墙的轮廓，是否说明 SLAM 已经完成？”参考答案：不能，当前可能只是扫描显示，还没有地图构建、位姿估计和相应验收。

这页最后可以说：

> **本课围绕一帧扫描走完整条数据链：让雷达数据可获取、可解释、可检查，再交给定位与建图算法使用。**

## 第 2 页｜目录

### 这页的讲课思路

**建议用 3～5 分钟讲路线，再用约 5 分钟做问题归位活动。**按 PPT 的 01～04 顺序讲，不逐项解释公式和代码。让学生知道每部分解决什么问题，以及前后为什么这样衔接。

开场可以这样讲：

> **这节课分四部分：先理解雷达测到了什么，再看驱动怎样取出数据，然后讨论数据怎样整理，最后接入 ROS 2 和导航系统。大家始终带着一个场景：机器人前面放了一块纸板，从雷达发现它，到下游程序正确理解它，中间需要哪些环节？**

**第一步：按目录介绍四段内容，每段落在一个问题上。**

| PPT 部分 | 本部分讲什么 | 讲给学生的核心问题 | 学完后的检查方式 |
| --- | --- | --- | --- |
| 01 激光雷达技术基础 | 概述发展、测距原理、性能指标 | 雷达测的是什么，哪些条件会影响测量？ | 能说明测距方式与指标含义，知道选型和使用需要核对具体型号 |
| 02 YDLIDAR 驱动实现原理 | 架构模块、SDK 接口、帧解析、坐标系 | 设备数据怎样经过 SDK 和驱动到达程序？ | 能沿数据链找到模块职责，把通信、解析与坐标表达的问题分开描述 |
| 03 数据处理与算法实现 | 坐标转换、角度重采样、过滤、强度 | 数据为什么要整理，整理后发生了什么变化？ | 能比较处理前后的数据，并解释参数对结果的影响，而不只判断画面是否好看 |
| 04 ROS2 接口规范与应用集成 | 消息类型、服务接口、TF 变换、Nav2 | 其他节点怎样正确接收、解释和使用扫描？ | 能检查实际接口、坐标关系与下游配置，说明“收到消息”和“正确使用”有什么区别 |

**第二步：用三句过渡，把四部分串起来。**

从 01 到 02：“知道距离如何产生之后，下一步要问：设备把它放在哪里，主控怎样读出来？”

从 02 到 03：“能取到原始数据之后，还要确认它们怎样排列、哪些值有效，以及是否需要整理成下游希望的形式。”

从 03 到 04：“数据整理好之后，还要告诉下游它的单位、时间和参考坐标系，并通过约定接口提供出去。”

其中 02 的坐标系侧重理解设备与驱动中的表达约定，03 侧重理解数据转换，04 的 TF 侧重说明雷达与机器人其他坐标系的关系。这是本课的讲解分工，具体处理发生在哪个模块，要以后续页面和实际代码为准。

**第三步：明确学习边界。**目录中的“算法实现”主要围绕雷达数据处理展开，不等于这一课要从头实现 SLAM 或导航规划器。Nav2 是后续使用扫描的应用场景之一；本课先把输入数据和接口交代清楚，不在目录页展开完整导航部署。

教师提示：每部分结束时都回到纸板场景追问一次，检查学生能否解释数据经过了什么环节。目录是学习路线，不是要求学生记忆四组名词。

### 课堂实验：把同一个观测任务放回四段数据链

**实验目标：**在安装、编译和调参前，先训练“提出问题 → 寻找证据 → 确定检查位置”的思路。目录页采用纸面或白板活动；具体上机实验随对应 PPT 页面展开，优先沿用第 1 页已列出的厂商官方驱动和 ROS 2 接口工具。

**准备与任务：**两人一组，在纸上写下四个框：测量基础、驱动取数、数据处理、接口集成。教师给出场景：“机器人与雷达保持不动，前方纸板缓慢靠近，希望程序正确显示并使用这次变化。”每组为四个框各填写一个问题和一项需要观察的证据。

**操作步骤：**

1. 用约 2 分钟按数据经过的顺序连接四个框，不写安装命令，也不急着猜参数值。
2. 每组补全下表中的问题与证据；允许提出不同检查方法，但必须说明它能支持什么判断。
3. 教师增加一个现象：“驱动没有报错，画面中的纸板方向却与实物不一致。”让学生圈出优先核对的环节，并说明还缺什么信息。
4. 邀请一组按四个框讲述检查顺序，另一组指出哪些结论证据还不充分。

| 环节 | 可以提出的问题 | 后续实验应收集的证据 |
| --- | --- | --- |
| 测量基础 | 纸板是否处在该型号允许的测量条件中？ | 具体型号与使用说明、物体摆放和测量条件记录 |
| 驱动取数 | 是否持续取得设备数据，而不是仅完成节点启动？ | 驱动日志、实际连接状态与扫描更新情况 |
| 数据处理 | 过滤或角度整理是否改变了纸板对应的数据？ | 相关参数、处理前后数据或受控参数对照结果 |
| 接口集成 | 下游使用的是哪条扫描，按哪个坐标系解释？ | 实际话题、消息头、显示配置及 TF / 下游配置 |

**讲解实验结果：**方向不一致时，安装方向、驱动角度约定、相关处理参数与坐标变换都可能需要核对；仅凭一张画面，不能唯一确定故障来源。应先固定实验条件、确认实际数据源，再结合后续知识收集证据，而不是一次修改多个参数直到“看起来正确”。

**验收：**每组用四句话串起完整链路，并指出一个“现象存在但结论还不能成立”的例子，例如“节点启动了，所以测距一定正确”。学生应能说明还需要什么证据，而不是只说“检查驱动”。

**常见偏差与引导：**如果只写“接线、启动、看 RViz”，追问测量条件、数据处理和坐标解释分别在哪里；如果把过滤描述为必然提高准确度，追问是否可能删掉真实目标；如果直接归因于 TF，追问是否已经确认原始扫描方向和实际安装。本活动不修改设备参数、不移动机器人，完成后保留四框图，供后续各章逐步补全。

### 板书与收束

```text
01 测到了什么？ → 02 怎样读出来？ → 03 怎样整理？ → 04 怎样交给下游？
贯穿场景：纸板靠近，测量变化怎样到达应用？
每段都问：看到了什么证据，它能证明什么？
```

课堂追问：“为什么能在 RViz 里看到点，还需要学习第四部分？”参考答案：显示成功只是一个观察结果，还要核对数据来源、消息约定、坐标关系和下游使用方式，才能评价集成是否正确。

这页最后可以说：

> **四部分共同回答一个问题：一条环境测量怎样经过驱动与处理，成为下游能够正确使用的数据。**

## 第 3 页｜激光雷达技术基础（第一章导入）

### 这页的讲课思路

**建议讲解 2～3 分钟，观察活动按条件另用 3～5 分钟。**这是一张章节过渡页，目的是把注意力从“驱动怎样运行”暂时转到“设备产生的测量到底是什么”。先提出问题，再说明本章会怎样回答，不在这里展开完整测距公式或型号参数表。

开场可以这样讲：

> **写驱动之前，我们先认识驱动要处理的数据。雷达看到的不是“这里有一堵墙”这样的语义，而是一定方向上的测距结果。接下来带着三个问题学习：它测到了什么，距离是怎样测出来的，又该用哪些指标判断这些结果是否适合机器人使用？只有理解测量本身，才能区分设备限制、环境影响和程序问题。**

**第一步：从“距离”追问到“方向与测量条件”。**指向教室中的墙或纸板，问：“只告诉机器人目标距离 1 米，能确定目标在哪里吗？”引导学生发现还需要方向和参考位置。对本课常见的平面扫描，可以先用“沿不同方向获得距离”建立直觉，不把它等同于已经识别出墙、门或行人。

**第二步：用副标题的三个部分交代本章目标。**

| 学习线索 | 教师怎样引出 | 此页希望学生带走的问题 |
| --- | --- | --- |
| Overview：概述 | 先认识设备用途、输出形式与应用场景，发展脉络随对应页面展开 | 机器人为什么需要环境距离信息？ |
| Ranging Principles：测距原理 | “设备没有卷尺，怎样把光学测量转换成距离？” | 实际型号采用什么方法，这种方法有哪些条件和限制？ |
| Key Metrics：关键指标 | “都能输出距离，为什么不同设备、不同设置下效果不同？” | 测得多远、测得多准、方向有多密、更新有多快，应怎样分别评价？ |

提醒学生，这几个指标不能只凭画面判断。点多不自动代表距离更准，读数稳定也不自动代表没有偏差；设备可表示或配置的范围，也不等于所有目标在整个范围内都能可靠测到。本章先建立这些区分，后续再解释具体定义与测法。

**第三步：把物理基础重新接回驱动。**驱动需要保留并正确表达测量的单位、方向、时间与有效性。遇到某些方向没有有效距离时，应先核对设备能力、目标和环境、参数与数据处理，不能只凭一个现象就判断传感器损坏或驱动写错。

可延续前页的官方 [LaserScan 消息定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/LaserScan.msg)作为输出参照：扫描里有角度、距离和时间信息。本页只说明为什么需要这些信息，不逐字段讲代码。

### 课堂观察：同一块纸板，为什么要分别看“位置、波动和更新”

**活动目标：**先形成可验证的问题，避免把测距、精度、扫描密度和更新速度混为一谈。采用第 1 页已准备好的厂商驱动与扫描显示，不安装新软件、不修改驱动或过滤参数。

**准备：**教师已确认设备型号、使用条件并完成基本数据检查；雷达与底盘固定，选取可测范围内的哑光纸板，记录大致摆放距离及方向。课堂不接触旋转机构，不遮挡设备运行所需空间，按设备说明使用。无实机时只完成预测和记录表设计，不把预想结果写成实测。

**操作与追问：**

1. **固定目标，观察约 5 秒。**让学生找出纸板对应的一段扫描，观察它是否持续出现、是否有跳动或缺失。追问：“如果看起来很稳定，是否就能证明距离准确？”参考引导：只能说明当前显示下变化不明显，准确度仍需可靠参考和明确测量方法。
2. **沿近似同一方向移动纸板，再停住。**移动量不必预设为某个精确值，但要保证前后位置可区分且均处在适合测量的范围。观察相应扫描位置怎样变化，追问：“改变的是目标距离，还是我们更改了雷达的测距原理？”引导学生把物体变化与测量机制分开。
3. **保持新的位置，再观察约 5 秒。**区分“目标不动后数据仍持续更新”和“画面只是停留在旧数据”。可结合前页的话题更新检查；不要单凭 RViz 看起来不动，就断定消息没有发布。
4. **讨论还缺什么证据。**如果纸板附近显示很多点，追问：“这些点来自哪些方向，能否仅凭数量说明每个距离值都更准确？”此处只提出角度采样和显示方式的问题，计算留到对应页面。

建议每组完成下面的记录，先写看到的事实，再写解释：

| 场景 | 应记录的现象 | 不能直接推出的结论 |
| --- | --- | --- |
| 纸板固定 | 对应扫描是否出现，有无明显波动或缺失 | 稳定就一定准确 |
| 纸板移动后停住 | 哪一段扫描位置改变，变化是否符合靠近或远离的方向 | 有变化就已验证所有角度和量程 |
| 画面基本不变 | 目标是否静止、消息是否仍在更新 | 画面不动就表示设备停止采样 |

**验收：**学生各说出一条“已经观察到的事实”和一条“还需要验证的问题”。例如：“纸板靠近后对应扫描靠近雷达；但没有规范参考测量，暂时不能评价绝对距离误差。”本活动用于建立观察方法，不输出精度合格结论。

**排查与结束：**找不到纸板对应扫描时，先确认显示数据在更新、坐标方向与扫描平面，再检查目标距离、尺寸和摆放条件。若没有可用数据，保留现象并按前页的数据链排查，不用反复移动目标掩盖问题。活动后移开纸板并恢复场地；设备是否继续运行，由教师按后续演示安排处理。

### 板书与收束

```text
本章三问：测什么？怎样测？怎样评价？
平面扫描直觉：不同方向上的距离测量
观察 → 记录 → 寻找参考 → 再评价，避免只凭画面下结论
```

课堂追问：“同一个静止目标的距离读数一直相同，能否证明没有测量偏差？”参考答案：不能，读数可能很稳定但存在系统性偏差，还需要合适的参考与测量条件来评价。

这页最后可以说：

> **先理解测量的来源与边界，再讨论驱动如何表达它；本章从原理和指标入手，为后面的解析、处理与接口集成建立判断依据。**

## 第 4 页｜激光雷达概述与发展历程

### 这页的讲课思路

**建议讲解 6～8 分钟，实验另用约 5 分钟。**按左上定义、左下优势、右侧三条发展路径的顺序讲。主线是“主动测量为什么有价值，以及技术怎样沿不同方向发展”，不把本页讲成型号背诵或价格比较。

开场可以这样讲：

> **LiDAR 是 Light Detection and Ranging，也就是利用光进行探测和测距。它主动发出光，再根据接收到的信号估计距离。先用脉冲往返时间建立直觉，然后看这种测量能带来什么优势，以及扫描结构、空间信息和应用成本怎样发展。注意：测距方法、扫描结构和产品定位是不同维度，不能混在一起分类。**

**第一步：解释主动探测，再用 TOF 作例子。**主动探测的重点是设备自己发出用于测量的光。对脉冲直接飞行时间法，光从设备到目标再返回，理想距离为：

```text
d = c × Δt / 2
c ≈ 3×10^8 m/s；Δt 是往返时间；d 是单程距离
```

先问“为什么除以 2”，再让学生说出往返路径。可参考 [NOAA 的激光雷达介绍](https://oceanservice.noaa.gov/facts/lidar.html)理解脉冲测距与环境测绘，但不要把其中航空系统的配置照搬到本课机器人雷达。

PPT 用 TOF 解释定义，课堂要补一句：这是测距方式之一，不是所有激光雷达都直接测脉冲往返时间。YDLIDAR 的[官方产品分类](https://www.ydlidar.com/products)同时列有 TOF 和三角测距等产品；本项目具体采用哪种，要看实际型号，不能仅凭品牌判断。

**第二步：把四条优势讲成“能力 + 条件”。**

| PPT 中的优势 | 可以怎样讲 | 需要补充的条件 |
| --- | --- | --- |
| 测距精度高，可达厘米级 | 合适设备在规定条件下能提供较精细的距离测量 | 不能承诺所有型号、所有距离和目标都达到同一精度；分辨率也不等于准确度 |
| 方向性强，角度分辨率优于 1° | 沿不同方向采样，有利于描述物体轮廓 | 是否优于 1°需看型号与设置；角度采样间隔、光束宽度和角度准确度不是同一个量 |
| 抗电磁干扰能力强 | 测距利用光学信号，具有不同于电气测量通道的特点 | 整机仍有供电、电子电路与通信接口，不能推断完全不受电磁干扰；还需考虑环境光等光学干扰 |
| 直接输出明确的距离数据 | 使用者可以获得带单位的测距结果，不必仅从普通图像推断尺度 | 仍可能存在无效、遮挡或异常回波；一个距离值不等于已识别物体类别 |

讲到环境光时，可补充器件厂商 [Analog Devices 对 LiDAR 接收端环境光影响的说明](https://www.analog.com/en/resources/analog-dialogue/articles/how-to-cancel-ambient-light-for-lidar-receivers.html)：主动发光并不意味着不受外部光照影响。本页只建立边界，不展开接收电路设计。

**第三步：把“三条并行发展路径”当作三个比较轴。**

| 发展路径 | 教师的解释重点 | 避免讲成什么 |
| --- | --- | --- |
| 机械旋转式 → 固态式 | 扫描与光束控制结构更加多样，目标包括体积、可靠性和集成能力等 | 不是所有固态产品都绝对没有运动部件，也不是已经全面替代机械旋转方案 |
| 单线 → 多线 / 面阵 | 在不同方向获取更丰富的空间信息，区别平面轮廓与立体采样需求 | 多线不等于每个距离值更准确，也不是所有面阵设备都采用相同测距方式 |
| 工业级 → 消费级 | 产品进入更多成本敏感场景，应用需求和规模影响设计取舍 | 不是统一的技术代际关系，也不能仅凭价格判断可靠性或适用场景 |

例如厂商 [Blickfeld Cube 产品手册](https://www.blickfeld.com/wp-content/uploads/2022/10/Blickfeld-A5-Manual_en_v.4.2.pdf)在固态 LiDAR 的功能说明中描述了运动的 MEMS 微镜，可见“固态”一词在不同产品中的口径需要核实。课堂可区分无大型旋转机构与严格无运动部件，而不是只背标签。

PPT 的“数十万元降至数百元”用来说明部分产品成本下降的趋势即可，不作为跨年代、跨类别的统一价格结论。本课不据此进行采购推荐，也不把低价平面雷达与高性能三维设备当作等价产品。

### 实验：算一次光的往返，再用官方资料区分分类维度

**实验目标：**理解 TOF 中的往返关系，并确认“测距原理、扫描结构、空间覆盖”是不同问题。

**A. 数值体验：1 米对应的时间有多短？**只需 Python 3 标准库，在 Ubuntu Bash 中运行下列课堂计算示例。它依据理想脉冲 TOF 关系编写，不是厂商仿真或真实计时程序：

```bash
python3 - <<'PY'
from math import isclose

c = 3e8
for distance in (1.0, 10.0):
    round_trip = 2 * distance / c
    recovered = c * round_trip / 2
    print(f'{distance:.1f} m -> round-trip {round_trip*1e9:.3f} ns '
          f'-> recovered {recovered:.1f} m')
    assert isclose(recovered, distance)

delta_d = 0.01
print(f'1 cm distance change -> round-trip change {2*delta_d/c*1e12:.3f} ps')
PY
```

预期输出：

```text
1.0 m -> round-trip 6.667 ns -> recovered 1.0 m
10.0 m -> round-trip 66.667 ns -> recovered 10.0 m
1 cm distance change -> round-trip change 66.667 ps
```

先让学生预测“10 米的往返时间是不是 1 米的 10 倍”，再运行确认。随后故意在纸上去掉解码公式中的 `/2`，说明会把单程距离算成两倍。最后追问：“厘米变化对应这么小的时间差，能否让 Python 发命令、等待回包，再用这段耗时直接测距？”答案是否定的：命令传输和软件调度等延迟不是光的飞行时间。

66.667 ps 表示理想模型中距离改变 1 cm 对应的往返时间差，不表示设备必须采用同周期的数字时钟，也不证明任何实际型号达到厘米准确度。真实实现还涉及探测、估计、标定与噪声，本页不展开。程序自动结束、不访问硬件、不生成文件。

**B. 资料核对：给型号做一张“有依据的分类卡”。**打开上文厂商官方产品页，选一个型号，再进入其产品说明或下载手册。两人一组填写下表，每项都写明资料位置；未明确给出的内容写“待确认”，不要由产品外观或名称推断。

| 要核对的问题 | 学生应填写什么 |
| --- | --- |
| 采用哪种测距方法？ | TOF、三角测距或资料明确写出的其他方法及依据 |
| 怎样控制测量方向？ | 是否旋转、使用微镜或采用其他方式；资料未写则不猜测 |
| 获得怎样的空间覆盖？ | 单点、平面扫描、多线或面阵等，以具体说明为准 |
| 哪条性能声明带有使用条件？ | 选一条距离或精度指标，抄录其适用条件；缺失条件时记录待核对 |

**验收：**能解释 TOF 为什么除以 2，并举出一个不能相互替代的分类维度，例如“TOF 说明怎样测距，机械旋转说明怎样改变方向”。没有实际型号资料时，完成 A 部分与分类表设计即可，不虚构产品参数。

**常见偏差与排查：**结果大了两倍先检查往返与单程，时间数量级不对先检查 ns / ps 换算；资料核对时，把“产品系列宣传语”与“具体型号规格”分开，不能把目录中的默认配置当成设备的实测能力。本实验验证计算与资料阅读方法，不验证真实雷达精度或寿命。

### 板书与收束

```text

```

## 第 5 页｜激光测距原理：TOF 与三角测距

### 这页的讲课思路

**建议讲解 8～10 分钟，计算实验另用约 8 分钟。**先比较两种方法“直接观察什么”，再解释误差来源，最后讨论使用条件。不要一开始就让学生背量程和精度数值，也不要把左右两栏讲成绝对的优劣排名。

开场可以这样讲：

> **两种方法都使用发射光和返回光，区别在于从返回光里提取什么信息。左边的脉冲 TOF 看光往返用了多久，右边的三角测距看返回光斑落在接收器的哪个位置。一个主要利用时间关系，一个主要利用几何关系，所以它们对硬件、距离变化和误差的敏感方式不同。**

**第一步：左栏用“时间 → 距离”讲清往返。**本页描述的是脉冲直接飞行时间法，不覆盖所有 TOF 实现。Δt 是发射到接收的往返时间，公式仍是 `d = cΔt / 2`。让学生先口答除以 2 的原因，再看页脚：

```text
若往返时间变化 1 ns：距离变化 ≈ 3×10^8 × 10^-9 / 2 = 0.15 m
若往返时间变化 0.1 ns：距离变化 ≈ 0.015 m
```

TDC 可理解为时间数字转换器，用来把时间间隔转换成数字量。但 TDC 标称时间分辨率、整机距离分辨率与测距准确度不能直接画等号，接收噪声、时延标定和估计算法等也会影响结果。“亚纳秒级”用于提示计时尺度，不是在指定所有设备必须具有相同结构或时钟频率。

**第二步：右栏用“光斑位置 → 几何关系 → 距离”讲清三角测距。**发射器和接收光学系统之间具有已知空间关系，目标距离变化会使返回光斑在位置敏感探测器或图像传感器上的位置变化。通过几何关系和标定，把该位置换算成距离。可对照厂商 [Micro-Epsilon 的三角测距原理说明](https://www.micro-epsilon.com/wiki/laser-triangulation/?sLang=en)。

教师画图时要画出发射端、接收端和目标，标出发射与接收之间的基线；强调这里不是用光斑亮度直接代表距离，也不是测量光斑移动所花的时间。PSD 和 CMOS 是可能采用的接收器类别，不代表所有设备都有相同信号处理方式。

**第三步：用简化几何说明为什么距离与基线重要。**为课堂计算，假定接收端采用理想针孔模型，光轴与发射方向平行，发射端位于接收端侧方 B 处，目标在发射光线上。忽略成像翻转，以光斑距主点的偏移量绝对值 u 表示：

```text
u / f = B / Z  →  Z = fB / u
小偏差近似：|δZ| ≈ Z² / (fB) × |δu|
```

其中 f 为焦距，Z 为沿发射方向的距离，B 为基线长度；计算时三者与 u 使用一致长度单位。在光斑定位误差固定的假设下，距离变远，换算出的距离误差会放大；增加基线可改善这一理想模型的几何敏感度，但也带来体积、遮挡和结构设计取舍。

这是教师编写的示意模型，不是实际 YDLIDAR 的标定公式。真实接收系统可能倾斜、有畸变和零点偏移，应使用厂商标定关系；不能拿此式替换驱动中的距离解码。

**第四步：逐项解释 PPT 的比较，补上条件。**

| PPT 比较项 | 建议怎样讲 |
| --- | --- |
| TOF 范围数米至数百米、厘米级精度 | 是部分产品能力的概括，不是 TOF 的统一起测距离、量程或保证精度；需查具体型号及目标条件 |
| TOF 受反射率影响小 | 不依靠单纯亮度反推距离，不等于反射率没有影响；弱回波仍会影响信噪比、有效量程与误差 |
| TOF 适合强光环境 | 某些型号有相应设计，但不是原理自动免疫强光；环境光可能干扰或使接收端饱和 |
| 三角测距成本低、近距离精度高 | 常见低成本近距方案可利用几何位置测量，但成本与精度仍由整机设计决定 |
| 三角测距通常小于 15 米 | 是本页面向常见设备的经验概括，不是几何原理规定的硬上限 |
| 三角测距对镜面反射敏感、适合室内 | 返回光是否进入接收视场很重要；使用场景要查规格，TOF 同样可能遇到镜面、透明目标等问题 |

关于 TOF 的弱回波和强光限制，可参考 [Analog Devices 的 LiDAR 接收端说明](https://www.analog.com/en/resources/analog-dialogue/articles/how-to-cancel-ambient-light-for-lidar-receivers.html)。最后把选型问题落到“距离、目标表面、环境光、精度要求、体积与成本”，不能只凭 TOF 或三角测距的名称决定。

### 实验：比较时间误差与光斑位置误差怎样变成距离误差

**实验目标：**通过理想模型看到两种方法的敏感度差别，训练控制变量，而不是预测某台设备的真实精度。

原理参照上述厂商资料，程序是课堂自行编写的计算示例，不是官方驱动算法或传感器仿真。只需 Python 3 标准库，不需要雷达、ROS 或串口，在 Ubuntu Bash 中运行：

```bash
python3 - <<'PY'
from math import isclose

c = 3e8
for timing_ns in (1.0, 0.1):
    distance_error = c * timing_ns * 1e-9 / 2
    print(f'TOF: dt_error={timing_ns:.1f} ns -> d_error={distance_error:.3f} m')

f, baseline, spot_error = 0.008, 0.040, 5e-6  # all lengths in metres
for distance in (0.5, 1.0, 2.0):
    spot = f * baseline / distance
    approximate_error = distance**2 / (f * baseline) * spot_error
    print(f'triangulation: Z={distance:.1f} m, u={spot*1000:.3f} mm, '
          f'approx_error={approximate_error*1000:.3f} mm')
    assert isclose(f * baseline / spot, distance)

z = 1.0
error_b = z*z / (f * baseline) * spot_error
error_2b = z*z / (f * 2 * baseline) * spot_error
print(f'double_baseline_error_ratio={error_2b/error_b:.3f}')
assert isclose(error_2b / error_b, 0.5)
PY
```

预期输出：

```text
TOF: dt_error=1.0 ns -> d_error=0.150 m
TOF: dt_error=0.1 ns -> d_error=0.015 m
triangulation: Z=0.5 m, u=0.640 mm, approx_error=3.906 mm
triangulation: Z=1.0 m, u=0.320 mm, approx_error=15.625 mm
triangulation: Z=2.0 m, u=0.160 mm, approx_error=62.500 mm
double_baseline_error_ratio=0.500
```

**操作和讲解顺序：**

1. 运行前预测：固定时间误差时，TOF 公式中是否直接出现目标距离？答案：本页理想误差换算没有，但真实时间估计误差本身可能随回波条件变化，不能据此保证远近精度相同。
2. 观察三角测距的三行输出：距离每翻倍，光斑偏移量减半，固定光斑误差对应的一阶距离误差约增为四倍。这说明远距离时不能忽略几何敏感度。
3. 将 `spot_error` 从 `5e-6` 改为 `2.5e-6`，重新运行，三角测距的近似误差应减半；一次只改这一个变量。
4. 解释最后一行：在 f、Z 和光斑误差均固定的模型中，基线翻倍使近似距离误差减半；这不等于实际设备只改外壳宽度就能得到同样收益。

这里的三角测距误差是小偏差一阶近似，TOF 时间误差也是假设输入。脚本没有模拟反射率、饱和、温漂或标定误差，因此不能用输出数值给两类实际雷达排名。

**验收：**学生能回答两种方法各自测什么，解释 1 ns 为什么对应约 15 cm，以及三角测距模型中远距离误差为何放大。提交修改前后结果时，必须写明哪一个变量改变、哪些条件保持不变。

**排查与结束：**数值相差千倍或百万倍时先检查 m / mm 和 ns / s；三角测距不能把图像像素坐标直接当成以米计的 u，真实使用还需像素尺寸、主点与标定。脚本自动结束、不生成文件、不控制硬件；实机对照应另设规范参考目标和测量方案。

### 板书与收束

```text
脉冲 TOF：测往返时间 → d = cΔt/2；1 ns ↔ 约 15 cm
三角测距：测光斑位置 → 标定几何 → 距离
示意模型 Z=fB/u：固定位置误差时，远处距离误差放大
实际性能 = 测距方法 + 整机设计 + 目标与环境 + 标定
```

课堂追问：“TOF 不靠亮度直接算距离，是否就能忽略黑色目标和强光？”参考答案：不能，回波强度与环境光仍影响接收和时间估计，应查具体设备的适用条件并测试。

这页最后可以说：

> **TOF 从时间求距离，三角测距从光斑位置和几何关系求距离；先认清观测量和误差来源，再比较具体设备的性能。**

## 第 6 页｜YDLIDAR 型号方案与精度制约因素

### 这页的讲课思路

**建议讲解 7～9 分钟，实验另用 10～15 分钟。**先沿左侧确认“我们手里是什么设备”，再沿右侧追问“为什么同一台设备在不同条件下表现不同”。这一页要让学生学会区分型号规格、软件配置和实测结果，不只是记住几个数字。

开场可以这样讲：

> **上一页比较了两种测距原理，现在把它们对应到实际型号。本课按 PPT 以 EAI 的 YDLIDAR S2 为目标设备，它采用三角测距。型号确认后，还不能马上认定测量一定准确：光束、探测器、目标表面和环境都会影响结果。我们用一个控制变量实验，分别看距离偏差、读数波动和无效测量，而不是只凭 RViz 的画面评价精度。**

**第一步：型号表是配置入口，不是通用选型排名。**

| PPT 型号系列 | 测距方案 | 讲解重点 |
| --- | --- | --- |
| S2 / X2 / X4 | 三角测距 | 常见室内近距应用；同类原理不代表波特率、采样率和量程相同 |
| G2 / G4 | 三角测距 | 核对具体版本的量程与采样设置，不由字母或编号推断性能 |
| TG / T15 | TOF | 按具体型号核对环境适用性和通信接口，不能把“强光”当作无条件能力 |

依据厂商[官方驱动参数表](https://github.com/YDLIDAR/ydlidar_ros2_driver/blob/humble/details.md)，上述三角测距分类有对应依据，TG15 / TG30 / TG50 属于 TOF；T15 属于网络型 TOF，表中的 8000 是网络端口号，不是串口波特率。本页不展开它的配置，只用来说明“同是 TOF 也可能接口不同”。型号名称应连同厂商一起确认，不与其他品牌的同名 S2 混用。

**第二步：逐项解释 S2 配置，避免混淆量纲。**

| 课件给定项 | 课堂应怎样解释 | 核对与边界 |
| --- | --- | --- |
| 650 nm 红色激光 | 波长描述光的光谱位置，不是距离精度或激光安全等级 | 暂按课件记录，所核对驱动参数表未给出波长，需以实机版本手册确认 |
| 三角测距 | 根据返回光斑位置与标定几何关系求距离 | 官方型号分类可支持，不能直接套用上一页的示意公式解码实机 |
| 115200 bps | 常见二进制 UART 下的链路比特速率 | 官方表列 S2 为 115200；它不是每秒测距点数 |
| “ADC 采样率 3 kHz” | 本页应讲成约 3 k 点/秒的测距点采样率 | 官方字段为 `SampleRate(K)`，不能据此认定内部 ADC 转换频率就是 3 kHz |
| 标称最大测距 8 m | 表示型号标称范围的上限，不是精度，也不是所有目标都能测到的保证 | 官方表列 S2 范围至 8 m，具体条件仍需手册和实测核对 |

再追问：“3 k 点/秒是不是每秒扫描 3000 圈？”答案是否定的。若仅为理解关系，假设每秒扫描 6 圈，理想平均约 `3000 / 6 = 500` 点/圈；这里的 6 Hz 是课堂算例，不是对本机扫描频率的确认。消息数组长度还可能受重采样和处理影响，不能只凭它推断内部采样率。

**第三步：右侧因素按‘影响哪一步’解释。**

| 制约因素 | 可以怎样解释 | 避免的误解 |
| --- | --- | --- |
| 激光束发散角 | 远处光斑可能更大，细小目标、边缘和相邻表面的回波更难分离 | 光束宽度与角度采样间隔不同，不能只由发散角算出软件的角度步长 |
| 探测器性能 | 弱回波是否可识别、强回波是否饱和，会影响有效测量与误差 | 探测器参数不等于整机精度，驱动也不能恢复根本没有获取的信号 |
| 时间分辨率 | 对脉冲 TOF，1 ns 对应约 15 cm 的距离变化 | 本课 S2 是三角测距，不能用此式直接计算 S2 精度 |
| 环境与目标 | 温漂、照明、表面反射方向等可能改变测量；大气湍流更需结合路径与场景讨论 | 不必把所有异常都归因于大气因素，室内短距先查摆放、表面、光照和设备状态 |
| 抑制与补偿 | 光学、电路、回波处理及温度补偿针对不同误差来源 | 软件参数不是万能修复，也不能假定 S2 已具备 PPT 列出的全部补偿功能 |

BRDF 是“双向反射分布函数”，本页用直觉解释为“表面把入射光往哪些方向反射、强弱如何分布”。同一材料改变朝向也可能改变接收回波，不只是“白色强、黑色弱”这么简单。环境影响可能表现为偏差、随机波动或无效值，不应全部笼统归为系统误差。

多回波处理能否使用，取决于设备与数据接口是否提供相应信息；不能靠在普通扫描上加一个参数就获得硬件没有输出的多回波。对环境光和接收饱和的影响，可参照前页的 [Analog Devices 接收端说明](https://www.analog.com/en/resources/analog-dialogue/articles/how-to-cancel-ambient-light-for-lidar-receivers.html)。

### 实验：固定目标，分别评价偏差、波动与有效率

**实验目标：**在相同配置下比较受控条件，学习“测得稳定”与“接近参考值”的区别。实机数据使用厂商驱动发布的 `LaserScan`，统计方法为课堂扩展，不是厂商出厂检定程序。

**准备与控制变量：**使用已配置好的 S2、哑光平板、固定支架及合适的长度参考工具。雷达与底盘静止，先按设备说明稳定运行；记录设备版本、驱动配置、运行时间、照明与目标材质。选取适合该设备的近距位置，不必把 8 m 上限作为第一次实验目标。

参考距离应从设备规定的测距参考位置，沿所选测量方向量至目标表面；参考位置不明确时，先做相对变化比较，不宣称得到绝对精度。让平板覆盖选定方向，避开边缘和背景，尽量使测量方向正对平板。

**1. 确认数据源。**在已加载 ROS 2 环境的终端，用官方 CLI 查看实际话题与字段：

```bash
ros2 topic list -t
ros2 topic info /scan --verbose
ros2 topic echo /scan --once --qos-reliability best_effort
```

若实际名称不同，替换 `/scan`。按官方 [LaserScan 定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/LaserScan.msg)，第 i 个测量方向为 `angle_min + i × angle_increment`，不能把数组第一个值默认当作正前方。此时只用该关系确认所选索引的方向，不展开消息实现。

**2. 收集同一方向的连续观测。**选定一个确实落在平板内部的方向，在相同摆放下取至少 20 帧，每帧只记录该方向的一个测距值，保留无效记录。课堂可逐帧读取并记录；若消息角度布局改变，应按方向重新确认索引，不能机械使用旧索引。

有限且在消息规定范围内的值才进入距离统计；NaN、Inf、超范围或驱动定义的无效值要单独标记。不要把无效值改成 0 后计算均值，也不要从整帧里随意挑最接近参考值的点。相邻测量可能相关，20 帧只能作为课堂初步观察，不能代表完整性能检定。

**3. 一次只改变一个条件。**基线组采用哑光平板固定距离；第二组可换到另一个已知距离，其余条件保持一致。若比较材质，应把目标放回同一参考平面并固定方向。不要同时移动目标、改变照明和过滤参数，否则无法解释差异。

| 组别 | 参考距离与条件 | 总帧数 / 有效数 | 有效值均值与参考的差 | 有效值样本标准差 |
| --- | --- | --- | --- | --- |
| A 基线 | 记录实际位置、方向和材质 | 实测填写 | 实测填写 | 实测填写 |
| B 对照 | 写清只改变的条件 | 实测填写 | 实测填写 | 实测填写 |

**4. 先用示例数据学会统计，再代入实测。**下面脚本仅用 Python 标准库，A、B 是人为构造的数据，`None` 表示一条已判定无效的记录，不是设备实际输出编码。真实数据应先按上述规则判断有效性，并替换参考值与列表。在 Ubuntu Bash 中运行：

```bash
python3 - <<'PY'
from statistics import mean, stdev

reference = 1.0  # metres; teaching example only
groups = {
    'A': [1.019, 1.020, 1.021, None],
    'B': [0.990, 1.000, 1.010, None],
}
for name, values in groups.items():
    valid = [v for v in values if v is not None]
    assert len(valid) >= 2
    bias = mean(valid) - reference
    spread = stdev(valid)
    print(f'{name}: valid={len(valid)}/{len(values)}, '
          f'mean_error={bias*1000:+.1f} mm, std={spread*1000:.1f} mm')
PY
```

预期输出：

```text
A: valid=3/4, mean_error=+20.0 mm, std=1.0 mm
B: valid=3/4, mean_error=+0.0 mm, std=10.0 mm
```

**结果怎样讲：**A 更稳定但均值偏离参考，B 均值更接近参考但波动更大；两组都只有 75% 有效记录。不能只看标准差、均值或丢掉无效记录后的一张图，就宣布哪组全面合格。这里的均值差也包含参考测量与摆放误差，不能全部归因于雷达自身。

**验收：**提交条件记录、固定方向的原始记录及统计结果，说明对照组只改变了什么；口答“为什么 8 m 不是精度”和“为什么 3 kHz 不是扫描圈数”。没有实机时完成示例统计与实验设计，并明确结果属于教学数据。

**排查与结束：**有效率低时先核对方向、目标覆盖、测量范围与设备状态；均值异常时检查单位、参考位置和几何摆放；波动明显时检查支架、振动、光照及回波条件。不要先用过滤把异常隐藏，也不要据此直接修改标定。命令等待时可按 Ctrl+C 退出，Python 自动结束；完成后恢复场地并按教师安排停止设备。本页编写时未进行 S2 实机测量。

### 板书与收束

```text
先认型号：厂商 + 型号 + 版本 → 原理 / 接口 / 配置
S2：三角测距；115200 是通信速率；3 k 是测距点采样率
```

课堂追问：“标准差很小，是否说明距离一定准确？”参考答案：不能，仍可能有固定偏差，还需要正确参考、测量条件和有效率记录。

## 第 7 页｜关键性能指标：测距范围与角度分辨率

### 这页的讲课思路

**建议讲解 7～9 分钟，计算与接口观察另用约 8 分钟。**先讲左侧“多近、多远能测”，再讲右侧“相邻测量方向隔多远”，最后把两者联系到小目标检测。重点区分距离范围、距离精度和角度采样间隔，而不是只背 0.1～8 m 与 1.2°。

开场可以这样讲：

> **量程告诉我们目标距离是否处在规定的工作区间，角度采样间隔告诉我们相邻测量方向有多密。目标在量程内，也不等于一定能看见：细目标可能落在相邻方向之间，远处的横向采样间距也会增大。这一页用两个指标解释，为什么“能测到 8 米”不能直接变成“8 米内所有障碍都能可靠发现”。**

**第一步：测距范围要带条件理解。**PPT 用 `[R_min, R_max]` 表示规定条件下可提供有效距离测量的区间。最小距离可能受光学几何、收发视场重叠、近场杂散光和处理规则等影响；不是所有型号都仅靠同一种阈值产生盲区。小于最小距离不代表“没有物体”，而是测量可能不可靠或没有有效输出。

最大距离与发射、接收、目标反射特性和环境等有关。课件提到 90% 白色漫反射目标，课堂应说明这是某些规格使用的测试条件，不是所有厂商、所有指标的统一基准。对黑色、倾斜、透明或镜面目标，不能无条件沿用白色目标的最大距离。

厂商[官方型号参数表](https://github.com/YDLIDAR/ydlidar_ros2_driver/blob/humble/details.md)列 S2 范围为 0.10～8.0 m，可作为本课型号参考，实机版本与适用条件仍需核对。把软件 `range_max` 设成更大值不会增加硬件能力；缩小输出范围也可能只是主动过滤了原本能测量的数据。

**第二步：右侧公式算的是理想平均角度采样间隔。**

```text
每圈点数 N ≈ f_sample / f_scan
平均角度间隔 δθ ≈ 360° / N = 360° × f_scan / f_sample
```

这里假设完整扫描 360°、转速与采样相对均匀、测距点采样率固定，且暂不考虑丢失、裁剪和重采样。`f_sample` 应理解为用于该模型的测距点采样率，不直接等同内部 ADC 转换频率。

PPT 将这个间隔称为角度分辨率，讲课时可保留术语，但要补充：它描述采样密度，不能单独证明两相邻目标实际可被分离。光束宽度、目标大小、回波混合和处理算法也会影响目标分辨能力；更不能把它当作角度准确度。

**第三步：核对 S2 算例，不直接把 10 Hz 设到实机。**数学上，`3000 / 10 = 300` 点/圈，平均间隔为 `360° / 300 = 1.2°`，计算成立；但“300 个点”不等于“300 个有效回波”。

同一官方参数表列 S2 扫描频率为 4～8 Hz（PWM），并指出这类型号不能通过普通扫描频率命令直接调速。因此本页的 10 Hz 应标注为固定 3 k 点/秒条件下的假设算例，不能当作 S2 的已确认运行规格。实际转速和控制方式应按本机硬件及资料确认，不在课堂为凑算例盲目提高转速。

| 假设扫描频率 | 理想平均点数 / 圈 | 平均角度间隔 | 教学说明 |
| --- | --- | --- | --- |
| 4 Hz | 750 | 0.48° | 固定 3000 点/秒的数学模型 |
| 6 Hz | 500 | 0.72° | 同上，仍需实测运行状态 |
| 8 Hz | 375 | 0.96° | 同上，不保证每点都有有效回波 |
| 10 Hz | 300 | 1.20° | 课件假设算例，不作为 S2 的实机设置依据 |

**第四步：把角度间隔变成空间直觉。**在相同距离 r 的圆周上，相邻采样方向对应两点的弦长为 `s = 2r·sin(δθ/2)`；小角度时可近似为 `r·δθ`，后一式必须用弧度。1.2° 在 1 m 处对应约 2.09 cm，在 5 m 处约 10.47 cm。这里比较的是圆周上的理想点间距，不是任意墙面上的精确点距。

因此越远的细目标越需要关注角度覆盖与扫描相位，不能仅凭目标在量程内就承诺检测。固定点采样率时，提高扫描频率会减少每圈点数，这是时间更新与空间采样之间的取舍，不代表任何场景都应该优先选择更慢或更快。

### 实验：计算采样密度，再核对扫描消息的表达

**实验目标：**复现课件的 1.2°，比较频率变化的影响，并区分原始测量与驱动发布的角度网格。先完成无硬件计算，有设备时再观察官方消息字段，不修改设备转速或驱动参数。

**A. 理想模型计算。**以下是课堂自行编写的 Python 标准库示例，不是官方雷达仿真。在 Ubuntu Bash 中运行：

```bash
python3 - <<'PY'
from math import radians, degrees, sin, atan, isclose

sample_rate = 3000.0
for scan_rate in (4, 6, 8, 10):
    count = sample_rate / scan_rate
    step = 360.0 / count
    print(f'{scan_rate} Hz: points/turn={count:.0f}, step={step:.2f} deg')

step = radians(1.2)
for distance in (1.0, 5.0):
    chord = 2 * distance * sin(step / 2)
    print(f'r={distance:.1f} m: chord={chord*1000:.3f} mm')

width, distance = 0.05, 5.0
target_angle = degrees(2 * atan(width / (2 * distance)))
print(f'5-cm target at 5 m: angular_width={target_angle:.3f} deg')
assert isclose(360 * 10 / 3000.0, 1.2)  # original slide example
assert target_angle < 1.2
PY
```

最后一行假设 5 cm 宽的目标正对雷达，目标中心距雷达 5 m。其张角小于 1.2°，说明在理想离散射线模型中可能落入采样间隙；不能据此断言所有扫描都会漏检。实际还涉及光束宽度、扫描相位和回波条件，命中与可靠分辨也不是同一回事。

运行后把 `sample_rate` 改成 6000，仅比较频率表的变化：同一扫描频率下，每圈点数应翻倍、平均角度间隔应减半。脚本后半段仍固定使用原课件的 1.2°分析空间间距，作为另一组独立算例。这是数学对照，不意味着 S2 能通过修改软件数值获得 6 k 点/秒。

**B. 有设备时观察输出网格。**沿用前页已启动并确认配置的厂商驱动，在加载 ROS 2 环境的终端运行：

```bash
ros2 topic echo /scan --once --qos-reliability best_effort
ros2 topic hz /scan
```

若话题名不同先替换。根据官方 [LaserScan 消息定义](https://github.com/ros2/common_interfaces/blob/humble/sensor_msgs/msg/LaserScan.msg)，记录 `range_min`、`range_max`、`angle_min`、`angle_max`、`angle_increment`、`scan_time` 和 `ranges` 长度。角度字段单位为 rad，用 `角度值 × 180 / π` 转成度，不能直接把数值与 1.2°比较。

检查数组方向时，第 i 项角度为 `angle_min + i×angle_increment`。输出可能已经经过固定网格、裁剪或其他处理，因此 `angle_increment` 和数组长度不一定等于原始点的分布；填充或插值也不会增加独立的硬件测量。消息声明的测距边界同样不能证明每种目标都能在边界处可靠测到。

记录接收频率作为数据链观察，不能无条件把 `ros2 topic hz` 的结果当成电机实际转速。观察数秒后按 Ctrl+C 退出；无数据时回到前页检查发布者、配置与 QoS，不通过反复修改频率来排查。

**验收：**提交计算表，并解释“每圈 300 点为什么不是 300 个有效点”和“为什么 8 m 内的小目标仍可能难以检测”。有实机的组另记录输出角度网格与接收频率，说明哪些是消息观察、哪些是模型假设；无设备组只报告计算结果。

**排查与结束：**点数计算错误先核对点/秒与圈/秒；空间间距错误先核对角度与弧度；消息与模型不一致时先核对实际频率、输出处理和型号。计算脚本自动结束，不访问硬件、不生成文件。本页编写时未运行 ROS 或调整 S2 转速。

### 板书与收束

```text
范围：规定条件下的有效测距区间，不是任意目标的检测保证
N≈f_sample/f_scan；δθ≈360°/N（完整、均匀扫描模型）
同一点采样率：扫描更快 → 每圈点更少 → 平均角度间隔更大
原始采样密度 ≠ 输出网格密度 ≠ 实际目标分辨能力
```

课堂追问：“驱动把一圈数据补成更多数组元素，能否让雷达真正看见原本未测到的细目标？”参考答案：不能仅靠增加输出元素创造独立测量，仍需核对真实采样、光学能力和目标条件。

这页最后可以说：

> **量程回答距离边界，角度采样回答方向密度；把模型、型号规格和消息输出分开，才能判断机器人实际能观察到什么。**
