# Codex 用量门禁恢复修复 — 0.7.3

日期：2026-11-14。状态：已通过验证。

## 问题与依据

用户截图显示 `[PROCESS_START_FAILED]`，实际用户会话已在 CLI 检测通过后新增了失败请求。只读检查插件存储发现一个被标记为 CANCELLED 且未收到 usage 的历史 GPT 请求，`unknownAcknowledged=false`，预算 500000，已知用量为 0。没有读取 Codex/CC Switch 凭据或修改用户连接配置。

原因是 `TokenLedger.begin()` 正常拒绝未知用量时抛出普通 Error；`ChatController.send()` 将准备工具桥的普通 Error 误归类为进程无法启动。已有 `TeamSession.configure()` 未提供给用户界面，用户无法正常解除门禁。此状态与 Codex 可执行文件不存在不同。

## 修复

- `TokenLedger.begin()` 返回类型化的 `WAITING_APPROVAL`；GPT 显示“等待用量确认”。真正的 CLI 启动错误仍使用原分类。
- 其他工具准备异常单独显示 `TEAM_PREPARE_FAILED`，不展示原始异常内容。
- GPT 面板新增“用量与预算”按钮，绑定当前项目。原生输入框设置预算，有未知用量时必须再明确确认；取消保持账本不变。
- 新增 `configureGPTUsage()`、`validUsageBudget()`：验证范围和已知用量，拒绝执行期间修改，拒绝账本变化后使用过期确认。
- 未通过用量/工具准备门禁时不新增“已发送”消息或 CLI 请求，保留输入草稿，不破坏首次发送会话。
- 工具桥准备失败时清理本地服务器；尚未拥有本轮请求时，清理不会取消其他任务。
- 确认成功只重新检测 CLI，不自动重发消息，不清空历史，不把未知用量按 0 记录。
- 版本由 0.7.2 更新为 0.7.3；此前两个历史源码文件本轮没有修改。用户实际账本和原会话只读检查，没有代为确认未知用量。

## 使用与边界

安装 0.7.3 后重新加载 VS Code 窗口，在 GPT 面板点“用量与预算”，输入高于已知累计值的预算；若有未知用量，阅读提示后选择是否确认继续。确认后主动重新发送所需消息，插件不会重发旧任务。

预算仍为请求前门禁，不能预知单次模型返回后的用量；未知账单不能靠本次修复补算。用户若取消确认，保护继续生效。用户实际的未知用量确认保留给本人操作。
