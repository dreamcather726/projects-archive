# ESP32 四足机械狗控制程序讲解

## 一、项目概述

这是一套基于 **ESP32 + PCA9685 舵机驱动板** 的四足机械狗控制程序。

它可以控制四条腿，每条腿包含“大腿”和“小腿”两个关节，共控制 8 个舵机。ESP32 连接 WiFi 后会启动一个网页服务器，用户可以通过浏览器完成以下操作：

- 调整每个舵机的中位；
- 设置机械狗的默认站立姿态；
- 临时改变某个关节的位置；
- 联动对角腿或全部腿；
- 测试简单的行走步态；
- 保存校准参数，使断电重启后仍然有效。

整个系统的数据流如下：

```text
浏览器操作
    ↓ HTTP 请求
ESP32 Web 服务器
    ↓ 修改关节参数
机械狗控制模块
    ↓ 计算舵机脉宽
PCA9685 舵机驱动板
    ↓ PWM 信号
8 个舵机运动
```

## 二、硬件和软件组成

### 2.1 主要硬件

- ESP32 开发板；
- PCA9685 16 路 PWM 舵机驱动板；
- 8 个舵机；
- 四足机械狗结构；
- WiFi 路由器或手机热点；
- 独立的舵机电源。

### 2.2 各文件的作用

| 文件 | 作用 |
|---|---|
| `test.ino` | Arduino 程序入口，负责系统初始化和主循环 |
| `pca9685_servo.h/.cpp` | 初始化 PCA9685，并把微秒脉宽转换成 PWM 计数值 |
| `dog_control.h/.cpp` | 机械狗的核心控制，包括关节、站立、绑定和行走 |
| `center_storage.h/.cpp` | 使用 LittleFS 保存和读取校准参数 |
| `wifi_control.h/.cpp` | 连接 WiFi，启动 Web 服务器并提供控制网页 |

可以把 `.h` 文件理解为模块的“功能说明书”，把 `.cpp` 文件理解为功能的具体实现。

## 三、程序入口 `test.ino`

Arduino 程序有两个特殊函数：

```cpp
void setup()
{
  // 上电后只执行一次
}

void loop()
{
  // 初始化完成后不断重复执行
}
```

### 3.1 `setup()` 做了什么

```cpp
void setup()
{
  Serial.begin(115200);

  initPca9685Servo();
  initCenterStorage();
  loadCenterTrimFromFile();
  loadStandPoseFromFile();
  connectWifi();
  setupWebServer();
  moveDogHome();
}
```

执行顺序为：

1. 启动串口；
2. 初始化 PCA9685 舵机驱动板；
3. 初始化 ESP32 的 LittleFS 文件系统；
4. 读取舵机中位微调；
5. 读取默认站立姿态；
6. 连接 WiFi；
7. 启动网页服务器；
8. 让机械狗进入站立姿态。

可以概括为：

```text
初始化串口
→ 初始化舵机驱动
→ 读取校准数据
→ 连接 WiFi
→ 启动网页
→ 进入站立姿态
```

### 3.2 `loop()` 做了什么

```cpp
void loop()
{
  handleWifiClient();
}
```

主循环不断检查浏览器有没有发来新的请求。

在这个项目中，网页相当于机械狗的遥控器。

## 四、PCA9685 如何控制舵机

### 4.1 硬件配置

程序中的主要配置如下：

```cpp
#define PCA9685_ADDR 0x40
#define I2C_SDA 8
#define I2C_SCL 9
#define SERVO_FREQ 50
```

含义如下：

| 配置 | 含义 |
|---|---|
| `PCA9685_ADDR` | PCA9685 的 I²C 地址为 `0x40` |
| `I2C_SDA` | ESP32 的 SDA 使用 GPIO 8 |
| `I2C_SCL` | ESP32 的 SCL 使用 GPIO 9 |
| `SERVO_FREQ` | 舵机 PWM 频率为 50 Hz |

50 Hz 表示每秒产生 50 个 PWM 周期，因此一个周期的时间是：

```text
1 ÷ 50 秒 = 0.02 秒 = 20 ms = 20000 μs
```

### 4.2 舵机脉宽范围

```cpp
#define SERVO_MIN_US 500
#define SERVO_CENTER_US 1500
#define SERVO_MAX_US 2500
```

程序设定：

- `500 μs`：一侧极限位置；
- `1500 μs`：理论中间位置；
- `2500 μs`：另一侧极限位置。

> 注意：这只是程序采用的范围。不同型号舵机的安全脉宽范围可能不同，实际调试时应先使用较小范围。

### 4.3 脉宽如何转换为 PCA9685 计数值

PCA9685 把一个 PWM 周期分成 4096 份，所以转换公式为：

```text
PCA9685 计数值 = 脉宽 × 4096 ÷ 20000
```

例如舵机中位脉宽为 `1500 μs`：

```text
1500 × 4096 ÷ 20000 ≈ 307
```

代码最终通过下面的语句输出 PWM：

```cpp
pwm.setPWM(channel, 0, pcaCount);
```

为了避免输出超出设定范围，程序首先调用 `clampPulseUs()`，把脉宽限制在 `500～2500 μs`。

## 五、机械狗的数据模型

### 5.1 四条腿的编号

```cpp
enum LegIndex {
  LEG_RF = 0,
  LEG_LF = 1,
  LEG_RB = 2,
  LEG_LB = 3
};
```

| 缩写 | 英文 | 含义 |
|---|---|---|
| RF | Right Front | 右前腿 |
| LF | Left Front | 左前腿 |
| RB | Right Back | 右后腿 |
| LB | Left Back | 左后腿 |

### 5.2 每条腿的关节

```cpp
enum JointIndex {
  JOINT_THIGH = 0,
  JOINT_CALF = 1
};
```

每条腿有两个关节：

- `JOINT_THIGH`：大腿关节；
- `JOINT_CALF`：小腿关节。

所以程序总共控制：

```text
4 条腿 × 2 个关节 = 8 个舵机
```

### 5.3 舵机通道映射

```cpp
LegServo legs[LEG_COUNT] = {
  {"RF", 1, 2, 1, 1},
  {"LF", 5, 6, -1, -1},
  {"RB", 9, 10, 1, 1},
  {"LB", 13, 14, -1, -1}
};
```

每一项包含：

```text
腿名称、大腿通道、小腿通道、大腿方向、小腿方向
```

例如：

```cpp
{"RF", 1, 2, 1, 1}
```

表示右前腿的大腿舵机接在 PCA9685 通道 1，小腿舵机接在通道 2。

左腿的运动方向被设置为 `-1`，是因为机械狗左右两侧的舵机通常是镜像安装的。同样的物理动作，在左右舵机上可能需要相反的脉宽变化。

因此，需要让学生区分：

```text
物理动作方向相同，不一定代表舵机脉宽变化方向相同。
```

## 六、最核心的舵机输出公式

程序计算关节最终脉宽的代码是：

```cpp
int pulseUs = SERVO_CENTER_US
            + centerTrimUs[legIndex][jointIndex]
            + standPoseUs[legIndex][jointIndex]
            + motionOffsetUs[legIndex][jointIndex];
```

也就是：

```text
最终输出脉宽
= 1500 μs
+ 中位微调
+ 站立姿态
+ 当前动作偏移
```

### 6.1 中位微调 `centerTrimUs`

中位微调用于修正舵机和机械结构的装配误差。

例如理论中位是 `1500 μs`，但舵机安装后关节向一侧倾斜，可以增加 `50 μs`：

```text
1500 + 50 = 1550 μs
```

程序把中位微调限制在：

```text
-400～+400 μs
```

### 6.2 站立姿态 `standPoseUs`

站立姿态表示机械狗正常站立时，关节相对中位需要偏移多少。

例如：

```text
中位微调 = +30 μs
站立姿态 = -200 μs
```

静止站立时的输出为：

```text
1500 + 30 - 200 = 1330 μs
```

### 6.3 动作偏移 `motionOffsetUs`

动作偏移表示机械狗走路或调试时的临时关节变化。

假设当前动作偏移为 `+100 μs`：

```text
1500 + 30 - 200 + 100 = 1430 μs
```

动作完成后，把动作偏移清零，机械狗就会回到站立姿态。

### 6.4 为什么要分成三个参数

三种参数的用途和生命周期不同：

| 参数 | 用途 | 是否长期保存 |
|---|---|---|
| 中位微调 | 修正硬件装配误差 | 是 |
| 站立姿态 | 描述机械狗默认站姿 | 是 |
| 动作偏移 | 描述当前临时动作 | 否 |

这种分层设计比直接到处修改最终脉宽更容易理解、调试和扩展。

## 七、“回到中位”和“回到站立”的区别

### 7.1 回到站立 `moveDogHome()`

`moveDogHome()` 会把每个关节的动作偏移清零：

```cpp
motionOffsetUs[legIndex][jointIndex] = 0;
```

最终输出为：

```text
1500 + 中位微调 + 站立姿态
```

因此，这里的 Home 指的是机械狗的默认站立姿态，并不是舵机的绝对中位。

### 7.2 回到中位 `moveDogCenter()`

程序把动作偏移设置成站立姿态的相反数：

```cpp
motionOffsetUs = -standPoseUs;
```

代入输出公式：

```text
1500 + 中位微调 + 站立姿态 - 站立姿态
```

抵消后得到：

```text
1500 + 中位微调
```

这样只会暂时抵消站立姿态，不会删除已经保存的数据。

## 八、机械狗如何产生行走动作

### 8.1 每个周期分成 20 帧

```cpp
#define GAIT_FRAME_COUNT 20
```

机械狗不是一次性跳到目标位置，而是把一个动作周期拆成 20 个小位置。连续执行这些位置后，舵机看起来就会平滑运动。

### 8.2 使用三角波生成关节偏移

`getWaveValue()` 生成的偏移变化近似为：

```text
-幅度 → +幅度 → -幅度
```

示意图：

```text
偏移
 +A       /\
         /  \
  0 ----/----\----
       /      \
 -A --          --
       时间
```

这是一种分段线性的三角波。它没有正弦函数那么平滑，但计算简单，适合微控制器入门教学。

### 8.3 大腿和小腿之间存在相位差

```cpp
int thighOffsetUs =
    getWaveValue(frameIndex, phaseOffset, thighAmplitudeUs);

int calfOffsetUs =
    getWaveValue(frameIndex,
                 phaseOffset + GAIT_FRAME_COUNT / 4,
                 calfAmplitudeUs);
```

小腿比大腿错开四分之一个周期：

```text
20 ÷ 4 = 5 帧
```

如果大腿和小腿完全同步，脚尖可能主要沿一条直线运动。加入相位差后，脚尖更容易形成“抬起、前移、落下、后移”的循环轨迹。

### 8.4 对角步态

四条腿被分成两组：

```text
第一组：右前腿 RF + 左后腿 LB
第二组：左前腿 LF + 右后腿 RB
```

第一组使用相位 0，第二组错开半个周期：

```text
RF、LB：相位 0
LF、RB：相位 10
```

因此两条对角腿同相运动，两组对角腿之间反相运动。这种思路接近四足动物的小跑步态。

> 这段代码属于基础的开环步态，没有使用逆运动学、陀螺仪反馈、足端接触检测或动态平衡算法，所以更准确地说，它是一个基础舵机步态测试程序。

## 九、`walkDog()` 如何执行一次行走

核心逻辑可以简化为：

```cpp
for (每一个步态周期) {
  for (周期中的每一帧) {
    计算四条腿的关节位置;
    等待一段时间;
  }
}
```

函数参数如下：

```cpp
walkDog(
  stepCount,         // 执行几个步态周期
  frameDelayMs,      // 每帧等待时间
  thighAmplitudeUs,  // 大腿摆动幅度
  calfAmplitudeUs    // 小腿摆动幅度
);
```

网页默认参数为：

```text
步数：2
帧间隔：80 ms
大腿幅度：160 μs
小腿幅度：120 μs
```

一个周期包含 20 帧，因此一个周期大约需要：

```text
20 × 80 ms = 1600 ms
```

两个周期大约需要：

```text
2 × 1600 ms = 3200 ms
```

动作结束后，程序调用：

```cpp
moveDogHome();
```

让机械狗重新回到站立姿态。

## 十、行走时如何响应“停止”命令

如果直接调用较长时间的 `delay()`，ESP32 在等待期间就无法及时处理网页请求。

本项目使用 `waitAndServiceControl()`：

```cpp
while (等待时间还没有结束) {
  处理 WiFi 请求;
  检查 stopRequested;
  delay(2);
}
```

用户点击网页上的“停止”按钮后，服务器执行：

```cpp
stopRequested = true;
```

行走循环检测到这个变量后就会提前退出，并让机械狗回到站立姿态。

程序还定义了一个回调函数类型：

```cpp
typedef void (*ControlServiceCallback)();
```

WiFi 模块将 `handleWifiClient` 注册给机械狗控制模块：

```cpp
setControlServiceCallback(handleWifiClient);
```

这样，机械狗控制模块不需要直接包含 Web 服务器的具体实现，也能在等待期间处理网络服务。这体现了模块解耦的设计思想。

## 十一、网页控制的工作原理

### 11.1 启动 Web 服务器

```cpp
static WebServer server(80);
```

这里的 `80` 是 HTTP 默认端口。

### 11.2 注册网页和 API 路径

```cpp
server.on("/", handleRootPage);
server.on("/api/state", handleStateApi);
server.on("/api/trim", handleTrimApi);
server.on("/api/stand", handleStandApi);
server.on("/api/offset", handleOffsetApi);
server.on("/api/walk", handleWalkApi);
server.on("/api/stop", handleStopApi);
```

API 可以理解为网页给 ESP32 下命令的地址。

例如：

```text
/api/trim?leg=0&joint=1&trim=50
```

含义是：

- `leg=0`：右前腿；
- `joint=1`：小腿关节；
- `trim=50`：中位增加 `50 μs`。

请求在程序中的调用过程为：

```text
网页 fetch()
→ ESP32 WebServer 路由
→ handleTrimApi()
→ setJointCenterTrim()
→ applyJointOutput()
→ writeServoPulseUs()
→ PCA9685 输出 PWM
```

### 11.3 状态 JSON

网页请求：

```text
/api/state
```

ESP32 会返回类似下面的 JSON：

```json
{
  "legs": [
    {
      "name": "RF",
      "joints": [
        {
          "trim": 0,
          "stand": 0,
          "offset": 0,
          "pulse": 1500
        }
      ]
    }
  ]
}
```

网页中的 JavaScript 读取这些数据，然后动态生成每条腿的控制滑块。

因此，本项目同时使用了三类技术：

- C++：控制硬件和提供服务器；
- HTML/CSS：显示控制页面；
- JavaScript：发送请求并更新页面。

## 十二、参数如何永久保存

普通变量在 ESP32 断电后会消失，所以程序使用 LittleFS 文件系统保存参数。

程序使用两个文件：

```text
/center_trim.txt
/stand_pose.txt
```

每条腿占一行，每行分别保存大腿和小腿的数据，例如：

```text
20,-30
10,-25
-15,40
0,30
```

读取时，程序先寻找逗号：

```cpp
int commaIndex = line.indexOf(',');
```

然后分别读取逗号两边的数字：

```cpp
line.substring(0, commaIndex).toInt();
line.substring(commaIndex + 1).toInt();
```

读取出的参数还会通过 `clampValue()` 限制范围，防止文件中的错误数据导致舵机输出过大。

## 十三、网页中的“绑定”功能

网页提供三种动作模式：

- 不绑定；
- 对角同向；
- 全部绑定。

### 13.1 对角绑定

对角腿之间的对应关系为：

```text
RF ↔ LB
LF ↔ RB
```

调整一条腿时，程序会同时调整它的对角腿。

### 13.2 全部绑定

四条腿都会变化，但分成两组：

```text
源腿及其对角腿：同相
另外两条腿：反相
```

程序还会根据每条腿的 `gaitSign`，把物理动作方向转换成该舵机实际需要的脉宽增减方向。

## 十四、代码中的安全限制

程序限制了三类偏移：

```cpp
#define CENTER_TRIM_LIMIT_US 400
#define STAND_POSE_LIMIT_US 500
#define MOTION_OFFSET_LIMIT_US 500
```

最终输出还会被限制在：

```text
500～2500 μs
```

这形成了两层保护：

```text
先限制各类偏移
→ 再限制最终舵机脉宽
```

例如：

```text
1500 + 400 + 500 + 500 = 2900 μs
```

由于超过最大值，最终输出会被限制为 `2500 μs`。

## 十五、代码中需要注意和改进的地方

### 15.1 WiFi 密码直接写在源代码中

程序把 WiFi 名称和密码直接写进了 `wifi_control.cpp`。课堂展示或分享代码前，应该修改已经暴露的密码，并将配置放到单独的私密文件中，例如：

```cpp
#include "wifi_secrets.h"
```

同时把私密配置文件加入 `.gitignore`，避免提交到公开仓库。

### 15.2 网页没有身份验证

同一局域网内，只要知道 ESP32 的 IP 地址，就可能控制机械狗。这个设计适合封闭的课堂实验环境，不适合直接暴露在开放网络中。

### 15.3 WiFi 连接可能永久阻塞

程序使用：

```cpp
while (WiFi.status() != WL_CONNECTED)
```

如果 WiFi 名称不存在或密码错误，程序会一直停留在初始化阶段。可以改进为：

- 加入连接超时；
- 连接失败后显示明确提示；
- 自动启动 ESP32 AP 热点作为备用控制方式。

### 15.4 舵机范围不一定适用于所有舵机

`500～2500 μs` 对部分舵机来说可能过大。首次调试时建议：

- 先卸下舵机连杆或抬起机身；
- 使用较小的脉宽范围；
- 逐个关节校准；
- 确认运动方向后再测试完整步态。

### 15.5 步数和帧间隔没有最大限制

大腿和小腿幅度已经被限制，但网页传入的步数和帧间隔没有最大值。过大的参数可能让一次请求执行很长时间。

### 15.6 中位保存功能存在重复

调整中位微调时，`handleTrimApi()` 已经自动调用：

```cpp
saveCenterTrimToFile();
```

网页又提供了“保存中位”按钮，因此两种保存方式存在功能重复。

### 15.7 LittleFS 可能自动格式化

```cpp
LittleFS.begin(true)
```

参数 `true` 表示挂载失败时允许格式化文件系统。这样可以提高自动恢复能力，但原来保存的参数也可能因此丢失。

### 15.8 当前步态属于开环控制

程序只按照预先生成的波形驱动关节，并不知道机械狗是否真的站稳。若要进一步改进，可以加入：

- IMU 姿态传感器；
- 足端接触传感器；
- 逆运动学；
- 足端轨迹规划；
- PID 姿态控制；
- 非阻塞状态机。

## 十六、推荐的课堂讲解顺序

### 第一部分：认识整个系统

先画出系统结构：

```text
手机或电脑网页
      ↓ WiFi
    ESP32
      ↓ I²C
   PCA9685
      ↓ PWM
    8 个舵机
```

让学生先知道每个硬件负责什么工作。

### 第二部分：认识数据模型

讲清楚：

```text
4 条腿
每条腿 2 个关节
总共 8 个舵机
```

再介绍腿编号、关节编号以及 PCA9685 通道。

### 第三部分：讲解核心公式

在黑板上写：

```text
最终输出 = 1500 + 中位微调 + 站立姿态 + 动作偏移
```

使用具体数值让学生进行计算。

### 第四部分：追踪一次网页请求

选择下面的请求作为例子：

```text
/api/offset?leg=0&joint=0&offset=100
```

带学生追踪完整调用链：

```text
网页 fetch()
→ WebServer
→ API 处理函数
→ 修改动作偏移
→ 计算最终脉宽
→ PCA9685
→ 舵机运动
```

### 第五部分：讲解步态

重点讲三个概念：

1. 一个动作周期被拆成 20 帧；
2. 大腿和小腿错开四分之一个周期；
3. 两组对角腿错开半个周期。

### 第六部分：讲解工程设计

最后介绍：

- 模块化；
- 参数边界保护；
- 文件持久化；
- 回调函数；
- 当前方案的不足；
- 可以继续扩展的方向。

## 十七、课堂提问建议

可以向学生提出下面的问题：

1. 为什么舵机 PWM 常用 50 Hz？
2. 为什么需要把微秒脉宽转换成 0～4095 的计数值？
3. 为什么左右腿的 `gaitSign` 不一样？
4. 中位微调、站立姿态和动作偏移为什么不合并成一个变量？
5. `moveDogCenter()` 为什么设置 `motionOffset = -standPose`？
6. 如果大腿和小腿没有相位差，脚尖轨迹会发生什么变化？
7. 为什么行走等待期间还要调用 WiFi 服务？
8. 目前的程序为什么不能保证机械狗一定不会摔倒？
9. 如果要让机械狗转弯，应该怎样改变左右腿的幅度或相位？
10. 如何避免 WiFi 连接失败后程序一直卡住？

## 十八、课堂总结稿

> 这段程序本质上是一个通过网络控制的八舵机系统。ESP32 接收网页发来的命令，把舵机中位微调、站立姿态和当前动作偏移相加，得到最终脉宽，然后通过 I²C 控制 PCA9685 输出 PWM。行走动作不是通过复杂的机器人运动学产生的，而是让关节按照三角波周期运动，并让两组对角腿保持半个周期的相位差。程序还使用 LittleFS 保存校准数据，使机械狗断电后仍能恢复原来的中位和站立姿态。

这个项目适合用来讲解以下知识点：

- Arduino 程序结构；
- C++ 模块化；
- 枚举、结构体和二维数组；
- I²C 通信；
- PWM 舵机控制；
- HTTP 和 Web API；
- JSON 数据；
- 文件持久化；
- 周期、相位和基础步态；
- 输入限制与硬件安全。
