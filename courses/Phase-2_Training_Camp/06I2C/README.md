# ESP32-S3 I2C 外设原理课

本课程共 1 课时，重点讲解 I2C 原理。扫描程序用于课堂演示，不增加复杂业务逻辑。

## 统一引脚

| I2C 信号 | ESP32-S3 |
|---|---:|
| SDA | GPIO 8 |
| SCL | GPIO 9 |
| GND | GND |

所有后续 I2C 示例均使用这组引脚。

## 1 课时安排

1. I2C 使用 SDA 数据线和 SCL 时钟线。
2. ESP32-S3 作为主机产生时钟并发起通信。
3. 每个从机使用一个 7 位地址，同一总线上的地址不能重复。
4. 主机发送地址后，从机使用 ACK 表示已经响应。
5. SDA、SCL 是开漏信号，需要上拉电阻。
6. 多个 I2C 模块可以并联在同一组 SDA、SCL 上。
7. 学习写数据、读数据和扫描设备地址。
8. 使用逻辑分析仪或串口观察 I2C 扫描结果。

演示代码：

- `01_i2c_scanner/01_i2c_scanner.ino`

## I2C 通信过程

### 写数据

```text
开始条件 → 从机地址 + 写方向 → ACK → 寄存器/命令 → ACK → 数据 → ACK → 停止条件
```

### 读数据

```text
写入寄存器地址 → 重复开始 → 从机地址 + 读方向 → 接收数据 → 停止条件
```

## 常用 Wire 函数

| 函数 | 作用 |
|---|---|
| `Wire.begin(8, 9)` | 指定 SDA、SCL 并启动 I2C |
| `Wire.setClock(100000)` | 设置 100 kHz 时钟 |
| `beginTransmission(address)` | 开始向指定从机写数据 |
| `Wire.write(value)` | 把一个字节放入发送缓冲区 |
| `Wire.endTransmission()` | 真正发送并返回通信结果 |
| `Wire.requestFrom(address, count)` | 向从机请求指定字节数 |
| `Wire.available()` | 判断接收缓冲区中还有多少字节 |
| `Wire.read()` | 读取一个字节 |

## `endTransmission()` 返回值

| 返回值 | 常见含义 |
|---:|---|
| 0 | 设备正常应答 |
| 1 | 发送数据过长 |
| 2 | 地址没有收到 ACK |
| 3 | 数据没有收到 ACK |
| 4 | 其他通信错误 |

扫描器就是依次尝试地址 `0x01～0x7E`，返回 `0` 时显示该地址。

## 本课程会使用的地址

| 模块 | 常见地址 |
|---|---:|
| MPU6050（AD0 接低电平） | `0x68` |
| MPU6050（AD0 接高电平） | `0x69` |
| 八路巡线模块 | `0x27` |
| SSD1306 OLED | `0x3C`，少数模块为 `0x3D` |

地址最终应以扫描结果和模块说明书为准。

## 上拉电阻

I2C 引脚通过器件内部的开漏晶体管拉低信号，释放后需要上拉电阻把信号恢复为高电平。
很多模块已经带有上拉电阻；如果总线上完全没有上拉，通信通常无法正常工作。

课堂短线、100 kHz 通信可先使用模块自带上拉。模块较多或线较长时，要检查并联后的
总上拉阻值和信号波形。

## 接线规则

1. 所有模块的 SDA 并联到 GPIO 8。
2. 所有模块的 SCL 并联到 GPIO 9。
3. 所有模块与 ESP32-S3 必须共地。
4. ESP32-S3 是 3.3V 逻辑，确认模块 SDA、SCL 不会被上拉到 5V。
5. 同一总线上不能出现两个相同地址的设备，除非模块支持修改地址或使用 I2C 复用器。
6. 接线和拆线前先断电。

## 常见问题

- **扫描不到设备：** 检查 SDA/SCL 是否接反、是否共地、模块是否供电。
- **扫描地址不稳定：** 检查导线、上拉电阻和供电，先把时钟保持在 100 kHz。
- **只能找到一个设备：** 检查其他模块的地址、供电以及是否与已有地址冲突。
- **ESP32-S3 异常：** 立即断电，检查 I2C 信号是否被上拉到 5V。
