# 第一模块 引言

## 0. 串口通信知识点总览（教学时必须先讲）

> 教学顺序要求：先讲本节知识地图，再进入代码。第一课时的大部分时间用于讲清 UART 原理和固定数据帧组成，不先让学生机械抄写函数。

### 0.1 串口通信是什么

- 串口通信是设备之间按照时间顺序，一位一位发送数据的通信方式。
- 本课程有两种使用场景：
  - `Serial`：ESP32-S3 与电脑通信，用于串口监视器调试，课堂波特率为 `115200`。
  - `SoftSerial`：两块 ESP32-S3 之间通信，课堂波特率为 `9600`。
- UART 全称为 Universal Asynchronous Receiver/Transmitter，即“通用异步收发器”。
- “异步”表示没有单独的时钟线，因此通信双方必须提前约定相同的波特率和数据格式。

### 0.2 接线和电气规则

- `TX` 是发送端，`RX` 是接收端。
- 双板通信必须交叉连接：本板 `TX` 接对方 `RX`，本板 `RX` 接对方 `TX`。
- 两块板必须连接 `GND`，建立共同的电平参考。
- 本课使用默认 `8N1`：8 个数据位、无校验位、1 个停止位。
- UART 可以同时发送和接收，属于全双工通信。
- ESP32-S3 GPIO 是 3.3V 逻辑电平，不可直接接入 5V 串口信号。

### 0.3 数据、字符和字节

- `bit` 是一个二进制位，只能是 0 或 1。
- `byte` 是一个字节，由 8 个 bit 组成，取值范围为 `0x00～0xFF`。
- 字符也要编码成字节后传输，例如字符 `A` 的 ASCII 十进制值是 65，十六进制值是 `0x41`。
- 串口监视器中的文字显示不等于线路上直接发送“文字概念”，线路上传输的仍然是字节。

### 0.4 接收缓冲区

- 串口收到的数据会先进入接收缓冲区，等待程序读取。
- `available()` 返回当前可读取的字节数，不是消息数。
- `peek()` 只查看下一个字节，不把它取走。
- `read()` 读取并取走下一个字节。
- 串口不会通知程序“完整一帧已经到达”，因此程序必须自己判断字节数量和数据边界。

### 0.5 文本发送与原始字节发送

```cpp
Serial.print(65);  // 发送字符 '6'、'5'，共两个字节
Serial.write(65);  // 发送数值为 65 的一个原始字节
```

- `print()`、`println()` 适合给人看的调试文字。
- `write()` 适合发送二进制协议和完整数据帧。
- HEX 工具发送 `55` 表示原始字节 `0x55`；普通文本框输入 `55` 表示两个字符 `'5'`、`'5'`，两者不能混用。

### 0.6 本课程固定数据帧

```text
55 05 CMD DATA CHECKSUM FF
```

| 位置 | 字段 | 固定值或作用 |
|---:|---|---|
| 0 | 帧头 `HEADER` | 固定 `0x55`，用于寻找一帧开始 |
| 1 | 长度 `LENGTH` | 固定 `0x05`，表示帧头后还有 5 个字节 |
| 2 | 指令 `CMD` | 表示要执行的功能 |
| 3 | 数据 `DATA` | 表示该功能使用的参数 |
| 4 | 校验 `CHECKSUM` | `LENGTH + CMD + DATA`，只保留低 8 位 |
| 5 | 帧尾 `TAIL` | 固定 `0xFF`，表示一帧结束 |

注意：`LENGTH=0x05` 不是“整帧 5 字节”。它表示帧头之后还有 5 字节，所以整帧共有 6 字节。

### 0.7 加法校验

校验规则：

```text
CHECKSUM = LENGTH + CMD + DATA，只保留低 8 位
```

示例：

```text
0x05 + 0x01 + 0xFF = 0x105
去掉进位后得到 0x05
完整帧：55 05 01 FF 05 FF
```

帧头和帧尾不参加校验计算。加法校验只能发现一部分传输错误，能力弱于 CRC，但适合本课手算和入门演示。

### 0.8 接收与执行的正确顺序

```text
等待至少 6 字节 → 寻找帧头 → 读取剩余字段
→ 检查长度 → 检查帧尾 → 重算校验和
→ 检查指令和数据范围 → 执行动作 → 发送应答
```

- 校验之前不能控制 LED、蜂鸣器或其他外设。
- 长度、帧尾或校验错误时直接丢弃，不发送应答。
- 指令不存在时返回 `CMD_ERROR / 0x01`。
- 指令存在但数据不合法时返回 `CMD_ERROR / 0x02`。
- 成功应答指令等于请求指令加 `0x80`，例如 `0x01` 的成功应答为 `0x81`。

## 1. 本课目标与现象导入

### 1.1 本课目标
- 本课要完成的实验任务：
  - 完成单字符串口读取实验。
  - 完成按行读取串口文字实验。
  - 完成固定二进制数据帧接收与应答实验。
  - 完成串口切换蜂鸣器歌曲实验。
  - 完成串口控制呼吸灯实验。
  - 完成板 A 发送指令的 UART 实验。
  - 完成板 B 接收并应答的 UART 实验。
- 本课要掌握的核心知识点：
  - 理解 `Serial.begin()`、`available()`、`peek()`、`read()`、`write()` 的作用。
  - 理解 `readStringUntil()`、`setTimeout()`、`trim()` 的使用场景。
  - 理解 `print()`、`println()` 和 `write()` 的区别。
  - 理解固定数据帧 `55 05 CMD DATA CHECKSUM FF` 的组成。
  - 理解加法校验、成功应答、错误应答的基本规则。
  - 理解 UART 的 `TX`、`RX`、共地、交叉接线和波特率一致性。

### 1.2 现象导入
- 现象：
  - 在串口监视器输入一个字符后，开发板会显示字符本身和对应的 ASCII 数值。
  - 在串口监视器输入一整行文字后，开发板会根据不同文字内容返回不同回复。
  - 发送正确的 HEX 数据帧后，LED 会被控制，同时串口返回应答帧。
  - 发送歌曲数据帧后，无源蜂鸣器会播放《两只老虎》或《小星星》。
  - 发送呼吸灯数据帧后，LED 可以启动、停止和改变呼吸速度。
  - 板 A 输入文字命令后，会把文字打包成数据帧发给板 B。
  - 板 B 接收数据帧后会控制 LED，并回发应答帧给板 A。

## 2. 本课共用预备知识

### 2.1 共用预备知识
- 本课会用到的旧知识：
  - 会使用 `Arduino IDE` 上传程序。
  - 知道 LED、无源蜂鸣器和 `PWM` 的基础控制方法。
  - 理解高电平、低电平、GPIO 和共地的基本概念。
- 本课新增的核心概念：
  - 串口通信是开发板和电脑、开发板和开发板之间交换数据的常用方法。
  - `available()` 返回的是缓冲区中的字节数，不是“消息条数”。
  - 文本串口适合做调试和人工输入，二进制数据帧适合做正式协议。
  - `TX` 负责发送，`RX` 负责接收，两块板之间需要交叉连接。
  - 数据帧必须先校验，再执行，不能收到数据就立刻控制外设。
  - `write()` 发送的是原始字节，`print()` 发送的是可读文本。
- 本课涉及的重点英文单词(函数命名、变量命名等使用的英文单词)：
  - `serial`：串口
  - `communication`：通信
  - `read`：读取
  - `write`：写入 / 发送原始字节
  - `available`：可用的 / 缓冲区中已有的
  - `peek`：偷看 / 只查看不取走
  - `frame`：数据帧
  - `header`：帧头
  - `length`：长度
  - `command`：指令
  - `data`：数据
  - `checksum`：校验和
  - `tail`：帧尾
  - `uart`：通用异步收发器
  - `timeout`：超时
  - `string`：字符串
  - `newline`：换行
  - `reply`：应答 / 回复
  - `ping`：连通性测试
- 学生开始实验前必须先知道的内容：
  - 文本实验一般使用普通串口监视器，正式数据帧实验要使用支持 HEX 发送的串口工具。
  - 本章单板实验的 USB 串口波特率主要为 `115200`。
  - 双板通信实验的软串口波特率为 `9600`，两端必须一致。
  - `TX` 不能接 `TX`，`RX` 不能接 `RX`，两块开发板必须共地。

## 3. 本课共用器材与基础接线约定

### 3.1 所需器材
- 开发板：
  - `ESP32-S3` 开发板 `2` 块
- 传感器/执行器/模块：
  - 普通 LED 或板载 LED
  - 无源蜂鸣器模块
- 电阻、面包板、杜邦线：
  - `220Ω` 电阻若干
  - 面包板 `1` 块
  - 杜邦线若干
- USB 数据线：
  - 开发板对应数据线 `2` 根
- 软件环境：
  - `Arduino IDE`
  - `esp32` 开发板支持包
  - `EspSoftwareSerial` 库
  - 普通串口监视器
  - 支持 HEX 发送 / HEX 显示的串口工具

### 3.2 共用硬件介绍
- 本课涉及的器件名称：
  - USB 串口、LED、无源蜂鸣器、两块 `ESP32-S3`
- 每个器件的作用：
  - USB 串口：连接电脑，用于输入命令和观察结果。
  - LED：用来验证串口控制是否成功。
  - 无源蜂鸣器：用来验证歌曲切换指令是否成功。
  - 第二块开发板：用来完成双板 UART 通信实验。
- 关键特性说明：
  - 单板实验中，`Serial` 通常用于和电脑通信。
  - 双板实验中，额外使用 `SoftwareSerial` 创建软串口。
  - 正式协议使用固定 6 字节数据帧：`55 05 CMD DATA CHECKSUM FF`。
  - `write()` 适合发送二进制帧，`print()` 和 `println()` 适合发送调试文本。
- 容易出错的地方：
  - 把 HEX 数据帧当普通文字发送。
  - 串口工具没有设置正确的换行方式。
  - 双板实验中 TX/RX 没有交叉连接，或者没有共地。
  - 两块板的软串口波特率设置不一致。
