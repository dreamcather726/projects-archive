# 串口课堂代码详细讲解

> 用途：8 月 10 日串口通信课程教师讲解稿。  
> 讲解范围：基础单字节收发、固定数据帧的声明、组帧发送、收帧校验、LED 指令和 PING 扩展。  
> 代码依据：仓库实际 `.ino/.h/.cpp` 文件；讲解时不擅自改动变量名、参数和协议值。

## 一、上代码前必须先讲的知识点

1. UART 没有单独时钟线，两端必须使用相同波特率和数据格式。
2. 双板连接使用 `TX→RX`、`RX←TX`，并连接 `GND`。
3. 接收数据先进入缓冲区；`available()` 返回字节数。
4. 文本显示与原始字节不是同一种发送方式：`print()` 发文字，`write()` 发原始字节。
5. 本课协议固定为 `55 05 CMD DATA CHECKSUM FF`，整帧 6 字节。
6. 校验和为 `LENGTH + CMD + DATA` 的低 8 位。
7. 正式通信必须先收完整帧、再校验、后执行，最后才应答。

## 三、代码一：单字节串口收发

源文件：`04Serial_communication/01_serial_read_char/01_serial_read_char.ino`

### 1. `setup()` 初始化

```cpp
void setup() {
  Serial.begin(115200);
  Serial.println("请输入任意字符：");
}
```

逐行讲解：

| 代码 | 详细说明 |
|---|---|
| `void setup()` | Arduino 上电或复位后只执行一次，用于初始化。`void` 表示没有返回值。 |
| `Serial.begin(115200);` | 启动电脑调试串口；参数 `115200` 是通信波特率，串口监视器必须选择相同数值。 |
| `Serial.println(...)` | 输出提示文字并换行，方便学生知道程序已经运行。 |

教师提问：如果代码是 115200、串口监视器是 9600，会出现什么现象？答案：通常乱码或无法正确显示。

### 2. 判断缓冲区是否有数据

```cpp
if (Serial.available() > 0) {
  int byteCount = Serial.available();
```

- 第一次 `available()` 用于做条件判断：只有至少收到 1 字节才进入代码块。
- 第二次 `available()` 取得当前待读字节数，保存到 `byteCount`。
- `byteCount` 的英文拆分为 `byte + count`，表示“字节数量”。
- 必须强调：这里得到的不是“有几条消息”。

教师演示：串口监视器选择 No line ending，分别发送 `A` 和 `ABC`，让学生观察初次进入循环时的待读字节数。

### 3. `peek()` 与 `read()`

```cpp
int nextByte = Serial.peek();
int receivedByte = Serial.read();
```

| 项目 | `peek()` | `read()` |
|---|---|---|
| 整体作用 | 查看下一个字节 | 读取下一个字节 |
| 是否从缓冲区取走 | 否 | 是 |
| 参数 | 无 | 无 |
| 没有数据时 | 返回 `-1` | 返回 `-1` |
| 本段变量 | `nextByte` | `receivedByte` |

因为两行之间没有其他读取操作，所以对同一个字节，`nextByte` 与 `receivedByte` 的数值应该相同；区别在于 `read()` 执行后缓冲区少了一个字节。

### 4. 输出数值和字符

```cpp
Serial.print("待读字节数：");
Serial.print(byteCount);
Serial.print("，peek：");
Serial.print(nextByte);
Serial.print("，read：");
Serial.print(receivedByte);
Serial.print("，字符：");
```

- `print()` 不自动换行，所以多个内容会出现在同一行。
- 当输入字符 `A` 时，`peek` 和 `read` 显示十进制 65，因为串口传输的是字符的 ASCII 编码。
- 此处用 `print(receivedByte)` 会显示数字 `65`，不是字符 `A`。

### 5. 区分回车、换行和普通字符

```cpp
if (receivedByte == '\r') {
  Serial.println("[回车]");
} else if (receivedByte == '\n') {
  Serial.println("[换行]");
} else {
  Serial.write(receivedByte);
  Serial.println();
}
```

逐项解释：

- `\r` 是回车 CR，ASCII 十进制值为 13。
- `\n` 是换行 NL，ASCII 十进制值为 10。
- 普通字符用 `write(receivedByte)` 把原始字节发回，因此 65 会显示为字符 `A`。
- 最后的空参数 `println()` 只负责换行。

课堂对比：

| 串口工具设置 | 发送 `A` 后附加内容 |
|---|---|
| No line ending | 只发送 `A` |
| Newline | 发送 `A` 和 `\n` |
| Both NL & CR | 发送 `A`、`\r`、`\n` |

## 四、代码二：`SerialFrame.h` 头文件

源文件：`04Serial_communication/03_data_frame/SerialFrame.h`

```cpp
#ifndef SERIAL_FRAME_H
#define SERIAL_FRAME_H

#include <Arduino.h>

void sendFrame(byte command, byte data);
bool readFrame();
byte getFrameCommand();
byte getFrameData();

#endif
```

本课只要求理解文件分工：

- `.h` 头文件告诉主程序“有哪些函数可以使用”。
- `.cpp` 文件保存函数的具体实现。
- `#include "SerialFrame.h"` 把这些声明引入 `.ino` 主程序。
- `#ifndef / #define / #endif` 用于防止头文件被重复包含，学生会认即可，不要求独立编写。

函数声明逐项解释：

| 声明 | 返回值 | 参数 | 整体作用 |
|---|---|---|---|
| `void sendFrame(byte command, byte data)` | 无 | 指令、数据 | 组成并发送完整数据帧 |
| `bool readFrame()` | `true/false` | 无 | 接收并检查一条数据帧 |
| `byte getFrameCommand()` | 指令字节 | 无 | 取得上一条合法帧的指令 |
| `byte getFrameData()` | 数据字节 | 无 | 取得上一条合法帧的数据 |

## 五、代码三：协议常量和校验和

源文件：`04Serial_communication/03_data_frame/SerialFrame.cpp`

### 1. 协议常量

```cpp
const byte FRAME_HEADER = 0x55;
const byte FRAME_LENGTH = 0x05;
const byte FRAME_TAIL = 0xFF;
const byte FRAME_SIZE = 6;
```

| 常量 | 数值 | 作用 |
|---|---:|---|
| `FRAME_HEADER` | `0x55` | 寻找数据帧开始 |
| `FRAME_LENGTH` | `0x05` | 表示帧头后还有 5 字节 |
| `FRAME_TAIL` | `0xFF` | 检查数据帧结束 |
| `FRAME_SIZE` | `6` | 整个数组和完整帧共有 6 字节 |

这里专门比较 `LENGTH` 与 `SIZE`：前者是协议字段值 5，后者是整帧实际字节数 6。

### 2. 保存最近一次合法结果

```cpp
byte frameCommand = 0;
byte frameData = 0;
```

- `readFrame()` 校验成功后，把指令保存到 `frameCommand`，把数据保存到 `frameData`。
- 主程序随后通过 `getFrameCommand()` 和 `getFrameData()` 取得结果。
- 初始值 0 只是上电时的默认值；在 `readFrame()` 返回 `true` 之前不能把它当成新命令。

### 3. 计算校验和

```cpp
byte calculateChecksum(byte command, byte data) {
  return (byte)(FRAME_LENGTH + command + data);
}
```

| 部分 | 解释 |
|---|---|
| 返回类型 `byte` | 只保存 8 位，范围 `0x00～0xFF` |
| 参数 `command` | 当前帧的指令类型 |
| 参数 `data` | 当前帧的指令数据 |
| `FRAME_LENGTH + command + data` | 本课程统一的求和范围 |
| `(byte)` | 把结果保留为一个字节，超出的高位进位被舍去 |

课堂手算：

```text
命令：LED 亮度 255
05 + 01 + FF = 105
保留低 8 位 = 05
完整帧 = 55 05 01 FF 05 FF
```

## 六、代码四：`sendFrame()` 组帧发送

```cpp
void sendFrame(byte command, byte data) {
  byte frame[FRAME_SIZE];

  frame[0] = FRAME_HEADER;
  frame[1] = FRAME_LENGTH;
  frame[2] = command;
  frame[3] = data;
  frame[4] = calculateChecksum(command, data);
  frame[5] = FRAME_TAIL;

  Serial.write(frame, FRAME_SIZE);
}
```

### 1. 函数整体作用和参数

- 整体作用：根据传入的指令和数据，自动生成并发送完整 6 字节数据帧。
- 参数 1 `command`：要发送的指令或应答类型。
- 参数 2 `data`：随指令发送的数据。
- 返回值：无。

### 2. 数组下标与帧位置

| 数组代码 | 帧位置 | 实际内容 |
|---|---:|---|
| `frame[0]` | 0 | 帧头 `0x55` |
| `frame[1]` | 1 | 长度 `0x05` |
| `frame[2]` | 2 | 函数参数 `command` |
| `frame[3]` | 3 | 函数参数 `data` |
| `frame[4]` | 4 | 自动计算的校验和 |
| `frame[5]` | 5 | 帧尾 `0xFF` |

数组有 6 个元素，下标从 0 开始，所以最后一个下标是 5。

### 3. 发送整帧

```cpp
Serial.write(frame, FRAME_SIZE);
```

- 参数 1 `frame`：要发送的字节数组。
- 参数 2 `FRAME_SIZE`：发送 6 个字节。
- 必须使用 `write()`，不能改成 `print(frame)`。

调用示例：

```cpp
sendFrame(0x81, 0xFF);
```

生成结果：

```text
55 05 81 FF 85 FF
```

## 七、代码五：`readFrame()` 接收和校验

### 1. 等待至少 6 字节

```cpp
while (Serial.available() >= FRAME_SIZE) {
```

- `Serial.available()` 返回缓冲区中的字节数。
- `FRAME_SIZE` 为 6。
- 不足 6 字节时不读取半条帧，等后续字节到达。
- 使用 `while` 是为了缓冲区中连续到达多帧或前面有干扰字节时可以继续寻找。

### 2. 寻找帧头

```cpp
byte header = Serial.read();

if (header != FRAME_HEADER) {
  continue;
}
```

- 每次先取出一个字节作为候选帧头。
- 如果不是 `0x55`，说明它是帧前干扰字节。
- `continue` 立即结束本次循环，重新查看剩余缓冲区。
- 此时绝对不能读取它后面的 5 个字节当作有效字段。

### 3. 读取剩余五个字段

```cpp
byte length = Serial.read();
byte command = Serial.read();
byte data = Serial.read();
byte checksum = Serial.read();
byte tail = Serial.read();
```

因为进入循环前已经确认至少有 6 字节，并且刚刚取走了帧头，所以剩下 5 个字段可以依次读取。

教师应让学生用手指对应板书位置：

```text
header → length → command → data → checksum → tail
  55       05        01       FF       05        FF
```

### 4. 检查长度

```cpp
if (length != FRAME_LENGTH) {
  continue;
}
```

- 收到的 `length` 必须等于协议规定的 `0x05`。
- 长度错误说明发送端与接收端格式不一致，当前帧不能执行。

### 5. 检查帧尾

```cpp
if (tail != FRAME_TAIL) {
  continue;
}
```

- 收到的 `tail` 必须为 `0xFF`。
- 帧尾错误可能表示数据缺失、错位或协议不一致。

### 6. 重算并比较校验和

```cpp
if (checksum != calculateChecksum(command, data)) {
  continue;
}
```

- 左边 `checksum` 是接收帧中携带的校验位。
- 右边是接收端根据 `command` 和 `data` 重新计算的结果。
- 两者不相等就丢弃，不能自动修改后执行。

### 7. 保存合法数据并返回

```cpp
frameCommand = command;
frameData = data;
return true;
```

- 只有三项检查全部通过，才保存指令和数据。
- `return true` 立即告诉主程序“收到了一条合法帧”。

函数末尾：

```cpp
return false;
```

表示当前没有可交给主程序执行的合法帧。可能是数据不足，也可能是刚才的数据帧错误。

### 8. `readFrame()` 流程总结

```text
available >= 6？
  否 → false
  是 → 读候选帧头
       ├─ 不是 55 → 丢弃并继续寻找
       └─ 是 55 → 读取剩余 5 字节
                  ├─ 长度错误 → 丢弃
                  ├─ 帧尾错误 → 丢弃
                  ├─ 校验错误 → 丢弃
                  └─ 全部正确 → 保存 CMD/DATA → true
```

## 八、代码六：主程序校验后执行

源文件：`04Serial_communication/03_data_frame/03_data_frame.ino`

### 1. 指令和引脚定义

```cpp
#define CMD_LED 0x01
#define CMD_ERROR 0x7F
#define PIN_LED 2
```

- `CMD_LED` 为 LED 亮度指令。
- `CMD_ERROR` 为错误应答指令。
- LED 接 GPIO 2，外接 LED 必须串联限流电阻。

### 2. 初始化

```cpp
void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
}
```

- 串口工具必须使用 115200。
- `pinMode()` 把 GPIO 2 设置为输出。

### 3. 主循环

```cpp
void loop() {
  if (readFrame()) {
    byte command = getFrameCommand();
    byte data = getFrameData();

    if (command == CMD_LED) {
      analogWrite(PIN_LED, data);
      sendFrame(0x81, data);
    } else {
      sendFrame(CMD_ERROR, 0x01);
    }
  }
}
```

逐段解释：

1. `if (readFrame())` 是安全门：协议检查没有通过就不进入控制代码。
2. `getFrameCommand()` 和 `getFrameData()` 取得刚才保存的合法内容。
3. `command == CMD_LED` 检查功能类型。
4. `analogWrite(PIN_LED, data)` 把 `0x00～0xFF` 直接作为 PWM 亮度。
5. `sendFrame(0x81, data)` 返回成功应答；`0x81 = 0x01 + 0x80`。
6. 其他指令返回 `CMD_ERROR, 0x01`，表示“不支持的指令”。

课堂验证表：

| 发送帧 | 预期现象 | 预期应答 |
|---|---|---|
| `55 05 01 FF 05 FF` | LED 亮度 255 | `55 05 81 FF 85 FF` |
| `55 05 01 00 06 FF` | LED 关闭 | `55 05 81 00 86 FF` |
| `55 05 02 01 08 FF` | 不执行 LED | `55 05 7F 01 85 FF` |
| `55 05 01 FF 04 FF` | 校验失败，不执行 | 无应答 |

## 九、代码七：PING 扩展与作业衔接

本段对应 8 月 10 日作业拓展题。PING 只检查协议连通，不改变 LED 状态。

### 1. 新增常量

```cpp
#define CMD_PING 0x05
```

### 2. 修改指令判断

```cpp
if (command == CMD_LED) {
  analogWrite(PIN_LED, data);
  sendFrame(0x81, data);
} else if (command == CMD_PING) {
  if (data == 0x00) {
    sendFrame(0x85, data);
  } else {
    sendFrame(CMD_ERROR, 0x02);
  }
} else {
  sendFrame(CMD_ERROR, 0x01);
}
```

### 3. 为什么要分两层判断

- 第一层判断 `command`：是不是 PING 功能。
- 第二层判断 `data`：PING 数据是否为协议规定的 `0x00`。
- 指令不存在使用错误码 `0x01`。
- 指令存在但数据不合法使用错误码 `0x02`。

### 4. 三条帧的计算

```text
PING 请求：       05 + 05 + 00 = 0A → 55 05 05 00 0A FF
成功应答：        05 + 85 + 00 = 8A → 55 05 85 00 8A FF
数据错误应答：    05 + 7F + 02 = 86 → 55 05 7F 02 86 FF
```

## 十、课堂板书和讲解检查

### 1. 必须保留的板书

```text
对象.函数(参数)

TX → RX    RX ← TX    GND ↔ GND
两端波特率和 8N1 必须一致

55 05 CMD DATA CHECKSUM FF
校验 = LENGTH + CMD + DATA（低 8 位）

先收完整帧 → 校验 → 检查数据范围 → 执行 → 应答
```

### 2. 学生必须回答的检查题

1. `available()` 返回字节数还是消息数？
2. `peek()` 和 `read()` 哪一个会取走数据？
3. `print(65)` 和 `write(65)` 分别发送什么？
4. 为什么 `FRAME_LENGTH` 是 5，而 `FRAME_SIZE` 是 6？
5. 哪三个字段参加校验和计算？
6. 校验错误后能不能先执行 LED 再提示错误？
7. `sendFrame()` 两个参数分别是什么？
8. `readFrame()` 在什么情况下返回 `true`？
9. PING 数据为 `0x01` 时为什么使用错误码 `0x02`？

### 3. 作业前最低掌握标准

- 能独立写出固定帧六个字段。
- 能手算不进位和有进位的校验和。
- 能解释 `available/peek/read/write`。
- 能把数组下标 0～5 对应到六个帧字段。
- 能说出 `readFrame()` 的三项检查：长度、帧尾、校验和。
- 能解释“协议错误不应答”与“指令/数据错误要应答”的区别。
