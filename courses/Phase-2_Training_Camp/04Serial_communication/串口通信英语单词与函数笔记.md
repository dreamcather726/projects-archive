# 串口通信英语单词与函数笔记

> 适用范围：ESP32-S3、Arduino 串口监视器、固定 6 字节数据帧和双板 UART 通信。  
> 学习目标：看到英文能说出中文；看到函数能说出“整体作用、参数作用、返回值和使用场景”。

## 1. 先学会看懂一行函数

示例：

```cpp
String message = Serial.readStringUntil('\n');
```

可以从左到右拆开：

| 代码 | 含义 |
|---|---|
| `String` | 返回结果的数据类型是字符串 |
| `message` | 变量名，意思是“消息” |
| `Serial` | 连接电脑的串口对象 |
| `.` | “这个对象的” |
| `readStringUntil` | 一直读取字符串，直到遇到指定内容 |
| `('\n')` | 参数；规定遇到换行符时结束读取 |
| `;` | 一条语句结束 |

记忆公式：

```text
对象.函数(参数)
谁来做.做什么(按什么要求做)
```

再看一个例子：

```cpp
Serial.begin(115200);
```

- 谁来做：`Serial`，电脑调试串口。
- 做什么：`begin`，启动串口。
- 按什么要求：`115200`，使用 115200 波特率。

### 1.1 参数和返回值是什么

- **参数（parameter）**：调用函数时放在括号里的输入条件。例如 `begin(115200)` 中的 `115200`。
- **返回值（return value）**：函数做完后交回来的结果。例如 `available()` 返回当前可读取的字节数。
- **无参数**：括号中没有内容，例如 `Serial.read()`。
- **无返回值**：函数只完成动作，不交回结果，例如 `message.trim()`。

## 2. 第一组：必须先记住的 20 个核心词

| 英文 | 拆分或来源 | 中文含义 | 在本课中的意思 |
|---|---|---|---|
| `serial` | serial | 串行、串口 | 数据按顺序一位一位传输 |
| `communication` | communicate + ion | 通信 | 两个设备按照约定交换数据 |
| `UART` | Universal Asynchronous Receiver/Transmitter | 通用异步收发器 | 不使用单独时钟线的串口硬件 |
| `transmit` | transmit | 发送、传输 | 把数据从本设备发出去 |
| `receive` | receive | 接收 | 接收其他设备发来的数据 |
| `TX` | Transmit | 发送端 | 串口发送引脚 |
| `RX` | Receive | 接收端 | 串口接收引脚 |
| `baud rate` | baud + rate | 波特率 | 双方约定的通信速率 |
| `bit` | bit | 位 | 二进制中的一个 `0` 或 `1` |
| `byte` | byte | 字节 | 8 个二进制位 |
| `frame` | frame | 数据帧 | 按照协议排好的一组完整字节 |
| `header` | head + er | 帧头 | 标记一帧开始，本协议为 `0x55` |
| `length` | long 的名词形式 | 长度 | 本协议中表示帧头后还有几个字节 |
| `command` | command | 指令、命令 | 表示要执行哪一种功能 |
| `data` | data | 数据 | 指令使用的具体数值 |
| `checksum` | check + sum | 校验和 | 用“检查 + 求和”判断数据是否可能出错 |
| `tail` | tail | 尾部、帧尾 | 标记一帧结束，本协议为 `0xFF` |
| `buffer` | buffer | 缓冲区 | 临时保存已收到、还没读取的数据 |
| `read` | read | 读取 | 从接收缓冲区取出数据 |
| `write` | write | 写入、发送 | 向串口发送原始字节 |

### 2.1 最重要的成对记忆

| 一组词 | 记忆方法 |
|---|---|
| `TX` / `RX` | T = transmit = 发；R = receive = 收 |
| `read` / `write` | read 从串口取；write 向串口发 |
| `header` / `tail` | head 是头；tail 是尾 |
| `request` / `response` | request 是请求；response 是应答 |
| `input` / `output` | input 是输入；output 是输出 |
| `valid` / `invalid` | valid 有效；前面加 `in-` 变成无效 |

## 3. 第二组：串口原理单词

| 英文 | 中文 | 课堂解释 |
|---|---|---|
| `asynchronous` | 异步的 | 没有单独时钟线，双方必须提前约定速率和格式 |
| `receiver` | 接收器 | UART 中负责接收数据的部分 |
| `transmitter` | 发送器 | UART 中负责发送数据的部分 |
| `ground` / `GND` | 地、地线 | 两块板必须共地，才能有相同的电平参考 |
| `clock` | 时钟 | UART 没有单独的时钟线 |
| `logic level` | 逻辑电平 | ESP32-S3 GPIO 使用 3.3V 逻辑电平 |
| `full duplex` | 全双工 | 可以同时发送和接收 |
| `half duplex` | 半双工 | 两个方向不能在同一时刻同时通信 |
| `start bit` | 起始位 | 告诉接收端一个字符要开始了 |
| `data bit` | 数据位 | 实际承载数据的位 |
| `parity` | 校验、奇偶校验 | UART 字符格式中的可选错误检查位 |
| `stop bit` | 停止位 | 表示一个字符传输结束 |
| `8N1` | 8 位、无校验、1 个停止位 | `8` = 8 个数据位；`N` = No parity；`1` = 1 个停止位 |
| `binary` | 二进制 | 由 0 和 1 组成的数据形式 |
| `hexadecimal` / `HEX` | 十六进制 | 用 0～9 和 A～F 简写二进制数据 |
| `ASCII` | ASCII 字符编码 | 例如字符 `A` 对应十进制 65，即十六进制 `0x41` |
| `protocol` | 协议 | 发送端和接收端共同遵守的格式与规则 |

### 3.1 串口原理一句话

```text
UART 没有单独时钟线，所以两端必须使用相同的波特率和数据格式；
双板通信时 TX 接对方 RX、RX 接对方 TX，并且必须共地。
```

## 4. 第三组：数据帧单词

本课固定帧：

```text
55 05 CMD DATA CHECKSUM FF
```

| 位置 | 英文 | 中文 | 固定值或作用 |
|---:|---|---|---|
| 0 | `FRAME_HEADER` | 帧头 | 固定 `0x55`，用于寻找一帧的开始 |
| 1 | `FRAME_LENGTH` | 帧长度 | 固定 `0x05`，表示帧头之后还有 5 个字节 |
| 2 | `command` / `CMD` | 指令类型 | 表示 LED、歌曲、呼吸灯或 PING 等功能 |
| 3 | `data` | 指令数据 | 表示亮度、歌曲编号、开关状态等参数 |
| 4 | `checksum` | 校验和 | `LENGTH + CMD + DATA`，只保留低 8 位 |
| 5 | `FRAME_TAIL` | 帧尾 | 固定 `0xFF`，表示一帧结束 |

相关词语：

| 英文 | 中文 | 在程序中的意思 |
|---|---|---|
| `size` | 大小、数量 | `FRAME_SIZE` 表示整帧字节数，本课为 6 |
| `calculate` | 计算 | `calculateChecksum()` 表示计算校验和 |
| `sum` | 总和 | `checksum` 中的 `sum` 就是相加结果 |
| `request` | 请求 | 发送端发给接收端的命令帧 |
| `response` / `reply` | 应答、回复 | 接收端处理后发回的结果 |
| `error` | 错误 | `CMD_ERROR` 表示错误应答指令 |
| `success` | 成功 | 请求执行成功时返回成功应答 |
| `valid` | 合法、有效 | 长度、帧尾和校验全部正确 |
| `invalid` | 不合法、无效 | 字段或数据不符合协议 |
| `discard` | 丢弃 | 错误帧不执行，直接丢弃 |
| `execute` | 执行 | 校验通过后才执行 LED 等动作 |
| `range` | 范围 | 指令数据允许使用的数值范围 |
| `low 8 bits` | 低 8 位 | 加法超过 `0xFF` 时去掉高位进位 |
| `ping` | 连通性测试 | 不控制外设，只检查通信是否正常 |

### 4.1 校验和示例

```text
55 05 01 FF 05 FF
```

计算：

```text
0x05 + 0x01 + 0xFF = 0x105
只保留低 8 位，得到 0x05
```

特别注意：帧头 `0x55` 和帧尾 `0xFF` 不参加校验和计算。

## 5. 核心串口函数详解

### 5.1 `Serial.begin(baudRate)`

英文拆分：`begin` = 开始；`baud rate` = 波特率。

```cpp
Serial.begin(115200);
```

- **整体作用**：启动 `Serial` 串口，并设置通信波特率。
- **参数 `baudRate`**：波特率。示例中的 `115200` 表示本课电脑与开发板使用 115200 波特率。
- **返回值**：课堂中可理解为无返回值，不需要用变量接收。
- **使用位置**：通常写在 `setup()` 中，只初始化一次。
- **常见错误**：程序为 `115200`，串口监视器却选择 `9600`，显示会乱码或无法正常通信。

双板软串口：

```cpp
SoftSerial.begin(9600);
```

作用相同，但它启动的是板间软串口，课堂代码使用 `9600`。

### 5.2 `Serial.available()`

英文拆分：`available` = 可用的、已经有的。

```cpp
int byteCount = Serial.available();
```

- **整体作用**：查看接收缓冲区中目前有多少个字节可以读取。
- **参数**：无。
- **返回值**：整数，表示可读取的字节数。
- **重要理解**：返回的是“字节数”，不是“消息条数”或“数据帧条数”。
- **常见用法**：

```cpp
if (Serial.available() > 0) {
  int receivedByte = Serial.read();
}
```

固定 6 字节帧要等够 6 字节：

```cpp
while (Serial.available() >= FRAME_SIZE) {
  // 开始读取一帧
}
```

### 5.3 `Serial.peek()`

英文：`peek` = 偷看、看一眼。

```cpp
int nextByte = Serial.peek();
```

- **整体作用**：查看接收缓冲区中的下一个字节，但不把它取走。
- **参数**：无。
- **返回值**：下一个字节的数值；没有数据时返回 `-1`。
- **记忆**：`peek()` 是“看一眼”，`read()` 是“拿出来”。
- **常见错误**：以为 `peek()` 会让缓冲区减少一个字节；实际上不会。

### 5.4 `Serial.read()`

英文：`read` = 读取。

```cpp
int receivedByte = Serial.read();
```

- **整体作用**：读取并取走接收缓冲区中的下一个字节。
- **参数**：无。
- **返回值**：读到的字节数值；没有数据时返回 `-1`，所以返回类型是 `int`。
- **正确顺序**：先用 `available()` 判断，再用 `read()` 读取。
- **常见错误**：没有数据时直接读取；或者把一次 `read()` 误认为能读完整字符串或完整数据帧。

### 5.5 `Serial.write(value)`

英文：`write` = 写入；在串口中可以理解为“发送原始字节”。

```cpp
Serial.write(0x55);
```

- **整体作用**：发送一个原始字节。
- **参数 `value`**：要发送的字节值，范围通常为 `0x00～0xFF`。
- **返回值**：成功交给发送缓冲区的字节数；普通课堂程序可以不接收。

对比：

```cpp
Serial.print(65);  // 发送文字字符 '6' 和 '5'，共 2 字节
Serial.write(65);  // 发送原始值 65，共 1 字节；文本显示时可能看到 A
```

### 5.6 `Serial.write(buffer, size)`

```cpp
Serial.write(frame, FRAME_SIZE);
```

- **整体作用**：连续发送一个字节数组中的多个原始字节。
- **参数 `buffer`**：字节数组的起始位置；示例中的 `frame` 保存完整数据帧。
- **参数 `size`**：要发送多少个字节；示例中的 `FRAME_SIZE` 为 6。
- **返回值**：成功交给发送缓冲区的字节数。
- **本课用途**：一次发送 `55 05 CMD DATA CHECKSUM FF`。
- **常见错误**：把第二个参数写成数组最后一个下标。6 字节数组最后下标是 5，但发送长度仍应写 6。

### 5.7 `Serial.print(value)`

英文：`print` = 打印、输出。

```cpp
Serial.print("value = ");
Serial.print(123);
```

- **整体作用**：把数据转换成便于人阅读的文字后发送，不自动换行。
- **参数 `value`**：要输出的文字、字符、整数、小数或变量。
- **返回值**：发送的字符数量；课堂中通常不接收。
- **适用场景**：串口监视器调试信息。
- **不适用场景**：正式二进制数据帧。

带进制参数：

```cpp
Serial.print(255, DEC);  // 255
Serial.print(255, HEX);  // FF
Serial.print(255, BIN);  // 11111111
```

- **第 1 个参数**：要输出的数值。
- **第 2 个参数**：显示进制；`DEC` 十进制、`HEX` 十六进制、`BIN` 二进制。

### 5.8 `Serial.println(value)`

英文拆分：`print + line` = 打印一行。

```cpp
Serial.println("finished");
```

- **整体作用**：先输出参数内容，再发送换行。
- **参数 `value`**：要输出的内容；也可以不写参数，只发送换行。
- **返回值**：发送的字符数量；课堂中通常不接收。
- **与 `print()` 的区别**：`print()` 不换行，`println()` 自动换行。

### 5.9 `Serial.readStringUntil(terminator)`

英文拆分：`read + String + Until` = 读取 + 字符串 + 直到。

```cpp
String message = Serial.readStringUntil('\n');
```

- **整体作用**：连续读取字符，直到遇到指定结束符或发生超时。
- **参数 `terminator`**：终止字符。`'\n'` 表示遇到换行符就结束。
- **返回值**：已经读到的 `String` 字符串；终止字符本身不放入结果。
- **本课用途**：读取串口监视器发送的一整行文字命令。
- **常见错误**：串口监视器没有发送 `\n`，函数只能等待到超时才返回。
- **补充**：如果发送端使用 `\r\n`，结果末尾可能还留有 `\r`，所以后面通常调用 `trim()`。

### 5.10 `Serial.setTimeout(timeMs)`

英文拆分：`set + timeout` = 设置 + 超时时间。

```cpp
Serial.setTimeout(100);
```

- **整体作用**：设置某些读取函数最长等待多长时间。
- **参数 `timeMs`**：等待时间，单位为毫秒。`100` 表示最多等待 100 ms。
- **返回值**：无。
- **会影响的函数**：`readStringUntil()`、`readString()`、`readBytes()`、`parseInt()` 等。
- **常见错误**：误以为它会改变波特率；它只改变最长等待时间。

### 5.11 `Serial.printf(format, ...)`

英文拆分：`print + formatted` = 按格式输出。

```cpp
Serial.printf("指令 0x%02X，数据 0x%02X\n", command, data);
```

- **整体作用**：按照格式字符串把多个变量组合后输出。
- **参数 `format`**：格式模板，例如 `"0x%02X"`。
- **后续参数 `...`**：依次填入格式模板的变量，例如 `command`、`data`。
- **返回值**：输出的字符数量。
- **常用格式**：`%d` 十进制整数；`%X` 十六进制；`%02X` 两位大写十六进制，不足两位补 0；`\n` 换行。
- **注意**：初学阶段优先掌握 `print()` 和 `println()`。

### 5.12 `Serial.flush()`

英文：`flush` = 冲刷、排空。

```cpp
Serial.flush();
```

- **整体作用**：等待已经放入发送缓冲区的数据发送完毕。
- **参数**：无。
- **返回值**：无。
- **重要误区**：它通常不是“清空接收缓冲区”。

## 6. 字符串函数详解

### 6.1 `message.trim()`

英文：`trim` = 修剪。

```cpp
message.trim();
```

- **整体作用**：删除字符串两端的空格、回车和换行等空白字符。
- **参数**：无。
- **返回值**：无；它直接修改原来的 `message`。
- **本课用途**：清除串口监视器发送的 `\r`，让 `message == "hello"` 能正确比较。

### 6.2 `message.length()`

英文：`length` = 长度。

```cpp
if (message.length() == 0) {
  return;
}
```

- **整体作用**：取得字符串当前长度。
- **参数**：无。
- **返回值**：字符串中的字符数量。
- **本课用途**：长度为 0 时说明没有有效命令。

### 6.3 `message.startsWith(prefix)`

英文拆分：`starts + with` = 以……开始。

```cpp
message.startsWith("led ")
```

- **整体作用**：判断字符串是否以指定内容开头。
- **参数 `prefix`**：要检查的开头文字；示例为 `"led "`。
- **返回值**：`true` 表示是，`false` 表示不是。
- **本课用途**：识别 `led 255` 这一类带参数命令。

### 6.4 `message.substring(from)`

英文拆分：`sub + string` = 字符串的一部分。

```cpp
String numberText = message.substring(4);
```

- **整体作用**：从指定下标开始，截取到字符串末尾。
- **参数 `from`**：开始下标；下标从 0 开始。`substring(4)` 会跳过 `"led "` 的 4 个字符。
- **返回值**：截取出的新字符串。

另一种写法：

```cpp
message.substring(from, to)
```

- **参数 `from`**：开始下标，包含这个位置。
- **参数 `to`**：结束下标，不包含这个位置。

### 6.5 `numberText.toInt()`

英文拆分：`to + Int` = 转换成整数。

```cpp
int value = message.substring(4).toInt();
```

- **整体作用**：把字符串开头的数字文字转换为整数。
- **参数**：无。
- **返回值**：转换后的整数；无法转换时通常得到 0。
- **常见误区**：无法转换和真正输入 `0` 都可能得到 0，正式协议还应额外检查输入是否合法。

## 7. 本课自定义数据帧函数

这些不是 Arduino 自带函数，而是本仓库为了课堂协议编写的函数。

### 7.1 `calculateChecksum(command, data)`

英文拆分：`calculate + check + sum` = 计算 + 检查 + 总和。

```cpp
byte checksum = calculateChecksum(command, data);
```

- **整体作用**：计算本协议的 8 位加法校验和。
- **参数 `command`**：指令类型字节。
- **参数 `data`**：指令数据字节。
- **返回值**：`FRAME_LENGTH + command + data` 的低 8 位结果。
- **注意**：帧头和帧尾不参加计算。

### 7.2 `sendFrame(command, data)`

英文拆分：`send + frame` = 发送 + 数据帧。

```cpp
sendFrame(0x81, data);
```

- **整体作用**：自动填写帧头、长度、校验和帧尾，并发送完整 6 字节数据帧。
- **参数 `command`**：要发送的指令类型或应答类型。
- **参数 `data`**：与指令一起发送的数据字节。
- **返回值**：无。
- **完整结果**：`55 05 command data checksum FF`。

### 7.3 `readFrame()`

英文拆分：`read + frame` = 读取 + 数据帧。

```cpp
if (readFrame()) {
  // 只有完整合法帧才会进入这里
}
```

- **整体作用**：寻找帧头，读取完整 6 字节，并检查长度、帧尾和校验和。
- **参数**：无；它直接从 `Serial` 接收缓冲区读取。
- **返回值**：`true` 表示收到合法帧；`false` 表示暂时没有合法帧。
- **重要规则**：返回 `true` 后才能执行外设动作。

### 7.4 `getFrameCommand()`

英文拆分：`get + frame + command` = 取得 + 数据帧 + 指令。

```cpp
byte command = getFrameCommand();
```

- **整体作用**：取得上一条合法数据帧中的指令类型。
- **参数**：无。
- **返回值**：一个 `byte` 类型的指令字节。
- **使用条件**：应在 `readFrame()` 返回 `true` 后调用。

### 7.5 `getFrameData()`

```cpp
byte data = getFrameData();
```

- **整体作用**：取得上一条合法数据帧中的指令数据。
- **参数**：无。
- **返回值**：一个 `byte` 类型的数据字节。
- **使用条件**：应在 `readFrame()` 返回 `true` 后调用。

### 7.6 `sendSoftFrame(command, data)`

```cpp
sendSoftFrame(CMD_PING, 0x00);
```

- **整体作用**：通过 `SoftSerial` 向另一块开发板发送完整数据帧。
- **参数 `command`**：指令类型。
- **参数 `data`**：指令数据。
- **返回值**：无。
- **与 `sendFrame()` 的区别**：协议相同，使用的串口对象不同。

### 7.7 `readSoftFrame()`

```cpp
if (readSoftFrame()) {
  // 处理另一块开发板发来的合法帧
}
```

- **整体作用**：从 `SoftSerial` 接收并校验一条双板通信数据帧。
- **参数**：无。
- **返回值**：合法帧返回 `true`，否则返回 `false`。

## 8. 软串口对象和构造参数

```cpp
SoftwareSerial SoftSerial(PIN_UART_RX, PIN_UART_TX);
```

| 部分 | 含义 |
|---|---|
| `SoftwareSerial` | 类名，表示软件模拟串口 |
| `SoftSerial` | 自己创建的对象名，意思是“软串口” |
| 第 1 个参数 `PIN_UART_RX` | 本开发板用于接收的 GPIO 引脚 |
| 第 2 个参数 `PIN_UART_TX` | 本开发板用于发送的 GPIO 引脚 |

本仓库使用：

```cpp
SoftwareSerial SoftSerial(42, 41);
```

因此 GPIO 42 是本板 RX，GPIO 41 是本板 TX。接线时本板 TX 要接对方 RX。

## 12. 五组最容易混淆的内容

### 12.1 `print()` 和 `write()`

```text
print = 把内容变成人能看的文字再发送
write = 发送字节本身
```

正式 HEX 数据帧使用 `write()`。

### 12.2 `peek()` 和 `read()`

```text
peek = 看，但不拿走
read = 读，并拿走
```

### 12.3 `available()` 和 `read()`

```text
available = 先问“有多少字节”
read = 再把一个字节取出来
```

### 12.4 `length` 和 `size`

- `FRAME_LENGTH = 0x05`：协议中的长度字段，表示帧头后还有 5 字节。
- `FRAME_SIZE = 6`：整个数组实际有 6 字节。

### 12.5 `Serial` 和 `SoftSerial`

- `Serial`：本课主要连接电脑，用于调试，波特率 `115200`。
- `SoftSerial`：本课用于两块开发板通信，波特率 `9600`。

## 14. 一页速记表

```text
UART 原理：TX 接对方 RX，RX 接对方 TX，必须共地；两端波特率和格式一致。

8N1：8 个数据位、No parity（无校验）、1 个停止位。

固定帧：55 05 CMD DATA CHECKSUM FF
校验和：LENGTH + CMD + DATA，只保留低 8 位。

begin(波特率)                 启动串口
available()                   返回待读字节数
peek()                        看一个字节但不取走
read()                        读取并取走一个字节
write(字节)                   发送原始字节
write(数组, 数量)             发送多个原始字节
print(内容)                   输出文字，不换行
println(内容)                 输出文字并换行
readStringUntil(结束符)       读取到结束符或超时
setTimeout(毫秒)              设置最长等待时间
trim()                        去掉两端空白、回车和换行
readFrame()                   接收并校验完整帧
sendFrame(指令, 数据)         组成并发送完整帧
getFrameCommand()             取得合法帧的指令
getFrameData()                取得合法帧的数据
calculateChecksum(指令, 数据) 计算校验和
```
