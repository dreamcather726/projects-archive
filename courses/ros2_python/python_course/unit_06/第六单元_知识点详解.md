# 第六单元知识点详解

## 从 Python 程序过渡到 ROS 2 节点

本单元将普通 Python 类改造成 ROS 2 节点，完成定时日志、状态发布和状态订阅。实验统一采用 Ubuntu 24.04 与 ROS 2 Jazzy。

配套代码：[完整功能包](ros2_ws/src/robot_status_py) 与 [普通 Python 回调模拟](simulation/callback_simulation.py)。构建、运行和多终端实验见第 16～19 节，课后作业附在最后。

各节先解释概念，再用“在 ROS 2 中的作用”说明它在本单元实验中负责什么。可以带着一条主线阅读：准备环境 → 创建节点 → 保存状态 → 定时生成消息 → 发布消息 → 订阅并处理消息。

参考资料：

- [ROS 2 Jazzy：开发 ROS 2 功能包](https://docs.ros.org/en/jazzy/How-To-Guides/Developing-a-ROS-2-Package.html)
- [ROS 2 Jazzy 官方 Python 发布者示例](https://github.com/ros2/examples/blob/jazzy/rclpy/topics/minimal_publisher/examples_rclpy_minimal_publisher/publisher_member_function.py)
- [ROS 2 Jazzy 官方 Python 订阅者示例](https://github.com/ros2/examples/blob/jazzy/rclpy/topics/minimal_subscriber/examples_rclpy_minimal_subscriber/subscriber_member_function.py)

## 1. 环境与工作空间

### 1.1 环境约定

**运行环境是程序运行时所依赖的系统、Python 解释器、库和路径设置。** 安装软件提供了所需文件，加载环境则让当前终端能够找到它们。

**在 ROS 2 中的作用：** 让终端能使用 `ros2` 命令，让 Python 能导入 `rclpy` 和消息类型，为运行节点做好准备。

```text
Ubuntu 24.04
ROS 2 Jazzy
ROS 2 安装对应的系统 Python
```

开始实验前，应已安装 `colcon`，并具备 `rclpy`、`std_msgs` 依赖。

加载 ROS 2：

```bash
source /opt/ros/jazzy/setup.bash
```

每个新终端都要重新加载。使用预编译 ROS 2 软件包时，Python 解释器需要与 ROS 2 构建时使用的解释器兼容，因此不建议在本实验中混用 Conda Python。

### 1.2 工作空间

**工作空间是集中存放和构建 ROS 2 功能包的目录。** 可以把它理解成整个机器人软件项目的工作文件夹，其中可以包含多个功能包。

**在 ROS 2 中的作用：** 把节点源码、安装结果和构建日志按用途组织起来，便于开发、构建和查找问题。本单元使用 `ros2_ws` 作为工作空间。

```text
ros2_ws/
├── src/       源码
├── build/     构建中间文件
├── install/   安装结果和环境脚本
└── log/       构建日志
```

`build`、`install`、`log` 由 `colcon build` 生成。

## 2. ROS 2 节点

节点是 ROS 2 图中的基本参与者。一个节点通常负责一个相对清晰的任务，可以创建发布者、订阅者、定时器、服务和动作等实体。

“ROS 2 图”可以先理解为运行中的节点及它们之间的通信关系。把不同职责交给不同节点，就像让不同工作人员分别负责采集、计算和显示。

**在 ROS 2 中的作用：** 将机器人功能拆成可以协作的部分。本单元让一个节点发送状态，另一个节点接收并显示状态。

本单元：

```text
robot_status_publisher  → 发布状态
robot_status_subscriber → 接收状态
```

节点是程序设计单位，不一定等同于一个完整机器人，也不一定永远对应一个独立进程。

## 3. rclpy 与 Node

### 3.1 rclpy

`rclpy` 是 ROS 2 的 Python 客户端库，提供初始化、节点、通信和执行器等接口。

**在 ROS 2 中的作用：** 让 Python 程序能够调用 ROS 2 的功能，例如初始化通信环境、创建节点和处理回调。

```python
import rclpy
```

### 3.2 Node

**`Node` 是 `rclpy` 提供的节点基础类，可以理解为已经准备好常用节点功能的类。**

**在 ROS 2 中的作用：** 自己编写的节点类继承 `Node` 后，就可以使用它提供的定时器、发布者、订阅者和日志方法。

```python
from rclpy.node import Node
```

常见成员方法包括：

```text
create_timer()
create_publisher()
create_subscription()
get_logger()
destroy_node()
```

### 3.3 继承 Node

```python
class RobotStatusNode(Node):
    def __init__(self):
        super().__init__("robot_status_node")
```

`RobotStatusNode` 是 `Node` 的子类，因此可以使用父类提供的节点功能。

## 4. `super().__init__()`

**在本单元的继承关系中，`super().__init__()` 用来调用父类 `Node` 的初始化方法。** 可以理解为先把节点需要的基础部分准备好，再添加自己的状态和处理逻辑。

**在 ROS 2 中的作用：** 初始化当前节点并设置它的名字，使后续的 `create_timer()` 等节点方法能够正常工作。

```python
super().__init__("robot_status_node")
```

作用：

1. 调用 `Node` 的初始化方法。
2. 创建底层节点资源。
3. 设置节点名称。
4. 为后续创建发布者、订阅者和定时器做准备。

本例子类重写了 `__init__`，需要在其中调用父类初始化；只写上 `(Node)` 不能代替这一步。漏掉该调用，后续节点 API 无法正常使用。

## 5. 节点状态与实例属性

**节点状态是节点需要记住的数据；实例属性是把这些数据保存在当前节点对象上的方式。** 例如，当前电量、速度和已接收消息的数量都可以成为节点状态。

**在 ROS 2 中的作用：** 让一次回调保存的结果能够在后续回调中继续使用。例如，订阅回调更新电量，定时器回调读取最新电量并输出日志。

```python
self.robot_name = "robot_01"
self.battery_percent = 85
self.speed_mps = 0.30
```

这些实例属性属于当前节点对象。只要节点对象仍在运行，多个回调就可以通过 `self` 访问同一组状态。

```python
def timer_callback(self):
    self.battery_percent -= 1
```

下一次调用同一方法时，可以看到更新后的电量。

## 6. 日志

**日志是程序运行时主动记录的信息，用来说明正在做什么、得到了什么结果或出现了什么问题。** 日志级别用于区分普通信息和不同程度的问题。

**在 ROS 2 中的作用：** 观察节点是否启动、回调是否执行、接收到的数据是什么，帮助定位程序在哪一步出现问题。

```python
self.get_logger().info("节点已启动")
```

常见日志级别：

| 方法 | 用途 |
| --- | --- |
| `debug()` | 调试细节 |
| `info()` | 正常运行信息 |
| `warning()` | 警告情况 |
| `error()` | 错误情况 |
| `fatal()` | 严重错误 |

与普通 `print()` 相比，ROS 2 日志包含节点名称、时间和级别，并能配合日志配置使用。

## 7. 定时器

**定时器是按设定周期让某个回调准备执行的机制。** 可以把它理解成周期性提醒：时间到了，交给执行器安排对应工作。

**在 ROS 2 中的作用：** 周期性输出日志、采集数据或发布状态。本单元设置约每秒触发一次回调，在回调里读取并输出机器人状态。

### 7.1 创建定时器

```python
self.timer = self.create_timer(1.0, self.timer_callback)
```

- 第一个参数是周期，单位秒。
- 第二个参数是回调方法本身。
- 返回值是定时器对象，保存在实例属性中。

### 7.2 定时器回调

```python
def timer_callback(self):
    self.get_logger().info("定时器触发")
```

创建定时器不会在当前语句中直接调用回调。执行器检测到定时器准备好后才会调度回调。

### 7.3 周期不是硬实时保证

设置 `1.0` 表示定时器目标周期约为 1 秒。操作系统调度、其他回调和程序负载可能带来延迟。普通 ROS 2 Python 节点不应把该数值理解为严格硬实时保证。

## 8. 初始化、spin 与关闭

**这三个步骤分别负责准备运行、处理事件和结束清理。** 其中，“上下文”可以先理解为保存一组 ROS 2 通信资源及其运行状态的对象。

**在 ROS 2 中的作用：** `rclpy.init()` 为创建节点做准备，`rclpy.spin()` 让执行器持续处理节点的回调，结束时销毁节点并关闭上下文，释放使用的资源。

### 8.1 rclpy.init

```python
rclpy.init(args=args)
```

初始化 ROS 2 通信上下文。节点创建应发生在初始化之后。

### 8.2 rclpy.spin

```python
rclpy.spin(node)
```

`spin` 把节点交给执行器处理，并阻塞当前线程，直到上下文关闭或运行被中断。执行器持续等待并执行准备好的回调。

### 8.3 清理

```python
node.destroy_node()
rclpy.shutdown()
```

- `destroy_node()` 销毁节点拥有的 ROS 资源。
- `shutdown()` 关闭 ROS 2 上下文。

常用结构：

```python
try:
    rclpy.spin(node)
except KeyboardInterrupt:
    pass
finally:
    node.destroy_node()
    rclpy.shutdown()
```

## 9. 执行器与回调

**执行器是负责等待并调度回调的对象；回调是具体完成工作的函数或方法。** 可以把执行器理解成安排任务的人，把回调理解成某项任务的处理步骤。

**在 ROS 2 中的作用：** 定时器到期或订阅消息准备好时，由执行器调用相应回调。因此，写好回调后，还需要让执行器运行，节点才能持续处理这些事件。

### 9.1 执行器的作用

执行器负责：

1. 等待定时器、消息等工作准备好。
2. 选择准备执行的回调。
3. 调用回调函数。
4. 回调结束后继续等待。

Jazzy 的 `rclpy.spin(node)` 在未提供执行器时使用全局执行器；默认全局执行器是 `SingleThreadedExecutor`。这一行为可见 [`rclpy` 的官方实现](https://github.com/ros2/rclpy/blob/jazzy/rclpy/rclpy/__init__.py)。

### 9.2 长回调的影响

```python
def timer_callback(self):
    time.sleep(5)
```

在默认单线程执行方式下，这个回调占用执行线程时，其他回调无法在同一线程中执行，可能造成消息和定时器延迟。

入门阶段建议：

- 回调只做必要处理。
- 避免长时间循环和阻塞等待。
- 复杂并发、回调组和多线程执行器留到后续课程。

## 10. 消息类型与消息对象

**消息类型规定一条消息有哪些字段、每个字段保存什么类型的数据；消息对象是按这个规定创建的一条具体数据。** 可以把消息类型理解成空白表格的格式，把消息对象理解成已经填写内容的一张表格。

**在 ROS 2 中的作用：** 让发送方和接收方按照约定的格式组织、读取数据。本单元使用 `String` 类型，把一条机器人状态文本填入消息对象的 `data` 字段。

### 10.1 导入消息类型

```python
from std_msgs.msg import String
```

`String` 是消息类型，不是普通 Python `str`。

### 10.2 创建消息对象

```python
message = String()
message.data = "robot_01|85|0.30"
```

`data` 是 `std_msgs/msg/String` 定义的字段。赋值时应使用字符串。

创建和填写消息并不会自动发送，必须调用发布者的 `publish()`。

### 10.3 为什么先使用 String

它便于把前面课程的状态字符串直接接入 ROS 2。真实项目通常应根据数据语义选择标准消息或自定义接口，而不是把所有结构化数据都塞进一个字符串。

## 11. 发布者

**发布者是节点中负责向指定话题发送消息的对象。** 话题是有名称的数据通信通道，可以先理解为节点之间约定的数据频道。

**在 ROS 2 中的作用：** 将当前节点得到的结果提供给其他节点。例如，状态发布节点通过 `robot_status` 话题发送电量和速度信息。

### 11.1 创建发布者

```python
self.publisher = self.create_publisher(
    String,
    "robot_status",
    10,
)
```

参数：

1. 消息类型 `String`。
2. 相对话题名称 `robot_status`。
3. QoS 队列深度 `10` 的简写。

QoS 是通信质量策略，用来约定消息如何传递和保留。这里的深度 `10` 表示采用保留最近消息的历史策略、深度设为 10，不是只允许总共发送 10 条消息。详见 [`create_publisher()` 的官方接口说明](https://github.com/ros2/rclpy/blob/jazzy/rclpy/rclpy/node.py)。

### 11.2 发布消息

```python
self.publisher.publish(message)
```

发布者只能发布匹配的消息类型。话题数据由 ROS 2 中间件传给兼容的订阅者。

### 11.3 话题名称

代码中的相对名称 `robot_status` 通常展开成 `/robot_status`。命名空间和重映射会影响最终名称，后续课程再展开。

## 12. 订阅者

**订阅者是节点中负责从指定话题接收消息的对象，并关联一个处理消息的回调。** 可以理解为订阅某个数据频道，等新数据到达后交给自己的处理函数。

**在 ROS 2 中的作用：** 使用其他节点提供的数据。例如，状态订阅节点接收 `robot_status` 消息，在回调中读取 `message.data` 并显示内容。

### 12.1 创建订阅者

```python
self.subscription = self.create_subscription(
    String,
    "robot_status",
    self.listener_callback,
    10,
)
```

参数：

1. 消息类型。
2. 话题名称。
3. 订阅回调。
4. QoS 队列深度。

### 12.2 订阅回调

```python
def listener_callback(self, message: String) -> None:
    self.get_logger().info(message.data)
```

收到消息后，执行器调度该回调，并把消息对象作为参数传入。

### 12.3 通信匹配

发布者和订阅者至少需要：

- 相同的最终话题名称。
- 相同的消息类型。
- 兼容的 QoS 配置。

本单元只使用相同的队列深度简写，完整 QoS 留到后续课程。

## 13. `ament_python` 功能包

**ROS 2 功能包是组织和分发一组相关代码、配置及依赖说明的单位；`ament_python` 是适用于 Python 功能包的构建类型。** 一个功能包可以提供多个可执行入口，不要求一个包只对应一个节点。

**在 ROS 2 中的作用：** 把本单元的定时日志、发布和订阅代码一起交给构建工具安装，再通过 `ros2 run` 启动对应程序。

### 13.1 创建命令

```bash
ros2 pkg create robot_status_py \
  --build-type ament_python \
  --license Apache-2.0 \
  --dependencies rclpy std_msgs
```

应在工作空间的 `src` 目录中创建功能包。

### 13.2 目录结构

```text
robot_status_py/
├── package.xml
├── setup.py
├── setup.cfg
├── resource/
│   └── robot_status_py
└── robot_status_py/
    ├── __init__.py
    ├── timer_logger.py
    ├── status_publisher.py
    └── status_subscriber.py
```

外层目录是 ROS 2 功能包根目录，内层同名目录是 Python 包。

## 14. package.xml

**`package.xml` 是 ROS 2 功能包的说明文件，记录名称、版本、维护者、许可证和依赖。** 依赖是这个功能包构建或运行时需要的其他软件包。

**在 ROS 2 中的作用：** 告诉工具这个包需要哪些组件。例如，本单元用 `rclpy` 编写节点、用 `std_msgs` 提供消息类型，因此需要声明这两个依赖。

```xml
<buildtool_depend>ament_python</buildtool_depend>
<depend>rclpy</depend>
<depend>std_msgs</depend>
```

`buildtool_depend` 声明构建工具依赖，`depend` 声明相关包依赖；增加代码中使用的 ROS 2 包时，应同步检查这里的声明。

## 15. setup.py 与 setup.cfg

**`setup.py` 和 `setup.cfg` 是本单元 Python 包的打包安装配置文件。** 前者通过 Python 代码描述包内容和可执行入口，后者在本例中指定入口脚本的安装位置。

**在 ROS 2 中的作用：** 把节点的 Python 函数安装成可以启动的程序，让 `ros2 run robot_status_py timer_logger` 找到并调用对应的 `main()`。

### 15.1 console_scripts

`console_scripts` 是可执行入口的配置项，把一个启动名称对应到“某个 Python 模块中的某个函数”。

```python
entry_points={
    "console_scripts": [
        "timer_logger = robot_status_py.timer_logger:main",
    ],
}
```

含义：

```text
ros2 run 使用的名称 = Python包.模块:函数
```

### 15.2 setup.cfg

```ini
[develop]
script_dir=$base/lib/robot_status_py
[install]
install_scripts=$base/lib/robot_status_py
```

它让可执行脚本安装到 `ros2 run` 能找到的位置。

### 15.3 修改配置后重新构建

增加或修改 `console_scripts`、依赖和包配置后，需要重新运行 `colcon build` 并重新加载工作空间。

## 16. 构建与加载

**构建是按功能包配置整理和安装代码等文件；加载是把安装结果的相关路径加入当前终端环境。** `colcon` 是本单元使用的构建工具，`source` 则是在当前 Bash 终端中执行环境脚本的命令。

**在 ROS 2 中的作用：** 让自己编写的功能包能够被 ROS 2 工具找到，并使用其中的可执行入口。只把源码放进 `src`，还没有完成这些安装和环境设置步骤。

以下路径中的 `~/course/ros2_python` 请替换为课程材料在自己电脑中的实际路径。先加载 ROS 2 环境，再构建本单元的功能包：

```bash
source /opt/ros/jazzy/setup.bash
cd ~/course/ros2_python/unit_06/ros2_ws
colcon build --symlink-install --packages-select robot_status_py
source install/setup.bash
```

- `--packages-select` 只构建指定包。
- `--symlink-install` 便于开发 Python 包。
- `source install/setup.bash` 把当前工作空间加入环境。

使用 `--symlink-install` 后，修改已有 Python 节点文件通常可在重启节点后生效；修改 `setup.py`、`package.xml` 等包配置后，需要重新构建并加载环境。

新终端需要加载两层环境：

```bash
source /opt/ros/jazzy/setup.bash
source ~/course/ros2_python/unit_06/ros2_ws/install/setup.bash
```

后一层称为 overlay，建立在 ROS 2 安装环境之上。

## 17. 运行与观察

**命令行工具是通过终端输入命令来启动程序、查询信息的工具。** `ros2 run` 负责启动功能包中的可执行程序，`ros2 node` 和 `ros2 topic` 的相关命令用于查看运行情况。

**在 ROS 2 中的作用：** 验证程序是否已经形成预期的节点和通信关系，例如确认节点存在、话题名称正确，以及是否收到了状态消息。

运行节点：

```bash
ros2 run robot_status_py timer_logger
```

节点每隔约 1 秒输出一次模拟状态，按 `Ctrl+C` 结束。检查节点、话题时另开终端，并按上一节加载环境。

查看节点：

```bash
ros2 node list
```

查看话题和消息：

```bash
ros2 topic list

ros2 topic echo /robot_status
```

`ros2 topic echo` 本身也会作为 ROS 2 图中的参与者订阅话题。

## 18. 多终端实验

**多终端实验是在多个终端中分别启动或观察程序，让它们同时运行。** 一个终端可以显示发布端日志，另一个显示接收端日志。

**在 ROS 2 中的作用：** 同时运行发布节点和订阅节点，观察一条状态从发送到接收的完整过程，再用第三个终端查询话题信息。

发布者和订阅者需要同时运行。每个终端先加载相同的 ROS 2 安装和工作空间：

```bash
source /opt/ros/jazzy/setup.bash
source ~/course/ros2_python/unit_06/ros2_ws/install/setup.bash
```

终端一运行发布者：

```bash
ros2 run robot_status_py status_publisher
```

终端二运行订阅者：

```bash
ros2 run robot_status_py status_subscriber
```

终端三观察话题：

```bash
ros2 topic list
ros2 topic info /robot_status
ros2 topic echo /robot_status
```

分别在运行程序的终端按 `Ctrl+C` 结束。只在第一个终端执行 `source`，不会自动影响其他终端。

| 可执行入口 | 功能包内的 Python 文件 | 内容 |
| --- | --- | --- |
| `timer_logger` | `robot_status_py/timer_logger.py` | 定时输出节点日志 |
| `status_publisher` | `robot_status_py/status_publisher.py` | 发布 String 消息 |
| `status_subscriber` | `robot_status_py/status_subscriber.py` | 订阅并显示 String 消息 |

## 19. 没有 ROS 2 环境时

**回调模拟是用普通 Python 代码模仿“保存一个函数，稍后调用它”的过程。** 它帮助理解程序调用关系，不需要先安装 ROS 2。

**在 ROS 2 中的作用：** 为理解定时器回调和实例状态做准备。完成模拟后，还需要在 ROS 2 环境中继续验证节点、真实定时器和话题通信。

在 `unit_06` 文件夹中运行配套模拟程序：

```powershell
python simulation/callback_simulation.py
```

Linux 或 macOS 将 `python` 换成 `python3`。

普通 Python 模拟：

```python
class TimerSimulator:
    def __init__(self, callback):
        self.callback = callback

    def spin_three_times(self):
        for _ in range(3):
            self.callback()
```

该模拟只表示“保存回调并在循环中调用”，不包含：

- ROS 2 节点图。
- 中间件通信。
- 真实定时器等待。
- ROS 2 执行器。
- 话题与消息类型检查。

## 20. Python 关键字与 ROS 2 API

**关键字是 Python 语言规定的语法词；API 是库或工具提供给程序使用的接口。** 例如，`class` 用来定义类，`create_publisher()` 则是 `Node` 提供的方法。

**在 ROS 2 中的作用：** 遇到不认识的写法时，可以判断应该查 Python 语法，还是查 `rclpy` 的接口说明，逐步学会独立阅读节点代码。

本单元出现的 Python 关键字：

| 关键字 | 作用 |
| --- | --- |
| `class` | 定义节点类 |
| `def` | 定义初始化方法、回调和入口函数 |
| `from` / `import` | 导入 ROS 2 模块和消息类型 |
| `try` / `except` / `finally` | 处理终止并清理资源 |
| `pass` | 捕获键盘中断后不执行额外操作 |

以下是库接口、Python 内置名称或常用标识符，不是关键字；其中 `self` 是当前对象参数的惯用名称：

```text

Node
create_timer
create_publisher
create_subscription
publish
get_logger
destroy_node
super
self
```

理解“语言关键字”和“库提供的 API”之间的区别，有助于查阅正确文档。

## 21. 常见错误速查

| 现象 | 常见原因 | 检查方式 |
| --- | --- | --- |
| `ros2: command not found` | 未加载 ROS 2 | `source /opt/ros/jazzy/setup.bash` |
| `Package not found` | 未构建或未加载 overlay | 构建并加载 `install/setup.bash` |
| `No executable found` | 入口未配置或未重新构建 | 检查 `setup.py` |
| `ModuleNotFoundError: rclpy` | Python 环境不匹配或未加载 ROS | 退出 Conda，加载 ROS 环境 |
| 节点名未出现 | 节点未运行或已退出 | 查看运行终端和 `ros2 node list` |
| 订阅者没有输出 | 名称、类型或 QoS 不匹配 | 使用 `ros2 topic info` |
| 回调创建时就执行 | 写成 `self.callback()` | 传入 `self.callback` |
| 修改 Python 后仍是旧行为 | 使用了其他工作空间 | 检查加载顺序和包路径 |
| 节点周期明显延迟 | 回调耗时或阻塞 | 缩短回调工作 |
| Ctrl+C 后出现清理错误 | 上下文已关闭或清理顺序不当 | 按示例集中清理流程 |
