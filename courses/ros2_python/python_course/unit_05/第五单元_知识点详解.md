# 第五单元知识点详解

## 面向对象编程与机器人功能封装

面向对象编程把相关的数据和操作组织到对象中。ROS 2 Python 节点通常使用继承 `Node` 的类来编写，因此需要重点理解 `class`、`self`、`__init__` 和 `super()`。

配套代码位于 [experiments](experiments) 文件夹，运行方式见文末的“配套代码与运行”，课后作业附在最后。

本单元会用“在 ROS 2 中的作用”说明各知识点的用途。可以先把“节点”理解成负责某项机器人功能的程序，把“回调方法”理解成收到消息或定时时间到达后执行的方法；具体节点代码会在第六单元学习。

## 1. 类与对象

### 1.1 什么是类

类是一种自定义类型，用来描述对象应该有哪些数据和行为：

```python
class Robot:
    pass
```

- `class` 是定义类的关键字。
- `Robot` 是类名，通常使用大驼峰命名法。
- `:` 后面是类的代码块。
- `pass` 表示暂时没有具体代码。

可以把类想成机器人的设计说明：规定每台机器人需要记录哪些状态、能够执行哪些操作。

**在 ROS 2 中的作用：** 可以用一个类组织某个节点的状态和功能。例如，第六单元的 `RobotStatusNode` 类把状态数据和定时输出状态的方法放在一起。

### 1.2 什么是对象

对象是根据类创建的具体实例：

```python
robot_1 = Robot()
robot_2 = Robot()
```

`robot_1` 和 `robot_2` 是两个不同对象。类是设计说明，对象是实际创建的实例。

**在 ROS 2 中的作用：** 定义节点类后，需要创建节点对象，程序才有具体的节点实例可以使用。创建多个实例时，应把各自的测距值、计数等状态分别保存在各自对象中。

### 1.3 属性和方法

- 属性：对象保存的数据，如名称、电量、速度。
- 方法：对象能够执行的操作，如设置速度、停车、显示状态。

**在 ROS 2 中的作用：** 节点用属性保存最新收到的数据，用方法处理数据或发布消息。例如，属性保存当前电量，定时回调方法读取电量并生成状态信息。

## 2. `__init__` 初始化方法

**`__init__` 是对象创建后自动执行的初始化方法，用来给新对象准备初始数据。** 可以把它理解成新机器人投入使用前的准备步骤，例如登记名称、设置初始速度。

**在 ROS 2 中的作用：** 节点通常在 `__init__` 中完成父类初始化、设置初始状态，并创建发布者、订阅者或定时器。它负责当前 Python 对象的初始化；第六单元的 `rclpy.init()` 则负责初始化 ROS 2 通信所需的上下文，两者作用不同。

### 2.1 基本写法

```python
class Robot:
    def __init__(self, name, battery):
        self.name = name
        self.battery = battery
        self.speed_mps = 0.0
```

创建对象：

```python
robot = Robot("robot_01", 85)
```

Python 创建实例后会调用 `__init__()`，把新对象和实参传入。

### 2.2 `__init__` 不是普通构造表达式

日常教学常把 `__init__` 叫作构造或初始化方法。更准确地说，对象已经由 Python 创建后，`__init__` 负责初始化该对象的状态。

`__init__` 通常不显式返回对象，也不能返回普通非 `None` 值。

### 2.3 双下划线名称

`__init__` 前后都有两个下划线，属于 Python 特殊方法。不要写成：

```text
_init_
init
__int__
```

这些名称不会自动承担初始化作用。

## 3. self

### 3.1 self 表示当前对象

**`self` 表示当前正在使用这个实例方法的对象。** 同一段方法代码被不同对象调用时，`self` 分别指向相应的对象。

**在 ROS 2 中的作用：** 节点方法通过 `self` 访问本节点保存的数据和功能。例如，接收数据的方法更新 `self.speed_mps`，定时回调再读取这个属性输出状态。

```python
class Robot:
    def set_speed(self, speed_mps):
        self.speed_mps = speed_mps
```

调用：

```python
robot.set_speed(0.30)
```

调用时，Python 会把 `robot` 自动作为第一个参数传给方法。概念上接近：

```python
Robot.set_speed(robot, 0.30)
```

### 3.2 self 不是关键字

`self` 只是实例方法第一个参数的通用命名约定，并非 Python 关键字。理论上可以换名字，但不应这样做，否则会降低代码可读性。

### 3.3 为什么属性可以跨方法使用

```python
class Robot:
    def __init__(self):
        self.speed_mps = 0.0

    def set_speed(self, value):
        self.speed_mps = value

    def show_speed(self):
        print(self.speed_mps)
```

三个方法通过 `self` 访问同一对象。`self.speed_mps` 保存在对象中，因此可以跨方法使用。

普通局部变量只在本次方法调用的局部作用域中存在：

```python
def set_speed(self, value):
    temporary_speed = value
```

`temporary_speed` 不会自动成为对象属性。

## 4. 实例属性与类属性

### 4.1 实例属性

**实例属性是保存在某个具体对象中的数据。** 通常使用 `self.name` 形式：

```python
self.name = name
self.battery = battery
self.speed_mps = 0.0
```

不同实例可以有不同值。

**在 ROS 2 中的作用：** 用实例属性保存每个节点自己的最新传感器值、消息计数和定时器对象。例如，将计数保存在 `self.count` 中，可以让不同节点实例分别记录自己的计数。

### 4.2 类属性

**类属性是定义在类上、可供这个类的实例共同读取的数据。** 直接定义在类代码块中：

```python
class Robot:
    category = "mobile_robot"
```

类属性通常表达类级共享信息。可以通过类或实例读取：

```python
Robot.category
robot.category
```

**在 ROS 2 中的作用：** 可以保存同类节点共用的固定说明或默认值，例如设备类别。各节点不断变化的测量记录应保存为实例属性，尤其不要把可变列表作为类属性让多个节点实例意外共用。

### 4.3 实例属性会遮蔽同名类属性

```python
robot.category = "special_robot"
```

这通常会在该实例上创建同名实例属性，而不是修改类属性。其他实例仍可能读到原类属性。

每台机器人不同的名称、电量和速度应使用实例属性，避免意外共享。

## 5. 实例方法

**实例方法是通过具体对象调用、能够读取或修改该对象状态的函数。** 第一个参数通常是 `self`：

```python
class Robot:
    def stop(self):
        self.speed_mps = 0.0

    def show_status(self):
        print(self.name, self.speed_mps)
```

通过对象调用：

```python
robot.stop()
robot.show_status()
```

方法可以读取和修改当前实例属性。

**在 ROS 2 中的作用：** 定时回调、订阅回调通常写成实例方法，这样就能使用节点保存的状态。例如，订阅回调保存新测距值，另一个方法读取这个值生成状态消息。

## 6. 封装

### 6.1 什么是封装

封装是把数据和操作数据的规则组织在一个对象中：

```python
class Robot:
    def set_speed(self, speed_mps):
        if not 0.0 <= speed_mps <= 0.50:
            raise ValueError("速度超出范围")
        self.speed_mps = speed_mps
```

所有调用者通过同一个方法修改速度，可以统一执行范围检查。

**在 ROS 2 中的作用：** 可以把消息处理、数据检查和状态更新组织在节点或辅助对象中。例如，多个回调需要修改目标速度时，都调用统一的检查方法，减少遗漏范围检查的情况。

### 6.2 单下划线约定

```python
self._battery = 85
```

单下划线表示该名称主要供类内部使用。这是开发者约定，不是真正的访问权限限制。

### 6.3 双下划线名称改写

```python
self.__battery = 85
```

双下划线开头会触发名称改写，主要用于避免子类名称冲突，不等同于其他语言中严格的私有成员。初学项目通常使用单下划线配合清晰接口即可。

## 7. 继承

**继承是让一个新类复用已有类提供的属性和方法，并按需要增加功能。** 已有类称为父类，新类称为子类。

**在 ROS 2 中的作用：** 自定义 Python 节点通常继承 `Node`，从而使用它提供的创建定时器、发布者、订阅者和记录日志等功能，再补充自己的机器人业务逻辑。

### 7.1 基本语法

```python
class MobileRobot(Robot):
    pass
```

`MobileRobot` 是子类，`Robot` 是父类。子类可以使用父类提供的属性和方法。

继承表达“是一种”关系：移动机器人是一种机器人。

### 7.2 示例一：直接使用继承来的方法

子类即使只写了 `pass`，它的对象也能使用父类已经提供的方法：

```python
class Robot:
    def __init__(self, name):
        self.name = name
        self.speed_mps = 0.0

    def stop(self):
        self.speed_mps = 0.0
        print(f"{self.name} 已停车")


class MobileRobot(Robot):
    pass


robot = MobileRobot("robot_01")
robot.speed_mps = 0.30
robot.stop()  # MobileRobot 中没写 stop()，实际使用的是 Robot.stop()
print(robot.speed_mps)
```

输出：

```text
robot_01 已停车
0.0
```

这个例子中：

- `MobileRobot` 继承了父类的初始化方法，所以可以接收 `name`。
- `name` 和 `speed_mps` 是父类初始化得到的实例属性。
- `stop()` 也是直接从父类继承来的。
- 继承不会复制出另一份方法代码，而是让 Python 能沿继承关系找到父类的方法。

### 7.3 示例二：子类在父类基础上增加功能

子类既可以复用原有功能，也可以增加自己特有的属性和方法：

```python
class MobileRobot(Robot):
    def __init__(self, name, wheel_count):
        super().__init__(name)
        self.wheel_count = wheel_count

    def check_wheels(self):
        print(f"{self.name} 有 {self.wheel_count} 个轮子")


robot = MobileRobot("robot_02", 4)
robot.check_wheels()  # 子类新增的方法
robot.stop()          # 父类继承的方法
```

可以把这个对象拥有的内容分成两部分：父类提供 `name`、`speed_mps` 和 `stop()`，子类增加 `wheel_count` 和 `check_wheels()`。

### 7.4 `super` 内置函数

```python
class MobileRobot(Robot):
    def __init__(self, name, battery, wheel_count):
        super().__init__(name, battery)
        self.wheel_count = wheel_count
```

`super()` 返回一个用于访问父类实现的代理对象。它是内置函数，不是关键字。

**在 ROS 2 中的作用：** 在节点子类中，`super().__init__("robot_node")` 调用 `Node` 的初始化方法并设置节点名称，为后续使用节点功能做好准备。子类重写 `__init__` 后，需要在其中安排父类的初始化。

### 7.5 为什么调用父类初始化

如果父类 `__init__` 创建：

```python
self.name
self.battery
self.speed_mps
```

子类跳过父类初始化后，这些属性可能不存在，使用时会产生 `AttributeError`。

不要简单地重复复制父类初始化代码；调用 `super().__init__()` 能复用父类逻辑，并在父类修改时保持一致。

对象的初始化顺序可以理解为：

```text
创建 MobileRobot 对象
        ↓
进入 MobileRobot.__init__()
        ↓
super().__init__() 初始化 Robot 部分
        ↓
继续初始化 wheel_count 等子类部分
```

如果删掉 `super().__init__(name, battery)`，之后访问 `self.name`、`self.battery` 或 `self.speed_mps` 时就可能出现 `AttributeError`。

## 8. 方法重写

**方法重写是子类重新定义父类已有的方法，让同一个操作在子类中有自己的实现。** 子类定义与父类同名的方法：

```python
class MobileRobot(Robot):
    def show_status(self):
        super().show_status()
        print(self.wheel_count)
```

调用子类实例的方法时，优先使用子类实现。

重写方法可以：

- 完全替换父类行为。
- 调用父类方法后增加行为。
- 在执行父类方法前进行检查。

方法名称和调用约定应保持合理一致。

下面两个子类对同一个 `move()` 操作给出了不同实现：

```python
class Robot:
    def move(self):
        print("机器人开始移动")


class MobileRobot(Robot):
    def move(self):
        print("移动机器人转动轮子前进")


class AerialRobot(Robot):
    def move(self):
        print("飞行机器人提升旋翼起飞")
```

`MobileRobot.move()` 和 `AerialRobot.move()` 都重写了 `Robot.move()`。如果子类没有重写，才会继续使用父类版本。

重写时也可以保留父类行为，再追加子类行为：

```python
class MobileRobot(Robot):
    def show_status(self):
        super().show_status()               # 先显示父类定义的通用状态
        print(f"轮子数量：{self.wheel_count}")  # 再显示子类特有状态
```

这里的 `super().show_status()` 与 `self.show_status()` 不同。后者会再次找到当前重写的方法，造成不断调用自身；前者明确从父类的实现继续执行。

**在 ROS 2 中的作用：** 为多种机器人编写共用的状态处理类时，子类可以重写状态生成方法，分别补充轮子数量或其他设备信息，再由节点发布结果。本单元先用自己编写的业务方法练习重写。

## 9. 多态的基础理解

**多态是用相同的调用方式操作不同对象，而各对象执行各自的行为。** 简单地说，就是“同一句调用，不同对象有不同表现”。

### 9.1 示例一：继承和方法重写形成多态

继续使用上一节的三个类：

```python
robots = [
    Robot(),
    MobileRobot(),
    AerialRobot(),
]

for robot in robots:
    robot.move()
```

输出：

```text
机器人开始移动
移动机器人转动轮子前进
飞行机器人提升旋翼起飞
```

循环中的代码始终只有一句 `robot.move()`，但 Python 会查看 `robot` 当前实际引用的对象：

- 是 `Robot` 对象，就调用 `Robot.move()`。
- 是 `MobileRobot` 对象，就调用重写后的 `MobileRobot.move()`。
- 是 `AerialRobot` 对象，就调用重写后的 `AerialRobot.move()`。

因此，**继承负责建立类之间的关系，方法重写负责提供不同实现，多态让调用者能够统一使用这些实现。**

### 9.2 示例二：函数不必分别判断机器人类型

可以把统一调用写进函数：

```python
def start_mission(robot):
    print("任务开始")
    robot.move()


start_mission(MobileRobot())
start_mission(AerialRobot())
```

`start_mission()` 只关心传入对象能否执行 `move()`，不需要写成下面这样：

```python
# 不推荐：每增加一种机器人，都要继续增加类型判断
if isinstance(robot, MobileRobot):
    robot.move()
elif isinstance(robot, AerialRobot):
    robot.move()
```

当以后增加 `UnderwaterRobot` 并提供自己的 `move()` 时，`start_mission()` 通常不需要修改。这是多态帮助减少分支判断的直观价值。


**在 ROS 2 中的作用：** 节点可以用相同的方法调用不同的机器人状态对象。例如，统一调用 `show_status()` 时，不同机器人对象各自显示自己的状态，调用处不必分别写一套操作步骤。

## 10. 组合

### 10.1 什么是组合

一个对象把另一个对象保存为属性：

```python
class Robot:
    def __init__(self, name, sensor):
        self.name = name
        self.sensor = sensor
```

机器人拥有一个传感器，这是“拥有一个”关系。

**在 ROS 2 中的作用：** 节点可以把传感器数据处理对象保存为属性，由回调调用它的方法。这样可以把节点通信和具体的数据处理分开组织，便于理解和复用。

### 10.2 组合示例

```python
class DistanceSensor:
    def __init__(self):
        self.distance_m = None

    def update(self, distance_m):
        self.distance_m = distance_m


sensor = DistanceSensor()
robot = Robot("robot_01", sensor)
```

访问组合对象：

```python
robot.sensor.update(0.55)
print(robot.sensor.distance_m)
```

### 10.3 继承与组合

- `MobileRobot` 是一种 `Robot`：使用继承。
- `Robot` 拥有一个 `DistanceSensor`：使用组合。

组合通常比不恰当的继承更灵活。选择时应先判断真实关系。

## 11. property

**`property` 可以让一个方法像普通属性一样被读取，也可以为属性赋值增加检查步骤。** 使用者仍然写 `robot.battery`，类内部则决定如何读取和保存这个值。

**在 ROS 2 中的作用：** 可以在节点使用的机器人状态对象中统一检查电量、速度等属性的赋值。例如，保存电量前检查它是否在 `0～100` 范围内；这是 Python 对象内部的属性接口，不会自动成为 ROS 2 参数。

### 11.1 读取属性

```python
class Robot:
    @property
    def battery(self):
        return self._battery
```

外部像普通属性一样读取：

```python
print(robot.battery)
```

### 11.2 setter

**setter 是属性的“写入入口”。** 当外部代码给 property 属性赋值时，Python 不会直接修改数据，而是自动调用对应的 setter 方法。因此，可以把范围检查、类型检查和数据保存集中写在一个位置。

```python
@battery.setter
def battery(self, value):
    if not 0 <= value <= 100:
        raise ValueError("电量范围错误")
    self._battery = value
```

赋值：

```python
robot.battery = 85
```

这条赋值语句的执行过程可以理解为：

```text
robot.battery = 85
        ↓
自动调用 battery 的 setter
        ↓
value 接收到 85
        ↓
检查数据并保存到 self._battery
```

其中：

- `@battery.setter` 表示下面的方法是 `battery` 属性对应的 setter。
- setter 方法名也必须写成 `battery`，与前面的 property 名称保持一致。
- `self` 表示当前对象，`value` 接收赋值号右侧的数据。
- `robot.battery = 85` 会自动触发 setter，一般不需要手动调用 setter 方法。

setter 常见的工作有三类：

1. **检查数据**：判断类型、范围或格式是否合法。
2. **转换数据**：例如去除字符串两端空格，或把单位转换后再保存。
3. **保存数据**：把处理后的值写入 `_battery` 这样的内部属性。

如果希望错误数据立即暴露，可以抛出异常：

```python
@battery.setter
def battery(self, value):
    if not isinstance(value, (int, float)):
        raise TypeError("电量必须是数值")
    if not 0 <= value <= 100:
        raise ValueError("电量必须在 0～100 之间")
    self._battery = value
```

```python
robot.battery = 80    # 合法，保存 80
robot.battery = 120   # 抛出 ValueError，不会执行保存语句
```

也可以不抛出异常，而是提示后保留原值：

```python
@battery.setter
def battery(self, value):
    if 0 <= value <= 100:
        self._battery = value
    else:
        print("电量超出范围，保留原值")
```

两种处理方式没有绝对的优劣，但同一个项目应该尽量保持统一。需要调用者明确处理错误时，通常使用异常；课堂演示或允许继续运行的简单程序，也可以给出提示并保留原值。

构造方法也可以通过公开属性完成第一次赋值，从而复用同一套检查规则：

```python
class Robot:
    def __init__(self, battery):
        self._battery = 0
        self.battery = battery  # 自动调用 setter

    @property
    def battery(self):
        return self._battery

    @battery.setter
    def battery(self, value):
        if not 0 <= value <= 100:
            raise ValueError("电量范围错误")
        self._battery = value
```

这样，无论是创建对象时传入电量，还是对象创建后重新设置电量，都会经过相同的校验逻辑。

### 11.3 注意递归赋值

setter 内部应该写：

```python
self._battery = value
```

如果写成 `self.battery = value`，会再次调用同一个 setter，造成无限递归。

## 12. staticmethod

静态方法不接收 `self` 或 `cls`，用于概念上属于该类、但不依赖对象或类状态的操作：

```python
class Robot:
    @staticmethod
    def is_valid_speed(speed_mps):
        return 0.0 <= speed_mps <= 0.50
```

调用：

```python
Robot.is_valid_speed(0.30)
```

如果操作与类的概念关系不大，放在普通模块函数中可能更合适。

**在 ROS 2 中的作用：** 可以把与机器人类有关、只依赖传入数据的检查操作写成静态方法。例如，节点处理速度数据时调用 `Robot.is_valid_speed(value)`，无需先创建一个机器人对象来完成检查。

## 13. classmethod

类方法的第一个参数通常命名为 `cls`，表示当前类：

```python
class Robot:
    @classmethod
    def create_default(cls, name):
        return cls(name, 100)
```

调用：

```python
robot = Robot.create_default("robot_01")
```

使用 `cls(...)` 而不是固定写 `Robot(...)`，有利于子类继承这个创建方式。

`cls` 与 `self` 一样，不是关键字，而是通用命名约定。

**在 ROS 2 中的作用：** 可以为节点使用的机器人状态对象提供统一的创建方式。例如，用 `Robot.create_default(name)` 创建具有默认电量的状态对象，减少节点初始化时重复填写相同数据的代码。

## 14. 本单元关键字与特殊名称

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `class` | 关键字 | 定义类 |
| `pass` | 关键字 | 空代码占位 |
| `self` | 参数命名约定 | 表示当前实例 |
| `cls` | 参数命名约定 | 表示当前类 |
| `__init__` | 特殊方法名 | 初始化实例状态 |
| `super` | 内置函数 | 访问父类相关实现 |
| `@property` | 装饰器 | 创建属性读取接口 |
| `@staticmethod` | 装饰器 | 创建静态方法 |
| `@classmethod` | 装饰器 | 创建类方法 |

点号 `.` 是属性访问语法，例如 `robot.name`、`robot.stop()`。它不是关键字。

**在 ROS 2 中的作用：** 阅读节点代码时，可以据此分清类定义、对象状态和方法调用。例如，`self.timer_callback` 表示取出当前对象的回调方法，`self.timer_callback()` 则表示立即调用它。

## 15. 对象生命周期与引用

**对象生命周期是对象从创建、使用到不再需要并可被回收的过程；引用是程序找到并使用某个对象的关联。** 可以把引用理解成指向对象的标签：增加一个标签不会自动创建另一个对象。

变量保存的是对象引用：

```python
robot_a = Robot("robot_01", 85)
robot_b = robot_a

robot_b.speed_mps = 0.30
print(robot_a.speed_mps)  # 0.3
```

两个变量引用同一对象。重新创建实例才能得到独立状态：

```python
robot_a = Robot("robot_01", 85)
robot_b = Robot("robot_02", 72)
```

这与第二单元列表赋值不自动复制的原理一致。

当对象不再被需要且没有引用使它继续存活时，Python 可以回收它；不要依赖它恰好在某一行之后立即被回收。

**在 ROS 2 中的作用：** 多个变量可能引用同一个节点或状态对象，经由其中一个变量修改状态，其他引用也能看到变化。节点退出时还应显式清理 ROS 资源，例如第六单元的 `node.destroy_node()` 和 `rclpy.shutdown()`；仅删除一个变量名不能代替这些清理步骤。

## 16. 与 ROS 2 的联系

ROS 2 Python 节点常采用下面的结构：

```python
class RobotNode(Node):
    def __init__(self):
        super().__init__("robot_node")
        self.speed_mps = 0.0
        self.timer = self.create_timer(1.0, self.timer_callback)

    def timer_callback(self):
        self.get_logger().info(f"速度：{self.speed_mps:.2f}")
```

对应关系：

| 面向对象知识 | ROS 2 中的对应写法或使用场景 | 作用 |
| --- | --- | --- |
| 类 | `RobotNode` | 组织一种节点需要的数据和操作 |
| 对象 | 创建 `RobotNode()` 实例 | 得到程序中具体使用的节点对象 |
| 属性与方法 | 状态数据与处理状态的操作 | 将节点保存的数据和执行的功能放在一起 |
| `__init__` | 节点类的初始化方法 | 设置初始状态，创建节点所需的通信对象和定时器 |
| `self` | `self.speed_mps` | 在不同方法中访问当前节点对象的状态 |
| 实例属性 | `self.speed_mps`、`self.timer` | 保存每个节点实例自己的数据和对象 |
| 类属性 | 同类节点共用的固定说明或默认值 | 表达共享信息，避免用它保存各节点独立变化的数据 |
| 实例方法 | `self.timer_callback` | 读取本节点的状态并执行回调逻辑 |
| 封装 | 统一的数据检查和状态更新方法 | 让多个回调使用相同规则处理数据 |
| 继承 | `RobotNode(Node)` | 复用 `Node` 提供的节点功能 |
| `super()` 与父类初始化 | `super().__init__("robot_node")` | 初始化父类的节点功能并设置节点名称 |
| 方法重写 | 业务子类重写状态生成方法 | 根据不同机器人补充各自的状态内容 |
| 多态 | 对不同状态对象调用同名方法 | 用一致的调用方式处理不同对象 |
| 组合 | 节点把数据处理对象保存为属性 | 组织节点通信和数据处理之间的协作 |
| `property` | 状态对象的电量读写接口 | 在属性赋值时检查数值范围 |
| `staticmethod` | `Robot.is_valid_speed(value)` | 提供不依赖实例状态的数据检查操作 |
| `classmethod` | `Robot.create_default(name)` | 统一创建节点使用的默认状态对象 |
| 回调传递与点号访问 | 传入 `self.timer_callback`，不加括号 | 交出待执行的方法，由定时器到期时调用 |
| 引用与对象生命周期 | 多个变量引用同一节点；退出时显式清理 | 理解状态共享，并正确结束节点使用 |

## 17. 常见错误速查

| 错误 | 原因 | 处理方法 |
| --- | --- | --- |
| `NameError: self` | 方法参数缺少 `self` | 实例方法第一个参数写 `self` |
| `AttributeError` | 属性未初始化或拼错 | 在 `__init__` 中统一创建 |
| 多个对象状态相互影响 | 使用共享可变类属性 | 将实例数据放到 `self` 中 |
| 子类缺少父类属性 | 未调用父类初始化 | 使用 `super().__init__()` |
| 重写后父类行为消失 | 子类完全替换同名方法 | 需要时调用 `super().method()` |
| property 无限递归 | setter 中再次赋值同名 property | 使用 `_battery` 等内部属性 |
| 方法调用参数过多 | 调用实例方法时手动传入 `self` | 使用 `robot.stop()` |
| 把组合写成继承 | 对象关系判断错误 | 区分“是一种”和“拥有一个” |
