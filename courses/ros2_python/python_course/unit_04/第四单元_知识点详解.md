# 第四单元知识点详解

## 模块组织、文件操作与运行环境

本单元把机器人程序从单个脚本拆分成多个模块，并学习读取配置、保存测量记录以及处理文件错误。

配套代码位于 [experiments](experiments) 文件夹，运行方式见文末的“配套代码与运行”，课后作业附在最后。

本单元继续用“在 ROS 2 中的作用”说明各知识点的用途。节点是负责某项机器人功能的程序，回调函数是在收到消息或定时器触发等情况下被调用的函数；本单元先学习组织代码和保存数据，第六单元再将这些基础用于真实节点。

## 1. 模块

### 1.1 什么是模块

一个 `.py` 文件就是一个 Python 模块。模块可以保存变量、函数和类，并被其他文件导入。

**在 ROS 2 中的作用：** 可以把测距处理函数放在独立模块中，再由节点导入使用，方便多个节点复用同一段处理逻辑。

`processing.py`：

```python
def choose_action(distance_m):
    if distance_m <= 0.40:
        return "停车"
    return "前进"
```

`main.py`：

```python
import processing

print(processing.choose_action(0.30))
```

### 1.2 import 关键字

`import` 用来导入模块，让当前文件可以使用该模块提供的功能。

**在 ROS 2 中的作用：** 节点使用 `import rclpy` 导入 ROS 2 的 Python 客户端库，之后才能通过 `rclpy` 调用初始化等功能。

示例：

```python
import math

print(math.pi)
```

使用 `模块名.名称` 可以看出内容来自哪里。

### 1.3 from 关键字

`from` 指定来源，`import` 指定导入的名称。

**在 ROS 2 中的作用：** `from rclpy.node import Node` 从指定模块中导入节点类；导入消息类型时也会使用相同写法。

```python
from math import pi

print(pi)
```

不要随意使用 `from module import *`，它会把多个名称直接放入当前模块，难以判断来源，也可能发生名称冲突。

### 1.4 as 关键字

`as` 为导入的模块或名称设置别名，相当于在当前文件中给它取一个方便使用的名字。

**在 ROS 2 中的作用：** 节点同时使用多个工具模块时，可以用清楚的别名区分来源，避免名称相同而混淆；别名只改变代码中的称呼。

示例：

```python
import math as m
print(m.pi)
```

别名应简短且容易理解。不要为了少打几个字符而使用含义模糊的别名。

### 1.5 模块只在当前进程首次导入时执行一次

导入模块时，模块顶层代码会执行。为了避免导入时自动运行主程序，应使用下面的程序入口保护。

**在 ROS 2 中的作用：** 将节点启动代码放在入口函数中，可以避免其他模块只想导入一个处理函数时，就意外创建并运行节点。

```python
if __name__ == "__main__":
    main()
```

## 2. 包与 `__init__.py`

包是用于组织多个模块的目录，可以理解成存放相关代码的文件夹。本单元使用带 `__init__.py` 的普通 Python 包，这个文件用于标识包，并可安排包导入时提供哪些名称。

**在 ROS 2 中的作用：** Python 包可以集中保存节点模块和工具函数；ROS 2 功能包还需要依赖声明、安装配置等文件，只有一个 Python 包目录并不等于完成了 ROS 2 功能包。

示例结构：

```text
robot_tools/
├── __init__.py
├── config.py
└── processing.py
```

导入包中的模块：

```python
from robot_tools.processing import choose_action
```

`__init__.py` 可以为空，也可以公开包的常用接口。

**在 ROS 2 中的作用：** 保留 `__init__.py` 可以组织节点所在的 Python 包，也可以在这里公开常用工具函数，让节点的导入语句更清楚。

```python
from .config import load_config
from .processing import choose_action
```

之后可以写：

```python
from robot_tools import load_config, choose_action
```

点号表示当前包中的相对导入，即从这个包内部寻找指定模块。

**在 ROS 2 中的作用：** 节点所在的 Python 包可以用相对导入引用同包内的工具模块，让包内部各文件之间的关系更清楚。

## 3. 程序入口

程序入口是组织启动流程的起点，通常先准备配置和对象，再开始主要工作。

**在 ROS 2 中的作用：** 节点入口负责安排初始化、创建节点、处理回调以及退出清理，后续会把这些步骤集中到 `main()` 中。

### 3.1 `__name__`

Python 会为模块设置特殊变量 `__name__`：

- 直接运行文件时，值为 `"__main__"`。
- 文件被导入时，值通常是模块名。

**在 ROS 2 中的作用：** 用它判断模块是否被直接运行，可以把直接执行时的启动动作与导入函数、类的行为分开。

### 3.2 main 函数

`main()` 是程序员定义的入口函数，用来集中安排主流程；仅仅定义它不会自动执行，还需要调用。

**在 ROS 2 中的作用：** 第六单元会在 `setup.py` 中把可执行程序名关联到节点模块的 `main()`，运行该程序时就会调用这个入口函数。

```python
def main():
    print("机器人程序启动")


if __name__ == "__main__":
    main()
```

这样既可以直接运行，也可以安全导入其中的函数。

`main` 不是关键字，只是常用的入口函数名。`__name__` 和 `__main__` 也不是关键字，它们是 Python 约定的特殊名称和值。

## 4. 输入与输出

输入是程序获取外部数据，输出是程序把结果交给外部，例如从键盘读取名称、在终端显示状态。

**在 ROS 2 中的作用：** 节点常通过订阅消息获得输入，通过发布消息给出输出；终端输入输出则适合本单元的独立练习和调试工具。

### 4.1 print

`print()` 把文字或数据输出到终端，便于查看程序执行结果。

**在 ROS 2 中的作用：** 学习阶段可用它检查处理函数的结果；正式节点显示运行状态时，通常使用节点日志，如第六单元中的 `self.get_logger().info(...)`。

```python
print("robot_01", 85, 0.30)
```

修改分隔符和结尾：

```python
print("robot_01", 85, sep=" | ", end="\n")
```

`print` 是内置函数，不是关键字。

### 4.2 input

`input()` 显示提示并等待用户输入一行文字，用户按回车后程序才继续执行。

**在 ROS 2 中的作用：** 可以用于独立的交互练习或辅助工具；不要在节点回调中用它等待键盘输入，否则会占住执行该回调的线程，可能拖延其他回调。

```python
robot_name = input("请输入机器人名称：")
```

`input()` 返回字符串。读取数字时需要转换并处理错误：

```python
try:
    speed_mps = float(input("请输入速度："))
except ValueError:
    print("请输入合法数字")
```

### 4.3 命令行参数

命令行参数是启动程序时附带的设置，例如用 `--speed 0.45` 指定本次运行速度。`argparse` 是用于读取和检查这些参数的标准库模块。

**在 ROS 2 中的作用：** 可以为数据转换、离线分析等辅助脚本提供启动选项；ROS 2 节点参数有专门的声明和传入方式，普通 `argparse` 选项不会自动成为 ROS 2 参数。

示例：

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--speed", type=float, default=0.30)
args = parser.parse_args()

print(args.speed)
```

运行：

```powershell
python robot.py --speed 0.45
```

## 5. 文件基础

文件是保存在磁盘等存储设备上的一组数据。变量通常只在程序运行期间使用，而保存到文件的数据可以在下次运行时继续读取。

**在 ROS 2 中的作用：** 可以保存节点使用的普通配置和实验测量记录，便于重启后读取或课后分析。

### 5.1 文本文件与二进制文件

- 文本文件保存可以按字符解释的内容，如 `.txt`、`.json`、`.csv`。
- 二进制文件保存字节，如图片、音频和压缩包。

本单元主要处理 UTF-8 文本文件。

**在 ROS 2 中的作用：** 文本文件适合保存可直接查看的配置和测距记录，二进制文件适合保存图像等数据；具体读写方式要与文件格式对应。

### 5.2 open

`open()` 按指定路径和模式打开文件，返回一个文件对象，后续通过这个对象读写内容；`close()` 关闭文件并释放相关资源。

**在 ROS 2 中的作用：** 节点启动时可以打开普通配置文件读取设置，实验工具也可以打开记录文件保存数据；操作结束后要关闭文件，后面会用 `with` 自动完成这一步。

```python
file = open("robot.txt", "r", encoding="utf-8")
content = file.read()
file.close()
```

参数含义：

- 文件路径。
- 打开模式。
- 文本编码。

### 5.3 文件模式

文件模式规定这次打开文件准备做什么，以及文件已经存在时如何处理。

**在 ROS 2 中的作用：** 读取配置用 `r`，重新生成一份实验结果可用 `w`，保留原记录并继续添加用 `a`，只允许新建文件可用 `x`；保存图像等字节数据时需要二进制模式。

| 模式 | 作用 | 文件不存在 | 文件已存在 |
| --- | --- | --- | --- |
| `r` | 读取 | 报错 | 从头读取 |
| `w` | 写入 | 创建 | 清空原内容 |
| `a` | 追加 | 创建 | 在末尾写入 |
| `x` | 独占新建 | 创建 | 报错 |
| `b` | 二进制附加标志 | 取决于主模式 | 读写字节 |

例如 `rb` 表示二进制读取，`wb` 表示二进制写入。

### 5.4 encoding

编码规定了文字如何与文件中保存的字节相互转换，`encoding` 参数用来指定这套规则。课程统一使用：

```python
encoding="utf-8"
```

读取时使用的编码与文件实际编码不一致，可能产生 `UnicodeDecodeError` 或乱码。

**在 ROS 2 中的作用：** 保存和读取包含中文设备名称、状态说明的文本时，明确使用 UTF-8 有助于在不同电脑上正确显示内容。

## 6. with 与上下文管理

上下文管理是把资源的准备、使用和收尾放在一个明确范围内。可以把它理解成“打开文件后在这一段代码中使用，离开时负责关好”。

**在 ROS 2 中的作用：** 节点或辅助脚本读取配置、保存记录时，可以用上下文管理安排文件的使用范围，避免忘记关闭文件。

### 6.1 with 关键字

`with` 用来进入受管理的代码块，离开代码块时执行约定的清理。对下面的文件操作来说，清理就是关闭文件。

**在 ROS 2 中的作用：** 读取节点的普通配置文件时，用 `with open(...)` 可以让文件在读取结束后自动关闭，包括读取过程中出现异常的情况。

```python
with open("robot.txt", "r", encoding="utf-8") as file:
    content = file.read()
```

### 6.2 as 关键字

在下面的文件操作中，`as file` 给打开的文件对象取名为 `file`，代码块内就能用这个名称读写文件。`file` 不是关键字，可以换成更明确的名称。

**在 ROS 2 中的作用：** 读取配置和写入记录时，可以分别使用 `config_file`、`log_file` 等名称，让人一眼看出当前操作的是哪个文件。

```python
with open("robot.txt", "r", encoding="utf-8") as status_file:
    content = status_file.read()
```

### 6.3 with 的优势

- 正常执行结束会关闭文件。
- 代码块中发生异常也会关闭文件。
- 资源范围清晰。

**在 ROS 2 中的作用：** 配置解析失败时仍能完成文件关闭，方便程序按异常处理流程结束本次操作；`with` 本身不会修复文件内容或消除异常。

## 7. 文件读写方法

### 7.1 读取

读取就是把文件内容取到程序中。对文本文件，`read()` 读取剩余全部内容并返回字符串，`readline()` 读取一行，`readlines()` 把剩余各行放入列表。

**在 ROS 2 中的作用：** 可以读取设备说明、配置文本或历史测距记录，供节点启动准备或离线分析使用；较长的文件处理应安排在回调外，避免占用回调执行时间。

```python
content = file.read()       # 读取剩余全部内容
line = file.readline()      # 读取一行
lines = file.readlines()    # 读取为行列表
```

逐行处理：

```python
for line in file:
    print(line.strip())
```

逐行处理不需要一次把整个大文件加载到内存。

### 7.2 写入

写入就是把程序中的数据保存到文件。`write()` 写入一个字符串，`writelines()` 依次写入一组字符串，两者都不会自动在每项后添加换行。

**在 ROS 2 中的作用：** 可以把节点采集到的测距值和计算出的状态整理成记录，供后续分析；大量或耗时的写入应安排在回调外。

```python
file.write("robot_01\n")
file.writelines(["line1\n", "line2\n"])
```

`write()` 不会自动添加换行，需要自己写 `\n`。

### 7.3 文件位置

读取后，文件对象会记录当前位置。再次 `read()` 可能得到空字符串。需要时可使用 `seek(0)` 回到开头，但多数程序采用清晰的单次读取流程。

**在 ROS 2 中的作用：** 离线分析同一份传感器记录时，理解文件位置可以避免把“已经读到末尾”误判为“文件没有数据”；需要重新读取时可回到开头或重新打开文件。

## 8. 路径

路径是文件或目录的位置说明，相当于程序寻找数据时使用的地址。

**在 ROS 2 中的作用：** 节点读取资源或保存记录时，要明确文件位于哪里；功能包安装后的位置可能与源码目录不同，后续需要按安装后的资源位置定位文件。

### 8.1 当前工作目录

当前工作目录是程序此刻处理相对路径时使用的基准目录。

相对路径从程序启动时的当前工作目录开始解释，不一定是脚本所在目录。

**在 ROS 2 中的作用：** 从不同终端目录启动节点时，当前工作目录可能不同，因此不能假定 `"config.json"` 总能找到节点代码旁边的配置文件。

```python
import os

print(os.getcwd())
```

### 8.2 绝对路径与相对路径

- 绝对路径包含完整位置。
- 相对路径依赖当前工作目录。

硬编码个人电脑的绝对路径会降低程序可移植性。

**在 ROS 2 中的作用：** 在开发电脑和机器人上部署同一程序时，应根据实际资源位置构造路径，避免把某台电脑的用户目录固定写进节点代码。

### 8.3 pathlib

`pathlib` 是处理路径的标准库模块，`Path` 对象把路径表示成可以拼接、查询和操作的对象。

**在 ROS 2 中的作用：** 确定配置或记录目录后，可以用 `Path` 拼接文件名、检查文件是否存在、创建输出目录；下面按 `__file__` 定位的写法适用于本单元脚本结构，不能直接代替安装后功能包资源的查找。

```python
from pathlib import Path

script_dir = Path(__file__).resolve().parent
config_path = script_dir / "data" / "robot_config.json"
```

常用操作：

```python
path.exists()
path.is_file()
path.is_dir()
path.name
path.suffix
path.parent
path.mkdir(exist_ok=True)
```

`exists()` 判断路径是否存在，`is_file()`、`is_dir()` 分别判断是否为文件、目录；`name`、`suffix`、`parent` 分别取得名称、后缀和上一级目录，`mkdir()` 用来创建目录。

### 8.4 os

`os` 是提供操作系统相关功能的标准库模块，也能获取工作目录、处理路径和目录。

**在 ROS 2 中的作用：** 阅读功能包安装配置或辅助脚本时，会遇到用 `os.path.join(...)` 拼接资源路径的代码；理解它有助于确认配置文件被放到哪里。

示例：

```python
import os

current_dir = os.getcwd()
config_path = os.path.join(current_dir, "data", "config.json")
```

新代码通常可以优先使用 `pathlib`；阅读旧代码和 ROS 2 包配置时仍会见到 `os.path`。

## 9. JSON

JSON 是一种用文本表示结构化数据的格式，可以保存名称与值的对应关系，也可以保存列表。它是数据格式，Python 字典是程序运行时的数据对象，二者需要通过解析和转换衔接。

**在 ROS 2 中的作用：** 可以保存程序自己读取的设备配置或状态快照；读取 JSON 得到的字典仍是普通 Python 数据，不会自动变成 ROS 2 参数或消息。

### 9.1 JSON 数据类型

JSON 的数据类型规定文件中可以表达哪些内容，读取时会转换为对应的 Python 类型。

**在 ROS 2 中的作用：** 例如读取设备名称得到字符串，读取多个距离阈值得到列表或字典，节点中的处理函数才能按对应类型使用这些数据。

| JSON | Python |
| --- | --- |
| 对象 `{}` | 字典 `dict` |
| 数组 `[]` | 列表 `list` |
| 字符串 | `str` |
| 数字 | `int` 或 `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

JSON 键和字符串必须使用双引号，不能写 Python 的单引号格式。

### 9.2 读取 JSON

读取 JSON 是把 JSON 文本解析成 Python 对象。`json.load()` 从已打开的文件读取，`json.loads()` 解析已有的字符串。

**在 ROS 2 中的作用：** 节点启动准备时，可以读取自定义的 JSON 文件，取得设备名称、测距阈值等数据，再交给处理函数使用。

```python
import json

with open("config.json", "r", encoding="utf-8") as file:
    config = json.load(file)
```

### 9.3 写入 JSON

写入 JSON 是把可表示为 JSON 的 Python 数据转换为 JSON 文本。`json.dump()` 写入文件，`json.dumps()` 返回字符串。

**在 ROS 2 中的作用：** 可以将节点当前的普通状态数据保存为文件快照，供下次读取或离线查看；若要通过话题传递，还需按选定的 ROS 2 消息类型组织字段。

```python
with open("config.json", "w", encoding="utf-8") as file:
    json.dump(config, file, ensure_ascii=False, indent=2)
```

### 9.4 配置检查

JSON 格式合法不代表配置内容完整。仍需要检查键是否存在、类型是否正确、数值是否在允许范围内。

**在 ROS 2 中的作用：** 节点使用自定义配置前，要检查例如停车阈值是否为正数、是否小于减速阈值，避免把不合要求的设置交给处理逻辑。

## 10. CSV

CSV 使用行和列保存表格数据。标准库 `csv` 能正确处理分隔符、引号和换行。

**在 ROS 2 中的作用：** 可以把接收到的测距值整理成“采样序号、距离、状态”等列，保存后使用表格工具查看或画图分析。

`csv.writer()` 创建写入器，`writerow()` 写一行字段；`csv.reader()` 创建读取器，遍历它时逐行取得字段列表。

**在 ROS 2 中的作用：** 写入器用于保存整理后的实验记录，读取器用于离线检查历史记录；读出的距离字段通常还需用 `float()` 转为数值才能计算。

写入：

```python
import csv

with open("log.csv", "w", newline="", encoding="utf-8") as file:
    writer = csv.writer(file)
    writer.writerow(["sample_id", "distance_m"])
    writer.writerow([1, 1.20])
```

读取：

```python
with open("log.csv", "r", newline="", encoding="utf-8") as file:
    reader = csv.reader(file)
    for row in reader:
        print(row)
```

CSV 读取结果通常是字符串，需要根据列含义转换类型。

## 11. 异常处理

### 11.1 什么是异常

异常表示程序运行时出现不能按正常流程完成的情况，例如文件不存在、数字格式错误或字典缺少键。

**在 ROS 2 中的作用：** 节点读取配置或转换输入数据时也可能遇到异常，明确处理这些情况可以给出原因，并决定结束本次处理还是退出程序。

### 11.2 try 与 except

`try` 包住可能出错的操作；如果其中抛出了匹配的异常，程序会转到对应的 `except` 分支处理。

**在 ROS 2 中的作用：** 节点把外部文本转换成数值时，可以捕获 `ValueError`，记录格式错误并结束本次处理，避免继续使用无效数据。

```python
try:
    speed_mps = float(speed_text)
except ValueError:
    print("速度格式错误")
```

- `try` 中放可能发生异常的代码。
- `except` 只处理指定异常。
- 不应使用一个空泛的 `except:` 隐藏所有问题。

### 11.3 多个 except

多个 `except` 用来区分不同种类的异常，一次异常只进入最先匹配的分支。

**在 ROS 2 中的作用：** 节点加载配置时，可以分别提示“找不到文件”“JSON 格式错误”和“缺少字段”，让排查问题的人知道应该修改哪里。

```python
try:
    with config_path.open("r", encoding="utf-8") as file:
        config = json.load(file)
    speed = config["max_speed_mps"]
except FileNotFoundError:
    print("文件不存在")
except json.JSONDecodeError:
    print("JSON 格式错误")
except KeyError as error:
    print(f"缺少字段：{error}")
```

异常应从具体问题出发分别处理。

### 11.4 else 与 finally

在异常处理结构中，`else` 安排 `try` 正常完成后的工作，`finally` 安排离开这一结构前的收尾工作，无论是否发生异常都会执行。

**在 ROS 2 中的作用：** 可以在配置读取成功后才应用设置；节点退出时，也可把释放节点资源和关闭 ROS 2 上下文的操作放在 `finally` 中，第六单元会给出完整示例。

```python
try:
    value = float(text)
except ValueError:
    print("转换失败")
else:
    print("转换成功", value)
finally:
    print("处理结束")
```

- `else` 在没有异常时执行。
- `finally` 无论是否有异常都执行。

### 11.5 raise 关键字

`raise` 主动抛出异常，表示程序发现当前输入或状态不符合要求，不能沿正常流程继续。

**在 ROS 2 中的作用：** 读取配置后发现阈值不合法时，可以用 `raise ValueError(...)` 报告具体原因，再由调用它的节点入口决定如何处理。

示例：

```python
if speed_mps < 0:
    raise ValueError("速度不能为负数")
```

它适合明确告诉调用者：输入违反了函数要求。

## 12. 本单元关键字详解

关键字是 Python 语法中有固定含义的词。下面把导入、资源管理和异常处理用到的关键字放在一起，便于查找。

**在 ROS 2 中的作用：** 阅读节点文件时，可以据此识别哪些语句负责导入依赖、管理文件和处理错误，完整理解节点从启动到退出的流程。

| 关键字 | 作用 | 示例位置 |
| --- | --- | --- |
| `import` | 导入模块或名称 | `import json` |
| `from` | 指定导入来源 | `from pathlib import Path` |
| `as` | 设置别名或绑定上下文对象、异常对象 | `as file` |
| `with` | 管理资源上下文 | 打开文件 |
| `try` | 尝试执行可能出错的代码 | 文件读取、类型转换 |
| `except` | 捕获指定异常 | `except ValueError:` |
| `else` | 没有异常时执行 | 异常处理结构 |
| `finally` | 无论是否异常都执行 | 清理或结束提示 |
| `raise` | 主动抛出异常 | 参数验证 |

`open`、`print`、`input` 是内置函数，不是关键字。`json`、`csv`、`os`、`pathlib` 是模块名。`read`、`write`、`mkdir` 是对象方法。

## 13. 模块化项目结构

模块化是按职责把程序拆成若干文件，每个文件集中解决一类问题，再通过导入和函数调用配合工作。

**在 ROS 2 中的作用：** 可以让节点模块负责接收、发布消息，让处理模块负责过滤测距和判断状态；这样处理算法可以先独立练习，再被不同节点复用。

```text
04_module_project/
├── main.py
├── config/
│   └── robot_config.json
└── robot_tools/
    ├── __init__.py
    ├── config.py
    └── processing.py
```

职责：

- `main.py`：组织程序流程和处理顶层错误。
- `config.py`：读取配置。
- `processing.py`：过滤测距并判断状态。
- `robot_config.json`：保存可以修改的参数。
- `__init__.py`：定义包的公开接口。

## 14. 与 ROS 2 的联系

ROS 2 的 `ament_python` 功能包沿用 Python 包结构。后续会看到 `package.xml`、`setup.py`、`setup.cfg`、包目录和 `__init__.py`。

例如，第六单元的 [节点模块](../unit_06/ros2_ws/src/robot_status_py/robot_status_py/status_publisher.py) 使用导入、`main()` 和 `try/finally` 组织流程，[安装配置](../unit_06/ros2_ws/src/robot_status_py/setup.py) 则把可执行程序名关联到入口函数。本单元的普通模块化项目为理解这些文件做准备。

| Python 内容 | ROS 2 用途 |
| --- | --- |
| 模块 | 把测距算法拆成独立文件，供节点导入复用 |
| Python 包与 `__init__.py` | 集中组织节点模块和工具函数，为功能包的 Python 代码提供结构 |
| 相对导入 | 在节点所在的 Python 包内部引用其他工具模块 |
| `import / from / as` | 导入 `rclpy`、节点类和消息类型，必要时使用明确的别名 |
| 导入执行与 `__name__` | 避免只导入工具函数时就意外启动节点 |
| `main()` | 集中组织初始化、创建节点、处理回调和退出清理 |
| 输入与输出 | 理解节点接收数据和给出结果的方向，后续衔接订阅与发布 |
| `print()` | 在独立脚本中查看结果，后续学习节点日志输出 |
| `input()` | 用于独立交互工具，避免在节点回调中等待键盘输入 |
| 命令行参数与 `argparse` | 为辅助脚本提供名称、文件路径等启动选项 |
| 文本与二进制文件 | 按数据格式保存普通配置、测量记录或图像等内容 |
| `open() / close()` | 打开配置或记录文件，操作结束后释放文件资源 |
| `r / w / a / x / b` 模式 | 选择读取、覆盖、追加、新建或二进制读写，避免误覆盖记录 |
| `encoding` | 正确保存和读取中文设备名称、状态说明 |
| `with ... as ...` | 为文件取清楚的名称，并在离开代码块时完成关闭 |
| `read / readline / readlines` 与逐行遍历 | 读取配置文本或历史记录，按数据量选择读取方式 |
| `write / writelines` | 把整理后的测量值和状态写入记录文件 |
| 文件位置与 `seek(0)` | 需要重复分析时回到文件开头，避免误以为文件为空 |
| 工作目录、绝对路径与相对路径 | 明确启动位置与资源位置，避免换个目录就找不到配置 |
| `pathlib / os.path` | 拼接资源路径、检查文件是否存在并准备输出目录 |
| JSON 数据类型 | 理解普通配置在文件格式与 Python 数据对象之间的对应关系 |
| `json.load / loads` | 从文件或字符串解析程序自定义的配置与状态数据 |
| `json.dump / dumps` | 将普通状态数据保存成 JSON 文件或转换为字符串 |
| 配置检查 | 使用设置前核对必要字段、数值类型和阈值范围 |
| CSV、`reader / writer / writerow` | 按行列读取和保存测距实验记录，便于后续分析 |
| 异常与 `try / except` | 报告读取、转换等错误，明确结束本次处理的方式 |
| 多个 `except` | 区分文件缺失、JSON 格式错误和字段缺失等原因 |
| `else / finally` | 在操作成功后继续处理，并安排退出前的资源清理 |
| `raise` | 主动报告无效阈值等不符合要求的输入 |
| 模块化项目结构 | 将节点通信、配置读取和数据处理按职责拆分 |

ROS 2 参数和参数文件有自己的机制；普通 JSON 配置实验用于学习文件和数据组织，不等同于 ROS 2 参数系统。

## 15. 常见错误速查

| 错误 | 原因 | 处理方法 |
| --- | --- | --- |
| `ModuleNotFoundError` | 模块路径或运行位置不正确 | 检查目录结构和导入名称 |
| 导入时主程序自动运行 | 顶层直接调用程序 | 使用 `__name__` 入口保护 |
| `FileNotFoundError` | 路径错误或文件不存在 | 输出并检查完整路径 |
| 中文乱码 | 文件编码不一致 | 统一使用 UTF-8 |
| 原文件被清空 | 使用 `w` 模式 | 写入前确认模式 |
| 写入内容连在一起 | `write()` 没有自动换行 | 添加 `\n` |
| `JSONDecodeError` | JSON 引号、逗号等格式错误 | 检查 JSON 语法 |
| `KeyError` | 配置缺少键 | 检查字段或使用 `get()` |
| CSV 出现空行 | 未指定 `newline=""` | 按示例打开 CSV |
| 捕获异常后仍没有数据 | 异常分支没有正常结束流程 | 明确返回、默认值或退出 |
