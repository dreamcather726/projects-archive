# 第 2 模块：ROS 2 话题通信进阶与消息类型

课程材料：[知识点详解](第二单元_知识点详解.md) · [实验说明与代码](experiments/01_sensor_status/实验说明.md)

## 内容范围

- 话题通信的异步、多对多和弱耦合特点。
- `rclpy` 发布者与订阅者的创建和运行。
- 标准消息、复杂字段与自定义消息设计。

## 详细知识点

### 1. 发布—订阅模型

- 发布者、订阅者、话题名称和消息类型之间的匹配关系。
- 话题适合连续数据流，不保证“请求一次、响应一次”。
- 一个话题可以有多个发布者和多个订阅者。
- 节点发现完成前首条消息可能丢失的原因。
- 发布频率、订阅处理速度与消息积压的关系。

### 2. rclpy 发布者与订阅者

- `create_publisher()`、`create_subscription()` 的参数和返回对象。
- 定时发布、事件触发发布以及回调中转发消息。
- 消息对象的创建、字段赋值与类型检查。
- 订阅回调的输入参数、对象属性保存与资源生命周期。
- 为什么通信对象必须保存为实例属性。

### 3. 常用消息类型

- `std_msgs`：基础标量和字符串消息。
- `geometry_msgs`：`Twist`、`Pose`、`PoseStamped`、`TransformStamped`。
- `sensor_msgs`：`LaserScan`、`Image`、`Imu`、`JointState`。
- `nav_msgs`：`Odometry`、`Path`。
- 标量、数组、嵌套消息和定长/变长字段。
- `Header.stamp` 与 `Header.frame_id`：数据时间和坐标系语义。
- 使用节点时钟填写时间戳，避免混用系统时间和仿真时间。

### 4. 话题名称与命名规范

- 绝对名称、相对名称、私有名称的解析思路。
- 节点命名空间如何影响相对话题名称。
- 重映射让同一份节点代码适配不同机器人或数据源。
- 话题应表达数据含义，不把发布节点名称硬编码进接口。

### 5. 命令行观察与调试

- `ros2 topic list -t` 同时查看名称与类型。
- `ros2 topic type`、`ros2 interface show` 查看消息结构。
- `ros2 topic echo` 观察字段和值。
- `ros2 topic pub` 手动构造测试消息。
- `ros2 topic hz`、`bw` 检查频率和带宽。
- `ros2 topic info --verbose` 检查端点和 QoS。

### 6. 自定义消息

- 何时应使用标准消息，何时需要业务自定义消息。
- `.msg` 字段、常量、数组和嵌套类型的设计。
- 接口包与 Python 业务节点包分离，避免循环依赖。
- 接口生成、依赖声明、重新构建和重新加载环境。
- Python 中导入生成后的消息类型并完成发布订阅。
- 自定义接口应稳定、语义清晰，避免频繁破坏性修改。

### 7. QoS 初步认识

- 队列深度不是发布频率，也不是订阅回调线程数。
- 默认 QoS 与传感器数据 QoS 的用途差异。
- 名称和类型正确但 QoS 不兼容时仍可能收不到数据。
- 可靠性、持久性等策略在第 6 模块系统学习。

## 课堂演示

1. 编写里程计简化发布节点和安全监控订阅节点。
2. 使用 `Twist` 演示嵌套字段赋值。
3. 用命令行发布紧急停车消息并观察订阅输出。
4. 修改命名空间和重映射规则，使同一节点服务两台模拟机器人。
5. 使用 `ros2 topic hz` 比较定时周期与实际发布频率。

## 实验任务

实现传感器状态链路：

- `sensor_publisher` 周期发布包含时间戳、距离、温度和状态码的自定义消息。
- `safety_monitor` 订阅消息，判断超距、过热和数据超时。
- 通过命令行验证消息结构、频率、带宽和端点信息。

## 常见问题

- 话题名称一致但消息类型不同。
- 回调签名错误，或消息字段赋了不兼容的 Python 类型。
- 忘记保存 publisher/subscription 对象导致通信实体被回收。
- 使用错误 QoS 订阅传感器数据。
- `frame_id` 含义不明确，后续可视化时数据落在错误坐标系。

## 验收标准

- 能独立完成标准消息与自定义消息的发布订阅。
- 能用命令行定位名称、类型、频率和 QoS 问题。
- 能解释时间戳、坐标系和队列深度的意义。
- 监控节点能正确识别异常值和数据超时。
