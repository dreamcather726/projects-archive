# 实验 3：巡检启停服务与巡检任务动作

## 为什么要做这个实验

“是否允许巡检”是一个立即生效并返回结果的配置请求，适合服务；“依次访问多个巡检点”持续时间较长，需要反馈进度并允许取消，适合动作。把两种需求放在同一个实验中，学生能真正理解通信方式应由业务语义决定。

## 实验的作用

- 完成 Python 服务端、异步服务客户端的闭环。
- 完成 Python 动作服务端、动作客户端、反馈、结果和取消。
- 学会处理服务不可用、目标拒绝和任务取消。
- 为第 9 章综合巡检任务管理器建立接口基础。

## 实验重点

1. 服务只做快速启停，不在服务回调中执行整个巡检。
2. 动作目标被接受不代表任务已经成功完成。
3. 动作执行循环必须主动检查取消请求。
4. 客户端 API 都是异步的，需要按 Future 完成顺序处理结果。

## 运行步骤

```bash
source /opt/ros/jazzy/setup.bash
cd <课程仓库>/ros2_course/unit_03_services_and_actions/experiments/01_patrol_task/ros2_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

终端 1 启动服务端：

```bash
ros2 run patrol_communication_py patrol_server
```

终端 2 启动客户端：

```bash
source /opt/ros/jazzy/setup.bash
cd <实验目录>/ros2_ws
source install/setup.bash
ros2 run patrol_communication_py patrol_client --ros-args \
  -p waypoint_count:=5 -p dwell_seconds:=0.8
```

客户端会先调用启用服务，然后发送动作目标，终端持续显示进度反馈。

测试取消：

```bash
ros2 run patrol_communication_py patrol_client --ros-args \
  -p waypoint_count:=10 -p dwell_seconds:=1.0 -p cancel_after:=3.0
```

也可以直接用命令行测试服务：

```bash
ros2 service call /set_patrol_enabled \
  patrol_interfaces/srv/SetPatrol "{enabled: false}"
ros2 action list -t
ros2 action info /run_patrol
```

## 预期现象

- 巡检未启用时，动作目标被拒绝。
- 客户端先启用巡检后，动作目标被接受。
- 每访问一个点都会收到当前点和完成比例反馈。
- 设置 `cancel_after` 后，任务中途取消并返回已访问点数。

## 验收任务

1. 使用服务关闭巡检，再直接用 `ros2 action send_goal` 证明目标会被拒绝。
2. 给动作 Goal 增加 `string route_name` 并显示在服务端日志中。
3. 拒绝 `waypoint_count <= 0` 或 `dwell_seconds <= 0` 的目标。
4. 让客户端在服务端未启动时每秒提示一次，而不是退出或无限静默等待。

## 常见问题

- 接口修改后 Python 仍看到旧字段：重新构建并重新加载工作空间。
- 目标发送后无反馈：检查服务端是否在执行、客户端是否注册反馈回调。
- 点击取消但任务继续：执行循环没有检查 `is_cancel_requested`。
- 服务和动作能找到但类型不一致：用 `ros2 service type`、`ros2 action info` 检查。
