# ROS 2 Python 课程教学使用说明

## 课程定位

本课程面向已经完成 Python 基础学习、准备进入 ROS 2 机器人开发的学生。全部业务节点使用 Python 和 `rclpy` 编写，不设置其他语言版本的实验。

推荐环境：Ubuntu 24.04、ROS 2 Jazzy、Python 3、Gazebo Harmonic。

## 每章建议授课节奏

每章可以按 4 个教学环节组织：

1. **问题导入**：先展示机器人系统中的实际问题，让学生知道为什么要学。
2. **知识讲授**：解释概念、API、命令、数据流和设计规范。
3. **教师演示**：教师边运行边提问，让学生预测结果。
4. **学生实验**：学生按实验说明独立完成，最后用验收清单检查。

建议不要连续讲完整章后再统一实验。每讲完一个关键概念，就执行一次最小命令或修改一次代码，让学生立即看到概念如何影响系统行为。

## 实验材料统一结构

每个实验至少包含：

- 为什么做：说明实验对应的真实机器人问题。
- 实验作用：说明它为后续哪种能力打基础。
- 实验重点：指出课堂必须观察的现象。
- 运行步骤：包含环境加载、构建、运行、观察和停止。
- 预期结果：学生能够判断自己是否运行正确。
- 常见问题：提供有证据的排查顺序。
- 验收任务：要求学生修改参数或扩展功能，避免只复制运行。

代码中的教学注释重点解释设计理由、ROS 2 生命周期和容易出错的位置；普通 Python 语法不重复大段解释。

## 统一构建与运行约定

在 Ubuntu 终端中执行：

```bash
source /opt/ros/jazzy/setup.bash
cd <实验工作空间>
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

新开终端后，需要再次依次加载 ROS 2 和当前实验工作空间。修改 `setup.py`、资源安装规则、自定义接口或依赖后必须重新构建；只修改通过 `--symlink-install` 安装的 Python 源码时，通常可以直接重新运行节点。

## 课堂验收建议

不要只检查“能否运行”，还应要求学生回答：

1. 这个节点在计算图中的输入和输出是什么？
2. 为什么选择话题、服务或动作？
3. 如果另一个节点未启动，当前节点会怎样？
4. 如何用 ROS 2 命令证明程序正在正确工作？
5. 哪个参数或 QoS 改动会改变当前实验现象？
