# 第九单元知识点详解

## ROS 2 自主巡检系统集成

这份文档把前面各单元的接口、参数、状态、安全和诊断组合为一个可交付的 Python ROS 2 巡检系统，内容覆盖需求拆分、接口表、状态机、动作任务、里程计、安全停止、工作空间叠加和故障注入。

配套实验位于 [experiments/01_patrol_robot](experiments/01_patrol_robot)。

## 1. 从一句需求拆成可验收条目

“做一台自主巡检机器人”过于模糊。需要拆解：

- 在什么场地运行？
- 巡检完成条件是什么？
- 遇到障碍如何处理？
- 怎样开始、反馈、取消和结束任务？
- 哪些故障必须停车？
- 用哪些命令证明系统达标？

本实验把任务简化为“在封闭场地反应式避障，累计行驶指定距离”。它不依赖地图，但能力边界必须在报告中明确。

## 2. 接口设计

让学生先提交接口表：

| 接口 | 类型 | 方向 | 用途 |
|---|---|---|---|
| `/scan` | LaserScan 话题 | 输入 | 障碍物距离 |
| `/odom` | Odometry 话题 | 输入 | 累计行驶距离 |
| `/cmd_vel` | Twist 话题 | 输出 | 底盘控制 |
| `/patrol/status` | String 话题 | 输出 | 最新状态 |
| `/patrol_distance` | 动作 | 双向 | 长时巡检任务 |
| `/patrol/emergency_stop` | 服务 | 双向 | 紧急停止设置 |

要求解释每个接口为什么使用该通信方式，并注明 QoS、频率、单位和坐标系。

## 3. 状态机与优先级

状态包括 IDLE、FORWARD、TURNING、COMPLETED、CANCELED、EMERGENCY_STOP、FAULT。

安全优先级应高于任务进度：急停/超时 > 取消 > 完成 > 正常避障。多个回调同时改变条件时，最终控制输出必须遵循这一优先级。

使用滞回阈值：进入转向用 `safe_distance`，恢复前进用更大的 `clear_distance`。若两个阈值相同，噪声会让状态在边界附近频繁切换。

## 4. 动作与控制循环解耦

动作执行回调管理任务生命周期和反馈；10 Hz 控制定时器根据最新传感器状态发布速度。不要在动作回调里用大循环直接完成所有控制，否则传感器、急停和取消可能无法及时调度。

动作执行期间反馈距离、百分比和状态。结束路径包括成功、客户端取消、急停和传感器故障；每条路径都返回结构化 Result。

## 5. 里程计距离累计

使用连续两帧位置的欧氏距离累加：

```text
distance += sqrt((x2-x1)^2 + (y2-y1)^2)
```

任务开始时必须重置累计值和上一位置。里程计可能漂移，本实验只把它作为短距离完成条件；不能把累计里程等同于高精度地图位置。

## 6. 故障安全

- 未收到 scan/odom 时拒绝目标。
- 任务中任一数据源超时，进入 FAULT 并停车。
- 急停服务立即把状态变为 EMERGENCY_STOP 并停车。
- 取消目标后停车并返回已行驶距离。
- 节点销毁前再次发布零速度。

应用层停车不是唯一安全措施。真实底盘还应有命令看门狗、硬件急停和独立安全控制链路。

## 7. Overlay 工作空间

第 8 章仿真工作空间作为 underlay，本章作为 overlay。构建和运行前先加载 underlay，再加载 overlay。这样综合项目复用已验证仿真包，不复制源码。

让学生解释 source 顺序，并使用 `ros2 pkg prefix` 证明每个包来自哪个工作空间。

## 8. 联调与故障注入

联调顺序：仿真模型 → bridge → 传感器数据 → 控制输出 → 动作任务 → 急停与故障。

必须主动注入：目标非法、重复目标、动作取消、急停、停止 bridge、修改 QoS/参数。只跑一次正常流程不能证明系统可靠。

## 9. 知识点检查

1. 为什么巡检用动作而急停设置用服务？
2. 为什么动作回调和控制循环要分离？
3. 两个安全距离阈值分别解决什么问题？
4. 里程计漂移会怎样影响完成条件？
5. 如果迁移到真实机器人，还需要增加哪些安全机制？
