# 实验 1：机器人心跳节点

## 为什么要做这个实验

真实机器人启动后，其他模块需要知道某个节点是否仍在运行。周期心跳是最简单的“存活证明”。本实验把普通 Python 的类、计时和字符串格式化，连接到 ROS 2 的节点、定时器、日志和参数，是进入 `rclpy` 的最小闭环。

## 实验的作用

- 建立从源码、功能包、构建、环境加载到运行检查的完整工程流程。
- 理解定时器只负责触发回调，节点必须通过执行器 `spin` 才会持续处理事件。
- 区分功能包名、入口名和运行时节点名。
- 为后续发布者、订阅者和生命周期节点打基础。

## 实验重点

1. 不执行 `source install/setup.bash` 时，当前终端找不到刚构建的包。
2. `timer_period` 是 ROS 参数；启动时修改它会改变心跳周期。
3. `ros2 node info` 显示节点已经存在，即使它还没有自定义发布者。
4. 按 `Ctrl+C` 后程序执行清理逻辑，而不是显示一长串异常。

## 运行步骤

以下命令在 Ubuntu 24.04 的终端中执行。

### 第 1 步：进入实验工作空间

```bash
source /opt/ros/jazzy/setup.bash
cd <课程仓库>/ros2_course/unit_01_ros2_engineering_basics/experiments/01_robot_heartbeat/ros2_ws
```

将 `<课程仓库>` 替换为仓库实际路径。

### 第 2 步：安装依赖

```bash
rosdep install --from-paths src --ignore-src -r -y
```

### 第 3 步：构建并加载工作空间

```bash
colcon build --symlink-install
source install/setup.bash
```

### 第 4 步：运行节点

```bash
ros2 run robot_basics_py robot_heartbeat
```

预期每秒看到一条包含序号和累计运行时间的心跳日志。

### 第 5 步：修改启动参数

停止节点后执行：

```bash
ros2 run robot_basics_py robot_heartbeat --ros-args -p timer_period:=0.5
```

预期心跳变为每 0.5 秒一次。

### 第 6 步：使用另一个终端观察

```bash
source /opt/ros/jazzy/setup.bash
cd <课程仓库>/ros2_course/unit_01_ros2_engineering_basics/experiments/01_robot_heartbeat/ros2_ws
source install/setup.bash
ros2 node list
ros2 node info /robot_heartbeat
ros2 param get /robot_heartbeat timer_period
```

## 预期现象

```text
[INFO] [...] [robot_heartbeat]: 心跳 #1：节点已运行 1.00 秒
[INFO] [...] [robot_heartbeat]: 心跳 #2：节点已运行 2.00 秒
```

时间数值允许有少量调度误差。

## 验收任务

1. 把节点运行时名称通过命令行重映射为 `/robot_01/heartbeat`。
2. 添加字符串参数 `robot_name`，让日志显示机器人名称。
3. 添加参数校验：`timer_period <= 0` 时给出错误并使用 1.0 秒默认值。
4. 用 `ros2 param get` 截图或记录实际参数值。

## 常见问题

### 提示找不到 package

执行：

```bash
ros2 pkg prefix robot_basics_py
```

如果找不到，重新构建并加载 `install/setup.bash`。

### 提示找不到 executable

执行：

```bash
ros2 pkg executables robot_basics_py
```

如果列表为空，检查 `setup.py` 的 `console_scripts` 后重新构建。

### 修改代码后没有变化

确认第一次构建使用了 `--symlink-install`，停止旧节点并重新运行。若修改了入口或安装配置，需要重新构建。
