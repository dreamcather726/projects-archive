# 实验 4：参数、Launch 与 TF2 坐标树

## 为什么要做这个实验

传感器测得的距离和位置只在它自己的坐标系中有意义。机器人要做融合、避障和导航，就必须知道传感器相对底盘、底盘相对里程计坐标系的位置。同时，传感器安装位置不应硬编码在算法中，应由参数和 Launch 统一配置。

## 实验的作用

- 把参数、YAML、Python Launch 和 TF2 串成一个完整工程。
- 理解静态安装关系与动态运动关系的区别。
- 掌握 Python 变换发布、监听和命令行诊断。
- 为 URDF/RViz、Gazebo 和导航中的坐标系统打基础。

## 实验重点

1. `base_link → front_laser` 是固定安装关系，使用静态变换。
2. `odom → base_link` 随机器人运动变化，使用动态变换。
3. TF 查询必须明确“目标坐标系”和“源坐标系”。
4. 参数文件通过 Launch 加载，路径资源必须安装进功能包。

## 运行步骤

```bash
source /opt/ros/jazzy/setup.bash
cd <课程仓库>/ros2_course/unit_04_node_tools_and_tf/experiments/01_tf_toolchain/ros2_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
ros2 launch robot_tools_py tf_demo.launch.py
```

新终端检查：

```bash
source /opt/ros/jazzy/setup.bash
cd <实验目录>/ros2_ws
source install/setup.bash
ros2 param get /static_sensor_tf x
ros2 run tf2_ros tf2_echo odom front_laser
ros2 run tf2_tools view_frames
```

最后一条命令会生成坐标树文件。也可以启动 RViz2，将 Fixed Frame 设为 `odom` 并添加 TF 显示。

## 预期现象

- `odom → base_link → front_laser` 形成一棵连通坐标树。
- `base_link → front_laser` 的平移保持不变。
- `odom → base_link` 随时间沿圆形轨迹变化。
- `tf_monitor` 每秒输出激光雷达在底盘坐标系中的安装位置。

## 验收任务

1. 修改 YAML，把雷达移动到机器人后方，验证 TF 输出变化。
2. 增加 `base_link → camera_link` 静态变换。
3. 用命名空间启动第二套节点，避免节点重名。
4. 故意把查询目标写成不存在的坐标系，记录异常，再恢复正确配置。

## 常见问题

- 找不到 Launch 或 YAML：`setup.py` 没有安装资源，修改后需重建。
- TF 查询一直失败：检查 frame 名称拼写和坐标树是否连通。
- 出现未来/过去外推异常：检查时间戳和 `use_sim_time` 是否一致。
- 静态变换方向错误：重新判断“父坐标系是谁、子坐标系是谁”。
