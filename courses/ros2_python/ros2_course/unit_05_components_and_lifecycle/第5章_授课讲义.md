# 第五单元知识点详解

## ROS 2 Python 节点模块化与生命周期

这份文档讲解如何把“能运行的脚本”整理为职责清晰、可配置、可测试、可恢复的机器人节点，并介绍 `rclpy.lifecycle` 的状态与转换。

配套实验位于 [experiments/01_managed_monitor](experiments/01_managed_monitor)。

## 1. Node 类为什么越来越大

随着功能增加，初学者常把订阅回调、数据过滤、决策、文件写入和设备控制全部放进一个 Node 子类。结果是：不启动 ROS 就无法测试算法；一个参数变化影响多个功能；异常清理散落；类拥有大量共享属性。

解决思路是分层：

- ROS 适配层：消息收发、参数、时间和日志。
- 业务逻辑层：普通 Python 类或函数。
- 资源层：设备、文件、模型等外部资源。
- 编排层：Launch 和生命周期管理。

## 2. 职责拆分的判断方法

可以用“变化原因”判断模块边界：传感器型号变化只应影响适配层；安全规则变化只应影响判断器；启动部署变化只应影响 Launch/配置。

节点也不是越小越好。两个功能若始终以同一频率运行、共享大量内部状态且没有独立部署价值，可以留在同一节点内的不同模块中。

## 3. 纯 Python 业务逻辑

例如异常检测器只接收数值并返回判断结果，不应该自己订阅 ROS 话题：

```python
class AnomalyDetector:
    def evaluate(self, distance):
        ...
```

这样可以直接用 pytest 测试负值、边界值和正常值。测试失败时，问题范围缩小到业务逻辑，而不是同时怀疑 DDS、QoS 和消息字段。

使用依赖注入可以把时钟、数据源或输出接口传给业务对象，避免在算法内部创建无法替换的全局对象。

## 4. Python 功能包工程组织

入口模块的 `main()` 负责创建节点和执行器；Node 类负责 ROS 生命周期；算法放独立模块。`console_scripts` 只注册入口，不应把业务逻辑写在 `setup.py`。

资源目录按职责划分：

```text
package/
├── package_name/   # Python 模块
├── launch/         # 系统启动
├── config/         # 参数
├── test/           # 测试
├── package.xml
└── setup.py
```

## 5. 为什么需要生命周期节点

普通节点构造完成后通常立即创建资源并开始工作。但相机可能未连接、模型可能加载失败、参数可能非法。系统需要知道节点“进程存在”与“功能可用”不是一回事。

生命周期提供受控状态：

- unconfigured：进程存在，尚未准备业务资源。
- inactive：资源已经配置，但业务输出未激活。
- active：节点对外提供完整业务功能。
- finalized：节点生命周期结束。

主要转换包括 configure、activate、deactivate、cleanup 和 shutdown。

## 6. 每个状态应该做什么

### configure

读取并校验参数，连接设备，加载模型，创建受管理发布者。失败时返回 FAILURE，不允许系统误以为节点已经准备好。

### activate

激活业务发布和控制循环。启动依赖应满足，例如传感器和底盘已经就绪。

### deactivate

停止业务输出，但保留可快速恢复的资源。控制节点应在停用时输出安全命令。

### cleanup

释放 configure 阶段创建的资源，回到可重新配置状态。要验证重复执行 configure → activate → deactivate → cleanup 不会泄漏资源。

## 7. 转换失败与恢复

每个生命周期回调都应捕获可预期异常、记录具体原因并返回明确结果。不要在错误发生后仍返回成功。

管理节点可按依赖顺序激活系统：驱动 → 感知 → 定位 → 控制。任一关键节点失败时，可以停用下游节点，而不是让它们使用无效数据继续运行。

## 8. 测试策略

- 单元测试：纯 Python 算法和参数边界。
- 节点测试：消息输入是否触发正确输出。
- 生命周期测试：每个状态允许和禁止哪些行为。
- 集成测试：Launch 启动、命名空间、参数与系统关闭。

要求学生特别测试边界值和失败路径，而不只测试正常值。

## 9. 知识点检查与实验

- 设备应在构造函数还是 configure 中打开？为什么？
- inactive 状态能否接收管理命令？能否发布控制命令？
- 算法写成普通类会不会“失去 ROS 功能”？
- cleanup 和进程退出有什么区别？
