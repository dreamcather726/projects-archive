# 第 5 模块：ROS 2 Python 节点模块化与生命周期节点

课程材料：[知识点详解](第5章_授课讲义.md) · [实验说明与代码](experiments/01_managed_monitor/实验说明.md)

本模块的“组件化”指 Python 项目中的职责拆分、模块复用、节点编排和受控生命周期，不安排共享库式的原生组件开发。

## 内容范围

- 单文件节点向职责清晰、可测试的 Python 模块重构。
- 使用 Launch 组合多个独立节点并通过配置切换功能。
- 使用 `rclpy.lifecycle` 管理节点状态转换。

## 详细知识点

### 1. 节点职责与系统边界

- 单一职责：采集、处理、决策、控制、记录分别由合适模块承担。
- 节点过大与节点过碎的代价。
- ROS 接口层与纯 Python 业务逻辑层分离。
- 用普通类、函数和数据类封装可复用算法。
- 依赖注入：时钟、传感器源和输出接口可替换，便于测试。
- 输入校验、状态封装和只读属性，避免跨回调随意修改共享数据。

### 2. Python 功能包组织

- 功能包内的节点入口、业务模块、工具模块和测试目录。
- 用 `__init__.py`、清晰导入路径和公共 API 管理模块边界。
- `console_scripts` 只做启动入口，复杂逻辑放入可导入模块。
- `launch/`、`config/`、`resource/` 的安装规则。
- 多个相关节点放在一个包与拆成多个包的判断标准。

### 3. 系统组合与启动编排

- 使用 Python Launch 组合多个独立 Python 节点。
- 通过命名空间、重映射和参数复用同一节点实现。
- 用 Launch 参数启用/禁用可选功能。
- 把底层驱动、感知处理、任务管理和可视化拆分为可替换子系统。
- 进程隔离的优点：故障边界清晰；代价：通信与资源开销增加。
- 系统关闭顺序、异常退出和节点自动重启策略的概念。

### 4. 生命周期节点状态机

- 普通节点启动后立即工作的问题：资源可能尚未准备好。
- 主要状态：`unconfigured`、`inactive`、`active`、`finalized`。
- 主要转换：configure、activate、deactivate、cleanup、shutdown。
- `LifecycleNode` 与生命周期回调。
- 在 configure 阶段创建或验证资源，在 activate 阶段开始业务输出。
- 回调成功、失败和错误对状态转换的影响。
- 清理文件、设备句柄、定时器和通信资源。

### 5. 生命周期命令与管理

- `ros2 lifecycle nodes/get/list/set`。
- 手动转换状态与管理节点统一编排。
- 节点之间的启动依赖，例如传感器激活后控制器才能激活。
- 转换超时、失败回滚和重复请求处理。
- 用状态话题或诊断信息向外报告节点可用性。

### 6. 测试与可维护性

- 纯 Python 业务逻辑使用单元测试快速验证。
- 节点通信与 Launch 使用集成测试验证。
- 生命周期每个状态分别测试允许和禁止的行为。
- 日志必须包含状态转换、失败原因和恢复建议。
- 配置默认值、接口和状态转换规则纳入文档。

## 课堂演示

1. 把传感器监控节点拆为消息适配层、阈值判断器和 ROS 节点层。
2. 同一判断器使用普通 Python 测试数据进行单元测试。
3. 使用 Launch 同时启动传感器、监控和记录节点。
4. 将监控节点升级为 `LifecycleNode`，演示配置、激活、停用和清理。
5. 故意让配置校验失败，观察状态保持和日志输出。

## 实验任务

实现可管理的巡检感知子系统：

- `sensor_adapter` 负责输入消息转换。
- `anomaly_detector` 封装纯 Python 异常判断逻辑。
- `managed_monitor` 是生命周期节点，只有 active 状态才发布告警。
- Python Launch 负责参数加载、命名空间和整体启动。
- 编写测试验证阈值边界及生命周期状态下的行为。

## 常见问题

- 所有代码堆在 Node 子类中，业务算法无法脱离 ROS 测试。
- 构造函数中直接打开可能失败的设备，节点还没进入配置状态就崩溃。
- inactive 状态仍在发布控制命令。
- cleanup 后资源未释放，再次 configure 时重复创建实体。
- Launch 组合被误解为把所有节点塞进同一个 Python 文件。

## 验收标准

- 业务逻辑可以在不启动 ROS 2 的情况下进行单元测试。
- Launch 能按配置组合和复用节点。
- 生命周期转换路径正确，非法配置会拒绝激活。
- inactive 状态停止业务输出，cleanup 后资源被正确释放。
