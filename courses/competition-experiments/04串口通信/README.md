# ESP32-S3 串口通信课堂实验

本课程共 4 课时，每课时 45 分钟。课程从“电脑向开发板发送一行文字”开始，
逐步过渡到数据帧、串口控制外设，以及两块 ESP32-S3 之间的 UART 双向通信。

## 正式通信格式

```text
55 05 CMD DATA CHECKSUM FF
```

- 帧头固定为 `0x55`。
- 长度固定为 `0x05`，表示帧头之后还有 5 个字节。
- `CMD` 是指令类型，`DATA` 是一个指令数据字节。
- 校验位等于“长度 + 指令 + 数据”，结果只保留低 8 位。
- 帧尾固定为 `0xFF`。

示例 `55 05 01 FF 05 FF` 表示把 LED 亮度设为 255。正式协议及应答规则见
`DATA_FRAME.md`。

## 学习目标

完成课程后，学生应能：

1. 说出波特率、TX、RX、GND、8N1 和全双工的含义。
2. 区分 `print()`、`println()`、`write()`，以及 `read()` 和
   `readStringUntil()` 的使用场景。
3. 说出帧头、帧长度、指令类型、指令数据、校验位和帧尾的作用。
4. 解析 `55 05 CMD DATA CHECKSUM FF` 格式的固定二进制帧。
5. 通过串口选择蜂鸣器歌曲、控制呼吸灯。
6. 完成两块 ESP32-S3 之间的 UART 交叉接线和双向收发。

### 第 2 课时后半：串口原理讲解（一）（0.5 课时）

1. UART 使用 TX 发送、RX 接收，两端必须共地。
2. TX 和 RX 要交叉连接，不能把 TX 接到 TX。
3. UART 没有单独的时钟线，双方必须约定相同波特率和数据格式。
4. 本实验的软串口默认使用 8 个数据位、无校验位、1 个停止位。
5. UART 可以同时发送和接收，属于全双工通信。
6. ESP32-S3 的 GPIO 是 3.3V 逻辑电平，不可直接接入 5V 串口信号。

### 第 3 课时前半：串口原理讲解（二）（0.5 课时）

1. 接收数据先进入缓冲区，`available()` 返回缓冲区中的字节数。
2. `read()` 每次取走一个字节，`peek()` 只看不取。
3. `readStringUntil()` 会等待指定结束符或超时，因此属于可能阻塞的读取函数。
4. `Serial` 用于电脑调试，额外的软串口用于连接另一块开发板。
5. 串口监视器显示的是文本；`write()` 还能发送图片、传感器原始值等二进制字节。
6. 发送端和接收端必须统一波特率、帧格式、命令名称和数值范围。

使用代码：

- 板 A：`06_uart_board_a/06_uart_board_a.ino`
- 板 B：`07_uart_board_b/07_uart_board_b.ino`

### 第 3 课时后半：学生实验（一）（0.5 课时）

1. 使用串口监视器分别发送一个字符和一行文字。
2. 切换“No line ending”“Newline”“Both NL & CR”，观察结果差异。
3. 用 HEX 模式发送正确帧和错误校验帧，观察是否执行。
4. 发送 `55 05 02 01 08 FF` 和 `55 05 02 02 09 FF` 切换歌曲。
5. 发送 `55 05 03 01 09 FF` 启动呼吸灯。

### 第 4 课时：学生实验（二）（1 课时）

1. 两人一组，分别给板 A、板 B 上传对应程序。
2. 按接线表交叉连接 TX、RX，并连接 GND。
3. 在板 A 的串口监视器输入 `ping`，检查板 B 的二进制应答。
4. 输入 `led 255`、`led 100` 和 `led 0`，远程控制板 B 的 LED。
5. 故意把两块板设成不同波特率，观察乱码或无法通信，再恢复为 `9600`。
6. 选做：增加有源蜂鸣器指令类型。
7. 选做：增加帧序号、应答超时和有限次数重发。

## 串口工具设置

1. 字符读取和 `readStringUntil()` 示例使用普通串口监视器，波特率 `115200`。
2. 正式数据帧实验使用支持 HEX 发送和 HEX 显示的串口工具。
3. HEX 模式发送 `55 05 01 FF 05 FF`，不能把它当作普通文字发送。
4. 双板实验可在板 A 的普通串口监视器输入文字，板 A 会自动打包二进制帧。

## 单板外设接线

| 元件 | ESP32-S3 引脚 | 接法 |
|---|---:|---|
| 普通 LED | GPIO 2 | GPIO 2 → 220Ω 电阻 → LED 正极，LED 负极 → GND |
| 无源蜂鸣器驱动输入 | GPIO 48 | GPIO 48 → 蜂鸣器驱动电路输入 |
| 外设地线 | GND | 与 ESP32-S3 共地 |

> 建议使用带三极管驱动的无源蜂鸣器模块。不要用 GPIO 直接给工作电流较大的
> 裸蜂鸣器供电。

## 两块 ESP32-S3 的软串口接线

本例使用 `EspSoftwareSerial` 库创建软串口，引脚为 GPIO 41 和 GPIO 42。
在 Arduino IDE 的库管理器中搜索并安装 `EspSoftwareSerial`。

| 板 A | 连接 | 板 B |
|---|---|---|
| GPIO 41（TX） | → | GPIO 42（RX） |
| GPIO 42（RX） | ← | GPIO 41（TX） |
| GND | ↔ | GND |

两块板都直接在 `.ino` 主程序中创建并启动软串口：

```cpp
#include <SoftwareSerial.h>

SoftwareSerial SoftSerial(42, 41);

void setup() {
  SoftSerial.begin(9600);
}
```

如果自己的开发板没有引出 GPIO 41、GPIO 42，可修改 `PIN_UART_RX` 和
`PIN_UART_TX`，但仍要保证 TX 接对方 RX、RX 接对方 TX。

软串口依靠程序模拟收发时序，课堂实验使用较稳定、容易观察的 `9600` 波特率。

## 常见问题

- **没有任何输出：** 检查串口端口和波特率是否为 `115200`。
- **HEX 帧没有响应：** 检查是否启用了 HEX 发送，并重新计算加法校验。
- **文字示例一直等到超时：** 串口监视器可能没有发送 `\n`。
- **双板通信没有回应：** 检查 TX/RX 是否交叉、是否共地、两端是否都为 `9600`。
- **双板通信出现乱码：** 通常是波特率不一致或接线接触不良。
- **板载 LED 逻辑相反：** 某些开发板的 LED 为低电平点亮，可交换 `HIGH` 和 `LOW`。
- **发送歌曲命令后暂时不能处理新命令：** 歌曲示例使用 `delay()` 顺序播放，
  新命令会在当前歌曲播放完后处理；后续学习非阻塞定时后可继续改进。
